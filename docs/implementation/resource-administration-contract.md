## Page/actions/data and permission design

- Master administration retains overview and adds simple Branches/Bed inventory configuration panels for the organisation currently returned by platform summary. Single current organisation UI; APIs explicitly carry organisation UUID and can serve another assigned organisation. Multi-organisation switching UI/staff management/MFA remain separate planned work.
- New permission platform.configure is granted only to active authenticated master_admin membership, separately from operational/clinical grants. Infer authorised organisations from branches carrying that permission, never request body. Nonmaster403, guessed foreign organisation404, foreign branch/bed404 within permittedorg; current assignments rechecked on every action. Network/CSRF policy remains unchanged.
- GET/POST `/api/v1/platform/organisations/{organisation_id}/branches/`. List bounded25/default100max. Branch create body `{name,code}` only, name<=160, code<=32 uppercase normalisation and alphanumeric/hyphen; no organisation reassignment/update/delete route. Unique code within org, including case-insensitive legacy collisions,409. Return `{id,name,code}`201. Names required/plain labels.
- GET/POST `/api/v1/platform/organisations/{organisation_id}/beds/`. List optional branch UUID, bounded limit/offset; branch list may include all same-organisation branches for configuration. Create body `{branch,number,room_number,category,status?}`; number/room_number<=32 nonblank, category same existing enum, status only available/cleaning/blocked(defaultavailable). No hard capacity limit; expanded beds are ordinary records. Branch belongs to authorisedorg; unknown/read-only fields400. Case-insensitive bed-number collision withinbranch409; normalise number/room whitespace/uppercase consistently.
- PATCH `/api/v1/platform/organisations/{organisation_id}/beds/{id}/` body `{expected_version,number?,room_number?,category?,status?}`. Branch/id/version cannot be directly assigned. Same nonoccupied statuses only; cannot manually occupy/reserve/free an active admission. All edits denied409 when reserved/occupied or active admission exists. Acquire row locks and check latest state+version; stale409 retains UI values and asks reload. No bed deletion or admission bypass.
- Admin bed response `{id,branch,number,room_number,category,status,version}`. Add Bed.version positiveinteger default1; admission allocation increments version atomically as status changes. Existing operational BedSerializer may omit version; admin reads it explicitly. Backend services remain authority; changing UI disabled state is not protection.
- Every successful configuration change creates AuditEvent in same transaction. Add details JSON defaultdict for nonclinical allowed-field before/after snapshots; branch create and bed create/update capture only approved config labels/states, not arbitrary request payload, passwords or patient identity. No public audit-write/edit/delete API. This is traceable configuration evidence, not full immutable/sensitive-read audit certification.
- Metadata GETs never create revisions or mutate data. UI essentials first, familiar branch/bed labels, text status alongsidecolour; create/edit forms retain errors/values, success refresh list; pagination shows all capacities. Branch choices in bed form must be pageable (no first100hardcap). Existing organisation overview branch/staff counts refresh after config create. No unsupported bulk import/rename/delete implied.

## Failure/threat/acceptance preflight

- Anonymous/missing CSRF/nonmaster/foreignorg/foreignbranch, malformed object/unknown fields/bogus state, duplicatecase code/number, occupiedbed edits and racing allocation/configuration must fail safely without audit/partial writes.
- Atomic service locking/constraints protect allocation+configuration. Organisation lock serialises branch code checks; branch lock serialises bed number checks; bed row lock protects edits/version against admissions. Consistent ordering within config; no allocation code may acquire branch lock after holding bed lock.
- Existing-role revocation takes effect immediately through usual permission functions; master config permission never implies patients.read, admissions.write or signing. Preserve all previous permission regressions.
- Backend RED: master success/no-opscope isolation; nonmaster deny; guessedforeign404; duplicatecase409; >100config inventory; staleversion409; occupied/reserved/active admission immutable; forgedstatus/branch/read-only rejected; atomic audits/config snapshots; allocation incrementsversion. Actual PostgreSQL race test must show either edit-before-admission consistent version or allocation-before-edit409, never editing an occupied allocation.
- Frontend RED: permitted master configure forms, nonconfigure user controls hidden, config POST/PATCH body/version,403/409 field feedback retained, branch choices after100 available, empty/error/retry, list refresh and pagination. Tests before code, typecheck/full suite/build after.
- Root OpenAPI/page-action mapping source precedes code. Source-only runtime/parity checks separate from existing deployment. No localStorage data, generated password or host secret needed for this slice.
