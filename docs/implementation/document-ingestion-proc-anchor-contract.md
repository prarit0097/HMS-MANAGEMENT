# AVCTL task observation and consumed handoff boundary

**DRAFT —18 November2026.** Coordinator design candidate after independent security/scenario review. Not a frozen production leaf, privileged implementation, syscall test, host provisioning or authority grant. Read [launch proof](document-ingestion-launch-proof-draft.md), [OS profile](document-ingestion-os-access-profile.md), [profile data](document-ingestion-profile-data-contract.md) and [publisher boundary](document-ingestion-publisher-db-boundary.md). The repository checker is complete and supplies no live authority.

## Decision and smallest deliverable

Select a root-pinned own-task descriptor, handed to the actual post-drop startup consumer beside the sealed record. Do not add another independent facts decoder. A pathname-only `/proc/self` reader cannot distinguish the approved task view merely by checking a filesystem-type integer; a root-opened proc-root handle would expose unnecessary process enumeration. Pin only the exact launcher's own task directory. This is an explicit amendment candidate to the earlier one-descriptor handoff, not an already supported fallback.

The first consumed leaf would be a fixed closed-maintenance AVCTL launcher and its post-drop startup entry, which validate their real handoff and exit with a fixed result. No registration/readiness/database/scanner/gate operation belongs to that initial executable acceptance. It cannot be installed as the production supervisor or claimed to complete expected-Control launch. A later runtime composition must place the known expected-install commit before the handoff as already required by the parent; no mode may skip that step and continue to publication. Source paths/signatures, credential provider, full image closure, exact syscall ABI and isolated lifecycle harness must still be independently frozen before executable implementation.

## Descriptor contract candidate

- FD3 remains the exact root-owned sealed O_RDONLY launch record. No record-key, canonical data format, S0/S1 helper or checker change is proposed.
- FD4 is an O_PATH|O_DIRECTORY handle for the initial root launcher's exact task directory in the reviewed host procfs view. Root verifies its own numeric PID/start/boot/namespace/unit context before capture. No request/environment-provided PID, path, FD or proc root is accepted. Its filesystem must be procfs; root checks device/inode stability during acquisition. No root device/inode snapshot is added to the record: runtime establishes and rechecks its own descriptor baseline, relying on the trusted cross-exec handle continuity plus independent PID/start/context equality. Root's initial mount/PID/user view and immutable launcher are trusted installation prerequisites, not facts authenticated by PROC_SUPER_MAGIC.
- Only reviewed stdio, FD3 and FD4 survive the single fixed drop-and-exec. Both descriptors become CLOEXEC immediately in trusted single-threaded startup, before threads, children, imports from mutable paths or credential delivery. The observer privately duplicates/checks its handles with CLOEXEC and closes only those duplicates in every path. No concurrent close/dup/FD-reuse actor is permitted in this trusted startup. All temporary task-file, namespace-parent, namespace and duplicate handles are acquired CLOEXEC and closed on every success/error outcome. Only the original FD3/FD4 pair is retained between future observations; startup failure closes it through process exit. Exact duplicate/check/read/recheck syscall ordering and ABI are still leaf obligations.
- Close FD3 and FD4 explicitly before any fork-child code; CLOEXEC alone does not cover fork. A deliberately inherited fork child must fail independent getpid/start comparison. Later exec loses both; there is no alternate pathname reader or descriptor rebuild from Control.
- Unlike the sealed record, task-directory UID/GID ownership is not required to remain root across privilege drop/exec. Proc task ownership changes with effective credentials and dumpability. Record ownership checks must never be reused as task-directory authority. Preserve the pinned kernel object identity and verify live process equality instead; exact post-drop read access must be measured, not fixed through a host permission change.

## Fixed observations and traversal

Use direct own-process getpid/getresuid/getresgid/getgroups and trusted prctl/capability observation independently of proc bytes. FD4 pins the original task, not every thread in its process: require independent native gettid equality with the captured PID before and after each observation, including future postwait/postcommit checks. Observation stays on that original main OS thread; another thread sharing getpid cannot borrow this anchor. No per-thread fallback is proposed. Task reads are limited to literal `stat`, `status`, `cgroup` and the authenticated `ns` directory relative to FD4; no arbitrary relative/absolute path, `..`, process enumeration or syscall that writes proc state. Each ordinary file must resolve without symlinks or crossing subordinate mountpoints, with the expected procfs identity checked on opened descriptors. A simple openat+O_NOFOLLOW on only the final component is insufficient. The implementation choice is constrained openat2 or an independently proved equivalent; exact flags, struct ABI, size caps and unsupported-kernel errors must be frozen before code. Unsupported proof denies, never retries through weaker path resolution.

Namespace files require a separate rule: proc `ns/*` entries intentionally use magic-link semantics, so a blanket no-magic-links traversal cannot also open them successfully. First authenticate the literal `ns` parent under the pinned task directory without substitution; then open only literal `user`, `pid`, `cgroup`, `mnt` namespace handles. Check expected nsfs filesystem type, kernel namespace type via NS_GET_NSTYPE and descriptor device/inode identity against the host/profile or root-record expectation. Type/identity equality is a conjunction, never an inode integer alone. Namespace handle opening is the only reviewed magic-link exception; it permits no user path or arbitrary descriptor link. Exact mount-crossing exception and resistance to a namespace-entry bind substitution remain executable freeze gates, not solved by this paragraph.

FD4 contains no boot_id file. Do not pretend it supplies fresh boot evidence: root obtains the boot UUID in the approved initial host proc view and binds it in FD3 plus the manifest-bound host policy; pinned descriptors/process lifetime cannot survive a reboot. Runtime must prove that lifetime/anchor conjunction, or adopt a separately reviewed bounded trusted boot source. No naked ambient boot path or automatic boot/profile refresh is authorised. This choice needs scoped review before the runtime contract replaces its prior fresh-boot-path wording.

Proc fields may change between reads; there is no atomic kernel snapshot claim. Check immutable PID/start plus namespace/context before and after bounded reads, and revalidate fresh context after any wait/known DB commit in the later composed publisher. A failed/short/oversize/unknown/permission-denied observation is unavailable; never cached readiness, counter release or gate enablement. No root-compromise, arbitrary trusted-supervisor execution, malicious same-UID handle theft, whole-VM rollback or immutable-executable-attestation claim follows.

## Pre-code scenarios and acceptance obligations

| Case | Required evidence before the consumed leaf can pass |
|---|---|
| Approved root capture -> exact drop -> same-PID fixed exec | Both intended handles survive once; descriptor/context validation succeeds under final IDs without retaining privileged credentials or changing host permissions. |
| FD4 missing/closed/wrong-directory/non-proc/replaced or reused | Fail before any authority or DB operation; no pathname fallback. |
| Ambient proc path replaced; subordinate ordinary-file bind mount | Pinned observations remain the intended task or fail; substituted bytes never validate as live authority. Test only inside an independently isolated mount namespace. |
| Forged namespace link or wrong nsfs/type/device/inode | Reject even if printed namespace text/inode number looks correct. Exact kernel lookup policy must be executable. |
| Proc task ownership/dumpability changes | Valid final reader works with the measured permitted policy or stays unavailable; no blanket root-owner acceptance rule. |
| Fork with intentionally inherited descriptors | Independent child PID/start mismatches despite reading the parent's task; ordinary child path closes both handles before child code. |
| Another thread shares getpid but has different namespace/credential context | Independent native gettid mismatch denies before using the original-task anchor; no cross-thread observation composition. |
| Second exec, FD-reuse race, partial/bounded read or unsupported syscall | No authority survives or weakens; fixed privacy-safe failure, owned resources closed. |
| Reboot/profile mismatch or closed guard during later composition | No automatic adoption, registration, readiness, slot release or intake opening. |

Future hostile mount tests must unshare before any mount operation, make propagation private inside that namespace and verify its separation first. Never bind/remount shared host /proc or change other apps; unsupported namespace capability is a blocked acceptance, not reason to change global settings. Exact owned process-group timeout/reap, isolated paths/cleanup, manifest/source integrity and app-preservation boundaries require a reviewed literal harness before any VPS execution. No hostile mount test ran for this document.

## Profile scope and remaining freeze gates

Current canonical profile-data slice supports AVCTL own projection only; seven service identities in root data do not implement seven runtime projections. Other role projections/child launch remain deferred design. Do not add schemas/helpers for them merely to make the broader draft appear complete.

## Scoped independent review disposition

Security and scenario reviews found no blocking contradiction for this DRAFT startup-validation-and-exit scope. Incorporated precise root-versus-runtime descriptor baselines, closure/CLOEXEC for every temporary observation handle, and original-native-thread confinement for future composition. These are reviewed design requirements, not test results or approval of the still-open syscall/namespace/boot/image/Control gates. Production leaf remains unfrozen.
