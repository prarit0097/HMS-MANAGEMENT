> **For agentic workers:** REQUIRED SUB-SKILL: Use Superpowers subagent-driven-development/executing-plans, TDD and review. Coordinator alone commits/pushes.

**Goal:** Let an authorised administrator inspect scoped nonclinical changes and let any full-session staff user inspect their own factor/session activity without exposing clinical charts, foreign organisations or raw stored payloads.

Frontend is an API client. Full immutable/read auditing, retention/export and incident response are separate release work.

## Decisions and scope

- Coordinator ruling under existing implementation authorisation: first expose the existing nonclinical change journal and personal security activity. A raw global AuditEvent browser would disclose other organisations and potentially clinical records; a complete certified audit archive needs separate storage/retention/read-event design. Cost if insufficient: later explicit audit-operator/read-audit extension, not an implicit chart-view grant.
- New platform.audit.read permission only active master_admin. It does not grant patients.read, clinical signing, resource/staff mutations or exports. Organisation access derives from a current active master branch in the explicit organisation; entire same-org nonclinical history is available as with current master configuration. Reads require require_platform/current MFA policy too (outside development fresh enrolled factor); not merely a URL/middleware write check. Self security activity needs authenticated self only, no master grant or extra recent proof; partial MFA challenge cannot access it.
- Administration allowlist: branch.created,bed.created,bed.changed,staff.created,staff.changed only, and event.branch.organisation must equal permitted org. Exclude patient/appointment/admission and every branchless/global security record. Even a recognised action with foreign/null branch is concealed. Self allowlist: security.enrolled,enrollment_started,login_verified,step_up,password,rotate,revoke,disable (all with security. prefix), actor=current user AND branch=null. No colleague/global user list. Unknown actions excluded, not relabelled as harmless events.
- No event update/delete/export API or UI. GETs do not write/recursively audit themselves; full read-event audit remains incomplete. Existing journal is not tamper-evident/immutable against database operators. No new failed-login recording, session enumeration, raw IP display, clinical access or recovery flow in this slice.
- Independent pre-code review refinements: org GETs call read-only require_platform, never lock_platform (which creates state). Suspended master membership denies org history, but an otherwise active full-session identity may still read its own branchless security activity. Use string route parameters plus explicit UUID validation to deliver malformed400. Reject bool as an integer ID/version, guard date underflow/overflow/invalid offsets with400, and test extreme year0001/default-window subtraction. Projected username<=150, branch name<=160/code<=32, bed number/room<=32; overlong/malformed stored fields are omitted, not stringified. UUID fields canonicalised/validated; object reference is UUID for config actions, positive decimal userID for staff/security, otherwise empty string. Versions/targetIDs bounded to positive signed64bit range (version may0); lists and scalars are both bounded.

Independent API tests mandatory. Unknown query keys and duplicate keys400 (avoid ambiguous filtering); detail accepts no query parameters. No new request bodies/writes. OpenAPI/page actions freeze before production code.

List query: limit(default25,max100 using existing clamp), offset(default0,max10000, invalid/negative400), action(exact enum for that endpoint), branch(UUID,administration only, must belong to org or404), after/before(ISO8601 with explicit Z/offset). Default before=now, after=before-30days; explicitly future before clips to now. Reject after>=before and windows>90days. Bounds after inclusive/before exclusive, order created_at descending then UUID descending, count before slicing. Response window echoes actual aware after/before; client pins these for pagination, clears pin on refresh/filter changes. Offsets bounded for query cost, not record capacity; narrow/change dates to browse larger histories. Other arbitrary search/user/object parameters400, no patient/name/password query logging. Self has no actor/branch override.

Summary fields: id(UUID),created_at,action,actor({id:int,username:string}|null),branch({id,name,code}|null),object_id(string reference <=36),method(totp|backup_code|null). Actor null displays Former account. Names reflect current identity/configuration, not a historical name snapshot. Self actor is caller and branch alwaysnull; UI can label You. Never include raw details in a summary. Security method is only an allowed string, other values=null.

Detail extends summary with details(object of normalised allowlisted fields) and details_truncated(boolean). Project per action, never return raw stored JSON. Branch snapshots allow only name/code strings. Bed snapshots allow number/room_number/category/status/version with type/enum validation. Staff allows target_user_id(positiveinteger), organisation_id only when exactly currentorg, and before/after{status,version,assignments:[{branch:UUID,role:enum}]}; only same-org assignment branches may appear. Drop unknown keys (password/token/secret/raw payload etc), invalid types, foreign branch/org fields and nested unknowns. Process at most1000assignments per snapshot and set details_truncated=true for longer lists; this protects response work, does not mutate data or create a hospital capacity limit. Return an empty safe object for malformed/unknown detail shapes. No dynamic key echo. UI resolves branch labels from already authorised projection/lookup; add detail branch_labels map UUID=>same-org{ id,name,code } for assignment IDs, only keys actually included, no general branch enumeration. Target username lookup optional only if current target still has same-org membership; otherwise display Former staff account, never raw ID as primary name. Add target={id,username}|null to AuditDetail for safe display. Object/event IDs may be secondary reference text, never primary identity labels.

Add core0006 indexes for AuditEvent branch+created_at+id and actor+created_at+id (and action as appropriate after query inspection); no clinical schema or historic event rewrite. Date/page bounds and indexes are engineering protections, not proof of target traffic capacity. No automatic retention/deletion.
