Status: **DESIGN PROPOSAL — not a frozen contract or implemented capability.** Review date: 24 October 2026. Scope is repository/document review and official-source research only. Coordinator owns contract approval, living-document integration, Git and any later implementation. No application tests, scanner execution, deployment, credentials or real patient data were used for this review.

## Actual source and the next safe boundary

Read together: [HMS.md](../../HMS.md), [plan.md](../../plan.md), [ledger](ledger.md), [identity contract](identity-security-contract.md), [audit contract](audit-history-contract.md), [network contract](network-access-contract.md), [OpenAPI](../api/openapi-v1.yaml) and [ICTHospital research](../research/2026-10-24-icthospital-comparison.md).

Observed source, not a readiness claim:

- `backend/apps/core/models.py`: Patient has one registration branch, protected FK and UHID; Encounter is a one-to-one Appointment check-in, not a general clinical document/visit authorisation model. Appointment/Patient branch consistency exists in services. Do not invent encounter ownership or cross-branch patient sharing from these models.
- `authorization.py`: patients.read belongs to reception, doctor and nurse. patients.write belongs to reception. Master has platform configuration/staff/audit permissions, not patient read or clinical authority. Current branch memberships are active-filtered; union permissions alone cannot authorise a different branch.
- `identity_security.py`, `middleware.py`, `hms/settings.py`: session/epoch/MFA and trusted-proxy network controls exist as bounded source. Stable-user locking is already used for selected sensitive operations. Existing documentation permits ordinary in-flight requests to finish; universal instantaneous revocation is not implemented. Preserve that precise limitation or freeze stronger file ordering explicitly.
- `AuditEvent` is an ordinary database model. Administration history is a redacted allowlist excluding clinical events; its GETs intentionally do not record reads. It is neither general PHI access accounting nor immutable against database operators. `services.audit()` alone does not solve download disclosure/failure ordering.
- There is no patient document model, file ACL, quarantine, scanner adapter, private-file storage/delivery contract, file encryption configuration or implemented retention/hold workflow in the inspected source. Existing serializers reject unexpected file payloads. MFA secret encryption keys are not document keys.
- Task 02 remains partial; Task 04 reception subsets exist, while protected files, payer summary, merge review and remaining queue work are planned. Research explicitly rejects public-disk clinical files. No external upstream code is admitted by this design.

**Recommendation:** freeze a registration-document-only first source slice. Design `clinical_reference` separately with explicit clinical category grants; external reports/prescriptions remain source material, never signed/approved orders. Implement/test private storage, deny-by-default ACL, intent/byte lifecycle, durable access audit and a fail-closed scanner interface against synthetic fixtures without waiting for all production recovery work. Real data and successful ready/download runtime acceptance require the actual reviewed scanner/validator, keys, private delivery and restore evidence. An unavailable engine must leave files unavailable; a synthetic test scanner must never be a runtime clean fallback.

Architecture/UI peers proposed `registration` and `clinical_reference`, six routes (list, create intent, detail, PUT bytes, GET content, withdraw), attachment download only and separate category grants. These remain proposals until coordinator freeze. No extra capability follows from this review.

## Lifecycle, scanner and hostile-content boundaries

1. Create an opaque document/intent ID with immutable patient/branch/category, uploader, version, expiry and server-generated object generation. Require a UUID idempotency key scoped to actor+operation and metadata fingerprint. Do not persist raw PHI request payloads in retry ledgers. Freeze intent count/storage quotas and expiry; quotas bound resources, not hospital capacity.
2. PUT accepts only the exact intent, current authorisation and one bounded immutable body. Proposed 10 MiB payload maximum must be enforced at edge and streaming application ingress, including missing/false Content-Length and chunked requests; reject multipart/extra parts unless explicitly contracted. Never read an unbounded body for authentication, CSRF or parser convenience. Server computes length and SHA-256 over received bytes; client digest is a claim, not proof.
3. Bytes enter a private quarantine location before any ready state. Server-generated opaque storage keys contain no patient name/UHID or user filename. Exclusive creation, no symlink following, containment checks and separate process permissions prevent traversal/overwrite. A metadata rollback must not leave public/orphan-accessible bytes; scoped reconciliation handles failed writes without deleting referenced records.
4. The trusted worker acquires a bounded lease and scans the exact immutable generation/digest. It has only quarantine-read and outcome-service privileges, no arbitrary SQL, shell command or URL supplied by a caller. No public mark-clean endpoint, user field, management UI override or unauthenticated callback. Scanner result binds document, generation, digest, engine/signature version, validation policy version and lease token. Reject duplicate stale leases, replaced bytes, unknown outcomes and invalid result shape. Recheck cancellation and current permitted uploader/category ceiling before promotion; withdrawn/revoked work cannot later become ready.
5. Missing engine/signature DB, stale signatures past a frozen freshness threshold, timeout, engine crash, invalid response, scan-size/recursion limit or unsupported/encrypted content are **not clean**. Use unavailable/rejected states with a plain next step; bounded retries preserve evidence. Freeze allowed verdicts and status/error mappings before code. Malware-found stays inaccessible and restricted; no raw engine output/paths/signatures displayed to staff.
6. Proposed types PDF/JPEG/PNG require extension, declared MIME, signature and structural validation to agree. Reject SVG, HTML, office/macros, archives, executables, polyglots/malformed/trailing content and unsupported types. A magic-prefix test alone cannot establish safety. Reject password/encrypted PDFs and PDF JavaScript, launch/open actions, embedded files, XFA/rich media/external resource actions using a pinned parser/sandbox policy. If that policy cannot be reliably enforced, defer PDF acceptance rather than silently declaring it safe. AV clean does not establish absence of active PDF behavior or clinical approval.
7. Freeze numeric page/pixel/dimensions, decompressed bytes, recursion/object count, worker memory/CPU/wall-time and queue budgets with a pinned structural validator before accepting those formats. A 10 MiB compressed file can exhaust decoder memory. No unbounded archive expansion, OCR, thumbnail/rendering, external URL retrieval or automatic clinical extraction. If images are re-encoded later, original/derived object digests and provenance remain distinct; a derivative cannot inherit an unrelated scan verdict.

## Delivery, audit and encryption gates

Use authorised API delivery of immutable ready bytes. Do not expose MEDIA paths, public bucket ACLs, static aliases, storage keys, arbitrary file-path query parameters or signed storage URLs. Reauthorise each list/detail/content/HEAD/retry request against current state. Initial contract should reject Range and disable conditional304 behavior explicitly, including wildcard validators; HEAD must not accidentally stream or bypass accounting. Every attempted representation remains private/no-store with safe MIME, `nosniff`, `Content-Disposition: attachment` and a generated ASCII filename such as `document-<opaque-id>.pdf`; never reflect CRLF, slashes, control/bidi characters or the raw supplied filename in headers. Download is the approved content disclosure; bulk export/share/email/portal delivery remain separate capabilities.

Before returning PHI metadata or opening the response stream, commit a bounded allowlisted access event with actor, branch/org, opaque patient/document reference, category/action, generation and request correlation. Audit failure must return generic503 before any PHI bytes. Record **access authorised/attempted**, not a claim the user received all bytes; streaming disconnect and successful completion are different outcomes. Do not log file bodies, diagnoses, raw filenames, secrets, session cookies, bearer URLs or raw engine output. Existing nonclinical admin history must not start exposing these new events automatically. Freeze whether list events record scoped query/result references and how event volume is bounded without losing accounting. Audit records themselves are protected PHI. Operator-resistant immutability/export to a separate sink is additional real-data release work, not already delivered by inserting AuditEvent.

Authenticated delivery must retain the environment AND durable network ceiling, trusted-proxy resolution and direct-origin closure through the last public file path. No alternate object origin may bypass policy. For a bounded ≤10 MiB response, freeze authorisation at the final post-lock pre-delivery instant; revocation after bytes leave cannot retract them. Define a wall-time limit and document that in-flight limitation. Any future presigned URL needs a fresh review: provider URLs are bearer capabilities, may be reusable and can continue a transfer begun before expiry; short expiry alone is insufficient for current-session/branch/network rechecks.

Require TLS and private at-rest encryption for quarantine, ready objects and backups. Freeze one actual provider/library implementation before coding encrypted storage; do not invent custom streaming crypto. Prefer authenticated encryption with document/org/generation binding, explicit key ID and independent document key configuration. Key loss, unknown key, binding mismatch or ciphertext corruption fails closed503 with no partial plaintext response. Separate keys from data/backups, Git and MFA keys; specify provision/access/recovery owner. Rotation writes a new verified immutable encrypted generation or safely rewraps its data key, preserving plaintext digest and old decrypt availability until all dependent backups age out. Test interrupted rotation and wrong/swapped key/object data. Production restore requires both encrypted objects and recoverable key references; encrypted files without keys are not a working backup.

## Deletion, correction and concurrency

No DELETE or replacement-in-place. Recommend withdraw only an uploader's **pending/non-ready** intent with current category write and expected_version; cancellation records actor/reason and keeps provenance. Ready-file correction/supersession, wrong-patient remediation and legal holds need an exact later contract before UI actions. If root chooses ready-file withdrawal now, freeze who can do it, its read visibility and original-preservation/audit rules first. No signed-record/final-bill attachment can silently disappear. No deletion job or legal retention duration is inferred from an upload expiry or ICT log-retention rule.

Actual PostgreSQL must prove: same intent concurrent PUT has one immutable object; identical key+digest retry returns the same authorised result; changed metadata/bytes409; create/upload/scan/withdraw retries do not duplicate audit state transitions; promotion vs withdrawal and revocation have defined serial winners; stale leases cannot resurrect withdrawn files; storage failure rolls back ready state; committed object is never overwritten; ready state requires exact stored digest and validation version. Deduplication across patients/organisations is out of scope: content hash must not become an existence oracle or shared ACL.

Backups need a versioned manifest linking patient/branch/category/document/immutable generation/digest/key reference, scan/provenance/correction links and audit dependencies. Portal restore cannot blindly overwrite shared Patient/Encounter/identity data. Test missing object/key, corrupt digest, cross-org reference, hold and partial restore into an isolated target. No source slice can claim full dataops restore from metadata-only database backup.

## Official research used and limits

- [OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html): layered type checks, private storage, permissions, antivirus and decompression limits inform the proposed hostile-content controls. It does not certify a validator or dictate our numeric limits.
- [Django 5.2 security documentation](https://docs.djangoproject.com/en/5.2/topics/security/): framework upload handling cannot itself guarantee safe user content. Attachment-only API delivery and strict admission are project proposals, not automatic Django protections.
- [ClamAV scanning documentation](https://docs.clamav.net/manual/Usage/Scanning.html): signatures are required; clamd TCP does not authenticate clients. Use a private controlled socket/worker boundary if selected. Clean AV alone is insufficient structural validation. No engine was installed or run here.
- [Amazon S3 presigned URLs](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html): URLs are reusable bearer capabilities and expiry is checked at request start. This supports deferring URLs when every read must recheck current authority; AWS is not selected infrastructure.
- [OWASP Cryptographic Storage](https://cheatsheetseries.owasp.org/cheatsheets/Cryptographic_Storage_Cheat_Sheet.html): authenticated encryption, separate keys and rotation planning inform the proposal. No algorithm/provider or key-recovery implementation is approved by this review.
- [OWASP Logging](https://cheatsheetseries.owasp.org/cheatsheets/Logging_Cheat_Sheet.html): protected audit design, sensitive-data exclusion and logging-failure testing inform the access-event proposal. No legal retention duration or compliance conclusion is made.
