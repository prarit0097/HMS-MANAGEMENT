## Boundary and engineering rulings

The proposed next implementation unit is four registration-only metadata APIs plus services/permissions/transport tests; no bytes/content route, encounter, clinical category, PDF, scan work, storage, ready/download state or dependency installation. Existing foundation models/migration remain the persistence contract. An intent is a declaration, never evidence a file was received.

Approaches considered: require storage/scanner for every metadata operation (prevents independent safe source work); expose working uploads from metadata alone (misrepresents availability); or source-test metadata independently while runtime file ingestion remains disabled. Recommend the third. Exact runtime policy: one deployment-owned `HMS_DOCUMENT_METADATA_ENABLED` boolean defaults false; disabled document routes return generic503 after session/action checks, without object lookup/projection or domain/audit writes. Under the reconciled B2a design, an otherwise valid disabled call commits its actor allowance and then returns503 outside admission; malformed configuration consumes none. No visitor-controlled activation. When explicitly enabled for reviewed synthetic acceptance, metadata commands may succeed without storage/scanner because they accept no bytes. They must never probe a permissive scanner fallback. Real-record runtime activation remains a separate reviewed rollout/security/dataops decision. Missing metadata DB/audit/authority/network dependencies always fail503.

`can_upload=false`, `can_download=false`, `upload_categories=[]` in every response; no URL, content route, storage locator or accepted-byte receipt. Metadata read/withdraw remains possible after future ingestion dependency failure under this contract; new byte admission is never implied. Production usable uploads require a later frozen private storage/encryption/parser/scanner/key/worker contract and actual evidence. This deliberate source/runtime distinction costs an extra slice before staff can attach a file.

## Authority and CurrentUser

Planned B2a static role additions (B1 changes no grants): only `reception` gains `documents.registration.read` and `documents.registration.write`. CurrentUser existing `permissions` union and `branch_permissions[branch_uuid]` arrays gain these strings under their existing shapes. | Action | Current authority, all at patient registration branch |
|---|---|
| List/detail | `patients.read` AND `documents.registration.read` |
| Create/withdraw/replays | Both read grants AND `patients.write` AND `documents.registration.write` |
| First withdrawal | Above AND actor is creator AND version matches AND selected time strictly before expiry AND stored state pending |

Master-only, doctor-only, nurse-only, other roles and unassigned users get neither document grant. A multi-role user qualifies only through active reception membership in the exact branch; reception-B plus doctor-A does not authorise documents-A. Active identity/current captured session epoch/effective environment AND overlay IP policy are required. No new privileged MFA requirement for reception; existing challenge/stale-session rejection remains. Retain existing epoch0 compatibility under locked User when IdentitySecurity is absent; do not create security rows as a read side effect. Existing MFA/profile services must serialize first-profile creation on that User lock.

No action grant anywhere:403 before patient/document lookup. Missing/foreign/inaccessible patient or mismatched document: identical404, including after a lock wait or replay. Withdrawal of another creator's visible intent:403 without receipt/event. A replay must independently reauthorise current scope before resolving/disclosing its result. Direct-service callers require server-minted captured session/epoch/network context; no public helper accepting arbitrary actor ID/trusted boolean. MCP/jobs get no extra route or authority.

## Exact HTTP surface

`P=/api/v1/patients/{patient_id}/documents/`. Register the four shapes using string path segments, not Django UUID converters. All path UUIDs and Idempotency-Key use lowercase canonical hyphenated UUID textual form; accept no braces, URN, whitespace or uppercase aliases. Malformed identifiers in registered shapes receive concealed JSON404 after authentication/global-action checks; unknown/unregistered paths such as content remain ordinary Django404 outside this closed view contract; malformed/missing required key400. UUID keys identify commands, never grant scope. Only listed methods exist; authenticated global-action checks precede method dispatch; HEAD/OPTIONS/PUT/PATCH/DELETE return local405 with no metadata, implicit DRF metadata/HEAD disabled. No content subpath is registered.

| Method/path | operationId | Exact input | Success |
|---|---|---|---|
| GET P | `listPatientDocumentIntents` | Optional `limit` canonical ASCII integer1..100 (no sign/leading zero/whitespace) default25; optional `cursor` below; optional `category=registration`. No body. |200 List |
| POST P | `createPatientDocumentIntent` | Required Idempotency-Key; Create JSON below; empty query |201 Result, including exact replay |
| GET P{document_id}/ | `getPatientDocumentIntent` | Empty query/body |200 Result |
| POST P{document_id}/withdraw/ | `withdrawPatientDocumentIntent` | Required Idempotency-Key; Withdraw JSON below; empty query |200 Result, including exact replay |

Unknown/duplicate query keys400. No offset/count/search/sort/branch/org query. Reject nonempty GET bodies400 with bounded inspection, never an unbounded parser read. All registered document-view responses, including local failures/405, have `Cache-Control: no-store`, `Vary: Cookie` and nosniff; existing pre-view network/session short-circuits retain their own headers (no universal Vary: Cookie promise), with no-store applied by network middleware and nosniff by outer SecurityMiddleware; no ETag/Last-Modified. Conditional request headers ignored, never304. Range unsupported400 `validation_error`; no metadata-specific416/content semantics. Size bounds apply irrespective of false/missing Content-Length or transfer framing; no blanket trusting declared length.

List order `created_at DESC,id DESC`. Keyset cursor is unpadded base64url of compact UTF-8 JSON exact keys `{v:1,patient_id,category:"registration",created_at,id}`; canonical UUIDs, UTC timestamp grammar below, max512 ASCII characters, no duplicate keys/noncanonical encoding/extra fields. The cursor JSON has fixed key order v,patient_id,category,created_at,id and exact compact ensure_ascii=True bytes; re-encoding must match input bytes/base64 spelling. v must be actual integer1, not bool. Timestamp must be an actual valid UTC calendar datetime. Cursor tuple must follow strict older-than comparison; patient/category must equal path/filter or400 `validation_error`. Cursor is a position, not an authorisation token. Select <=101 IDs, return<=limit, private sentinel determines has_more. No total COUNT. New inserts appear on explicit first-page refresh; immutable ordering prevents duplicates caused by state changes. Each page has its own selection instant, not a multi-request frozen snapshot.

Create exact required fields, no extras: `{category,filename,media_type,size_bytes,sha256}`. category exactly `registration`; media_type exactly `image/jpeg` or `image/png`; size_bytes actual JSON integer (not bool/float/string), inclusive1..10485760; sha256 exact64 lowercase ASCII hex; filename Unicode scalar string (reject U+D800..U+DFFF), reject controls before trimming, then trim outer whitespace and require1..120 code points; reject C0/C1 controls, DEL, bidi formatting controls, slash/backslash, NUL, `.`/`..`, all-whitespace. No Unicode normalization beyond trim; render text only. These are declarations; do not claim extension/signature/byte validation. No creator, status, version, time, branch, encounter, scanner or storage input.

Withdraw exact required fields `{expected_version,reason}`; version actual integer1..2147483647; reason Unicode scalar string, reject controls/surrogates before trimming, then trim and require10..500 code points; reject C0/C1/DEL/bidi controls. New-key attempt against expired/withdrawn intent409 `intent_state_conflict`; stale version409 `version_conflict`; version2147483647 cannot increment and returns409 `version_conflict`. No restore/unwithdraw/delete.

POST Content-Type exactly application/json with optional UTF-8 charset; no multipart, file field, content encoding or alternate media type. Capture at most4097 original bytes before any installed DRF authentication/CSRF/parser may consume the stream, fail413 above4096; preserve exact bounded bytes for ordinary session authentication/real CSRF and strict handler parsing. Do not copy network-specific transport code blindly. Strict UTF-8 object JSON, no BOM, duplicate keys at any depth, nonfinite values, scalar/array root, unknown fields or coercion. Enforce maximum nesting depth8 (root depth1) and reject deeper input400; trap parser RecursionError at the actual pre-handler/CSRF boundary with generic400. Valid real-CSRF JSON at exactly4096 must succeed when remaining fields are valid; oversize must never reach an unbounded framework read. No disabling/bypassing CSRF, global parser replacement or shared unrelated endpoint behavior change. A document-only content negotiator always selects fixed compact JSON/application/json, ignoring Accept/indent; document format-suffix override is disabled so unknown format query reaches strict400 validation rather than pre-auth framework404. No local406 path is promised. Local exception mapping uses fixed strings/codes and never forwards generic str(exc.detail), serializer values or media/method input. B1 pure helpers establish none of these real HTTP guarantees.

## Closed response and error schemas

All objects below reject additional properties in future OpenAPI; fields listed are required. IDs are canonical UUID; timestamps UTC RFC3339 `YYYY-MM-DDTHH:mm:ss.ffffffZ` (exact6fraction digits). Boolean fields must be actual booleans. Serialise detached scalar values only; complete encoded response <=256KiB, fail503 before disclosure if exceeded.

`MetadataCapabilities={can_create_intent:boolean,can_upload:false,can_download:false,upload_categories:[],allowed_media_types:["image/jpeg","image/png"],max_size_bytes:10485760,max_filename_characters:120}`. `can_create_intent` reflects current write conjunction AND enabled metadata policy; it does not promise ingestion. Shared static limits are declaration bounds, not upload availability. A disabled response is an error, never a success capability projection.

`Intent={id,patient_id,branch_id,category:"registration",filename,media_type,size_bytes,status,version,created_at,expires_at,is_creator,can_withdraw,can_upload:false,can_download:false}`. filename/media/size are declared values. `status` exactly pending|expired|withdrawn; version1..2147483647; `is_creator` boolean; can_withdraw derived from current grants/creator/state/version/time. No user display name/identifier, digest, withdrawal reason, withdrawn actor, storage information, patient demographics or scan text. Avoid an extra target-User lock for a display label.

`Result={server_time,document:Intent,capabilities:MetadataCapabilities}`. `List={server_time,results:Intent[0..100],has_more:boolean,next_cursor:string|null,capabilities:MetadataCapabilities}`. next_cursor nonnull iff has_more; no total/count beyond bounded result array. One server_time supplies all expiry/action projections in a response. Withdrawal reason persists only under foundation protection; not echoed in ordinary projections.

`Error={code,message,field_errors?,request_id?}`; no other properties. code enum below, message fixed server text<=200characters, request_id server UUID, field_errors optional object whose only keys are category,filename,media_type,size_bytes,sha256,expected_version,reason,limit,cursor,Idempotency-Key; each value1..3 fixed messages<=160characters. No supplied values, PHI, filename, body, exception or SQL echoed.

## State, replay, quotas and selection

Persist only pending or withdrawn. At one final coherent selected_at, pending projects expired when selected_at>=expires_at; withdrawn always remains withdrawn. No GET status write/version bump. created_at is server-captured creation time; expires_at exactly+30minutes forever. Replay never refreshes timestamps. A slow create can return an already-expired projection; it still creates no bytes.

Fingerprint operation is exactly intent.create or intent.withdraw, with create document_id=null and withdrawal document_id canonical. The raw4096-byte limit applies only to incoming JSON, not ensure_ascii fingerprint expansion of an otherwise valid normalized payload. Fingerprint before receipt: SHA256 over UTF-8 compact sorted-key JSON (`ensure_ascii=True`, separators comma/colon) of `{operation,patient_id,document_id,payload}`; create document_id=null, withdraw document_id=path UUID; payload uses validated normalized scalar fields including trimmed filename/reason. Reject invalid values before fingerprinting; no JSON floats. This makes JSON whitespace/key order and outer trim equivalent, but changed patient/digest/reason/version a conflict. DocumentIntentReceipt actor+operation+key namespace remains separate from reception IdempotencyRecord. Receipt stores only hash/result reference, never request JSON.

Replay checks current action/scope, exact fingerprint and referenced patient/document before projection. Same key returns current pending/expired/withdrawn state and one NEW successful-disclosure event; no duplicate intent/receipt/version bump. Create replay remains201, withdraw replay200, including after expiry. New key cannot rewithdraw. Failure precedence: current global action/scope -> valid key/payload -> creator check for withdrawal -> matching receipt/fingerprint and referenced-result consistency -> new-command terminal state -> expected/max version -> mutation. A corrupt/mismatched receipt result fails503 without projection; otherwise changed fingerprint409 has no result echo/event. Valid replay bypasses transition/deadline/version checks but never current authority or creator/scope. Another creator fails403 even for terminal intent. Ambiguous commit never sends success; same-key later retry either observes committed receipt/result or safely performs missing command after current authorisation.

Proposed bounded quotas (engineering policy, not hospital capacity): <=20 simultaneously pending AND unexpired intents per patient; <=1000 new intents per organisation in rolling3600seconds. Threshold checks under the org/patient gate at creation, SQL existence threshold via bounded IDs rather than unbounded COUNT; withdrawn/expired do not consume active quota, but creation history still consumes rolling quota. At threshold429 with Retry-After until earliest applicable expiry/window exit, rounded up1..3600. Replay and withdrawal are exempt from new-intent quotas, never from authority/audit. No deletion to free quota.

All four routes use a shared durable fixed UTC-minute limiter:60 admitted requests per actor per aligned minute, across workers/branches/organisations. It explicitly permits up to120 across adjacent minute edges; never describe it as rolling60seconds. Planned one DocumentMetadataRateWindow actor-PK User PROTECT row, window_started_at/minute alignment, admitted_count1..60; reverse guard refuses nonempty state. Phase A outermost durable transaction locks fresh actor User NO KEY UPDATE -> existing IdentitySecurity -> actor limiter row, validates captured epoch/global action, then increments/resets and commits BEFORE any patient lookup or phase B. Missing row created under User lock; exact minute end resets, backward time503, saturated count429/Retry-After1..60 without growth. Failure/unknown phase-A commit503/no business work; no refund. Phase B scope404/conflict/quota/audit/commit failure retains a successfully committed allowance. Unauthenticated/no-action/invalid transport/CSRF failures before service consume none. No process cache/Redis/broker/new provider. B2 requires exact schema/constraints/execution-plan freeze and actual PostgreSQL race evidence before implementation; B1 has no limiter or DB access. Quotas do not cap all retained history; monitoring/retention and real-record activation remain release gates.

## Lock, audit and transaction gate

No target creator User/StaffAccessRevision, Bed, Appointment, Encounter or network-operator lock. `of=('self',)` prevents incidental joined locks. Actor User serializes absent same-key receipts; unique constraint is backstop. All supported metadata writers use org/patient gate. Recheck resolved patient/branch/org after waits, never follow mismatch into a second organisation lock.

Capture actor/session epoch/network descriptor at entry; reject stale epoch rather than refreshing captured proof. Recheck active identity, current exact-branch conjunction and immutable patient scope after all waits. Then select one server_time after potentially blocking inserts/checks, recheck current authority/effective network and withdrawal deadline; clock moving backward from start503. Revalidate after any later forced wait. Withdraw crossed expiry rolls back transition/receipt/event. No promise of instant revocation after selected result; network policy may change after pure final snapshot.

Event contains no filename/reason/payload. No generic admin-history union or audit browse API. Failure to commit event prevents metadata/capability/cursor disclosure. On denied/error responses do not fabricate a document event referring to an inaccessible patient.

Public services must own outermost commit: reject an ambient transaction before processing, use durable atomic boundary, return only detached primitives after successful commit. No on_commit audit, generator, model, lazy queryset or serializer query after release. Unknown commit outcome503 without projection; later keyed retry reconciles. Exceptions handled only after atomic exits, not inside a broken transaction.

Finish policy reads then choose one selected_at; final pure epoch/grant/expiry/budget checks and bounded detached encoding precede commit. Unknown COMMIT is never claimed rolled back: when execution returns,503/no projection, discard suspect connection, explicit keyed reconciliation later.
