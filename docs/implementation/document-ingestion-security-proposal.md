# Private image ingestion: security and operations proposal

**DRAFT — 8 November 2026.** Engineering proposal for reconciliation, not a frozen contract, measured capacity, implementation or release approval. Read with [ingestion design](document-ingestion-design.md), [6 November triage](../operations/document-ingestion-planning-checkpoint-2026-11-06.json) and the current metadata contract. No installs, tests, provisioning or live operations were performed for this document.

## Boundary and material assumptions

Select application-mediated raw JPEG/PNG ingress, encrypted immutable generations and one durable PostgreSQL-backed worker for **isolated synthetic acceptance**. Production placement remains blocked on coordinator host/resource/isolation inspection and storage/key/backup decisions. No public object URL, direct upload, browser preview, broker, Redis, OCR or clinical approval pipeline is needed. A registration attachment remains source material, never an approved clinical record or signature.

Coordinator read-only host observation on 8 November: 4 CPUs, 15992MiB RAM total/10961MiB available, 4095MiB swap and 122259MiB available disk; 21 existing containers; no clamd/clamscan found on PATH. This is a changing shared-host observation, not reserved capacity or complete scanner inventory. Existing swap means plaintext-spill protection is an unresolved activation gate; do not change other applications to satisfy this draft.

Inspected current `document_models.py`, `document_authority.py`, `document_access.py`, `document_services.py` and `backend/requirements.txt`: B3 uses issued request-bound contexts, a five-second service deadline, conjunctive branch grants, durable metadata admission, closed operation/error vocabularies and a 4096-byte JSON body ceiling. Existing intents constrain registration/JPEG/PNG/1–10485760 bytes/30-minute expiry/pending-or-withdrawn. Current cryptography pin is 50.0.2; Pillow and ClamAV are absent from requirements. **Pillow plus separately managed ClamAV/FreshClam are proposed new dependencies**, versions/support/patch policy to review and pin before code. Use stdlib sockets/process/filesystem/hash primitives and existing cryptography; no new framework or Python scanner client package.

Preserve four B3 endpoints, projections, receipts and historical events. New linked content/work records and ingestion projections carry byte states. A ready file survives declaration expiry; expired metadata is not proof of unavailable accepted content. Existing parent withdrawal must always deny subsequent promotion/download even if invoked through old B3; new accepted-content withdrawal must work after declaration expiry. This requires shared state checks, not changing old response schemas or pretending their creator/30-minute withdrawal rule covers ready files.

## Proposed budgets: feasibility gates, not observed results

All values below are **new proposals**. Reject/revise them before freeze if ordinary staff tasks or measured host isolation fail; do not attribute them to old October research.

| Resource | Proposed exact bound |
|---|---|
| Entity | One raw image, canonical delivered Content-Length 1–10485760, exactly declaration size and SHA-256; no multipart/content encoding/query fields |
| Transport | Upload absolute 60s from ingress start; no-progress 10s; download absolute 30s; no-progress 10s; DB admission/finalization separately at most 5s each, never extend a B3 context |
| Concurrency | 1 upload and 1 download per actor; aggregate 2 uploads/2 downloads per isolated installation; 1 validating/scanning generation; durable leases enforce cross-process bounds |
| Ingress allowance | 6 new reservations/actor/rolling minute, 60/organisation/rolling hour, 20 pending received generations/organisation; unchanged B3 allowance remains independent |
| Storage reservation | Reserve declared bytes plus 4096 envelope bytes before intake; global outstanding/retained encrypted objects cap 1GiB for synthetic adapter; reject if filesystem free space would fall below 1GiB or 20%, whichever is larger |
| Application resources | Separate byte-serving process group capped 512MiB/1 CPU; plaintext per body at most 10MiB, no disk spool; request buffering/temp files disabled or private encrypted equivalent proven |
| Image child | 256MiB memory, 5s wall, 3s CPU, 16 descriptors, no network, read-only runtime; 12000000 pixels, each dimension 8192, one frame; only JPEG/PNG decoders |
| Scan | Private clamd group provisional 2GiB/1 CPU, 1 thread; 20s client wall/attempt including transfer; max 3 attempts at initial, +60s, +300s; no accepted verdict after 10min from receipt |
| Durable work | Claim transaction 5s, lock wait 500ms/statement 2s; 45s lease, no extension, monotonic fencing token; worker poll 2s, claim one; no external I/O under locks |
| Signature readiness | Successful load, PING and VERSION/database identity within 60s, loaded official signature timestamp at most 48h old, future timestamp tolerance 5min; repeat check after scan |

Quotas consume an initial reservation even when the body later fails; exact same-key reconciliation never allocates a second generation. Transient reservations expire only after fenced reconciliation, not merely wall-clock passage. Clinical/API process limits must remain separately protected. Linux cgroup/namespace enforcement is part of acceptance; Python memory checks alone do not establish isolation. If ClamAV cannot load/update within its cap, ingestion remains unavailable; do not reduce signatures or silently raise shared-host limits.

## Minimal service boundary and sequence

Names below are proposed internal contracts, not callable tools or permission grants. HTTP operation names/routes/errors are reconciled in the separate API draft before OpenAPI freeze.

1. `reserve_upload(actor_request, patient, intent, expected_version, key)` authenticates genuine session/CSRF/effective trusted-proxy IP, current branch-conjoined patient-read/write and registration-read/write grants, creator identity, pending/unexpired declaration and feature/readiness/quota state. Commit request fingerprint, immutable generation UUID, authority provenance, capacity reservation and attempt identity; no body/storage I/O inside transaction. Same actor/key/different fingerprint conflicts; concurrent keys cannot allocate two generations for one intent.
2. `receive_generation(reservation, bounded_stream)` reads outside locks, bounds actual count, computes digest and checks declaration/media. On disconnect/timeout do not claim success. Generate encrypted immutable object; finish durable write before attempting DB receipt. Revalidate live session/epoch, current grant/scope/IP, intent/version/expiry and reservation fence under short transaction; commit content receipt, scan work and linked audit atomically. No scan before this commit is resolved. Intake must finish before declaration expiry; accepted work can finish within its separate ten-minute receipt window.
3. `claim_scan(worker_identity)` mints narrowly scoped work authority for one committed generation and increasing fence. Worker principal has only claim/read-generation/record-verdict/promote capabilities for that scope; it cannot select arbitrary patients/paths or mint user admissions. Recheck originating actor active/auth epoch, same patient/organisation/branch, creator/conjoined grants, current effective policy for recorded trusted origin IP, withdrawal and deadline before claim and promotion. No browser `DocumentContext` is persisted/reused. **Coordinator design ruling:** ordinary logout ends future browser disclosure but does not cancel an already committed durable scan command; actor epoch/grant/network revocation prevents promotion. Logout is not assumed to increment auth epoch; this ruling must enter the frozen contract.
4. `validate_and_scan(claim)` decrypts/authenticates the exact immutable generation outside locks, recomputes size/digest, performs bounded image validation and real ClamAV scan; then `finish_scan(claim, evidence)` records immutable evidence. `promote_generation(claim)` commits accepted-file pointer plus mandatory audit only after current authority, matching content/digest/validator-policy/scanner-policy/signature generation/fence and no-withdrawal checks. Promotion is a DB reference to the same encrypted object, not a rename/copy/second unscanned file. Stale lease completion is rejected.
5. `authorize_download(actor_request, accepted_file)` uses fresh current read grants/session/network checks; decrypt/authenticate/hash the whole bounded object outside locks, then short final current-authority/state/fence recheck and committed disclosure audit **before any body bytes**. No audit commit acknowledgement means no disclosure. Send only that checked in-memory generation as attachment. Recheck before every at-most-64KiB emitted block and at least once/second; stop on denial or check failure. Bytes already emitted cannot be recalled; socket/proxy buffering must be bounded and measured. Audit records attempted disclosure, not proof that the client saved all bytes.

Each short DB phase samples current authority around lock waits and before commit; grants/policy are sampled observations, not an impossible promise of atomic serialization against every later change. No worker admin bypass, public mark-clean endpoint, arbitrary scanner path/URL, retry tool, SQL/shell command or scanner-verdict import exists. Automated bounded transient retries reuse the same service/fence. Recovery operators may pause/requeue eligible failed work only through a separately contracted audited permission ceiling; this proposal exposes no operator mutation API.

## Private encrypted generations

Synthetic adapter stores outside webroot/static/media routes, under a dedicated UID/private 0700 directory with 0600 files, fixed server-generated UUID names and no caller path components. Open relative to retained directory descriptors; reject symlinks/nonregular files, require exclusive create, fsync file and directory, and prohibit overwrite. Scanner UID cannot read keys, DB credentials or storage; image child receives only one bounded plaintext buffer, no filesystem credentials. Shared `www-data` ownership is not acceptable proof of this separation.

Use an independent random 256-bit data key per generation; AES-GCM encrypt the entire bounded payload with a fresh 96-bit nonce. Canonical associated data binds envelope version, organisation/patient/intent/generation IDs, size and digest. Wrap the data key with a separately managed document KEK and independent nonce, binding generation and KEK version; store wrapped key and version in DB. Object envelope has bounded fixed-format header/nonce/ciphertext/tag, no secrets. Fail closed on missing key, wrong AAD/tag/digest, missing object or unsupported envelope. Never release unauthenticated plaintext. AEAD nonce discipline and tag failure are described in the [cryptography 50 documentation](https://cryptography.io/en/50.0.0/hazmat/primitives/aead/). This envelope design needs independent cryptographic review; existing MFA Fernet keys are never reused.

KEK rotation rewraps data keys without changing file identity/verdict; keep old keys through verified dependency-manifest restoration, not just until latest deployment. Process memory is not durable encrypted storage; disable plaintext spill/core dumps and require encrypted swap or disabled swap in acceptance. No claim of perfect Python memory zeroization.

## Image checks and genuine scanner

Layer declaration/extension policy, magic/detected decoder agreement, full decode and malware scanning; neither filename nor MIME nor clean antivirus is sufficient. Preserve original bytes/digest; no hidden recompression, EXIF extraction or clinical interpretation. [OWASP upload guidance](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html) supports layered controls and private storage.

Image child sets explicit pixel limit and treats decompression warnings as errors; `verify()`, reopen, enforce format/dimensions/frame count and `load()` with truncated-image acceptance disabled. Reject animation, unsupported formats and decoding errors. Enforce bounded PNG ancillary/text processing and JPEG metadata through the same memory/time cap; rejection is preferable to decoder resource escape. Pillow documents that verification does not decode image data and reopening is needed; [Image reference](https://pillow.readthedocs.io/en/stable/reference/Image.html) informs these checks. This is not proof that every polyglot/trailing payload is rejected; original full bytes are scanned and only attachment-delivered. Strict trailing-container policy requires representative parser tests before freeze.

Clamd uses a private Unix socket mode0660, no TCP listener; service account separation and no outbound scanner access except dedicated FreshClam update path. Client permits only fixed PING/VERSION/INSTREAM. Send `zINSTREAM` plus NUL, 64KiB chunks with network-order four-byte lengths, then zero length; bound reply to 4096 bytes and require exactly the expected clean reply/terminator. FOUND, ERROR, limit, malformed, EOF and timeout never become clean. [Official clamd protocol](https://raw.githubusercontent.com/Cisco-Talos/clamav/main/docs/man/clamd.8.in) defines this framing; [scanning guide](https://docs.clamav.net/manual/Usage/Scanning.html) warns TCP lacks authentication.

Proposed daemon limits: StreamMaxLength=10485760, MaxFileSize=12582912, MaxScanSize=33554432, MaxRecursion=4, MaxFiles=100, MaxThreads=1, MaxQueue=2, AlertExceedsMax=yes. Keep engine formats/signatures enabled; application rejects nonimages independently. Real version-specific behavior must be checked: limits can skip work, and MaxScanTime is not a universal wall deadline. Therefore timeout kills/quarantines the isolated scanner service generation and fences its result before retry; merely closing a socket is insufficient. These cautions follow the [official configuration sample](https://raw.githubusercontent.com/Cisco-Talos/clamav/main/etc/clamd.conf.sample). Pin supported engine/config; sample-main options are not assumed available in installed versions.

FreshClam alone updates official signed databases; updater cannot mark files clean. Snapshot loaded database identity before/after attempt, reject reload ambiguity, retain engine/signature/config/validator identities with verdict. A recent updater log or PONG alone is not readiness. Last-attempt transient failure remains unavailable/quarantined; malware/invalid-image outcomes are final for that generation.

Clamd temporary extraction storage must be dedicated non-swappable memory storage capped32MiB, never shared `/tmp`; overflow is non-clean. Bound scanner logs to10MiB with two retained rotations and omit filenames/content/signature payloads from staff errors. Existing accepted content does not become unaccepted on each routine signature update or scanner outage; explicit security quarantine and restore-rescan remain denial paths. This availability choice needs contract freeze alongside readiness behavior for new intake.

## Commit ambiguity, retention and restore

Object-write-before-DB failure leaves encrypted orphan on hold, never downloadable. Reconcile original reservation/key via fresh authorized read; unknown DB commit must not trigger deletion, new identity or rescan promotion. Inventory job uses bounded batches of 100 every five minutes, no object I/O under locks. Delete only orphan proven unreferenced on two authoritative DB checks at least 24h apart, with no active reservation/lease/ambiguous commit/backup hold; uncertainty retains and alerts. Withdrawn/failed/quarantined content has proposed seven-day minimum hold then explicit audited retention policy; ready attachments have **no automatic deletion in this slice**. Full-store condition refuses new intake, never evicts records to make room.

Withdrawal is durable visibility denial plus fencing; retain accepted/history/scan identities. Scan completion cannot resurrect it. Deployment rollback first closes new capability/work admission and drains or fences old workers; older source sees retained B3 rows unchanged, and must never expose new content. No destructive reverse migration/object purge.

Backup manifest binds DB snapshot, all referenced generation hashes/envelopes, KEK versions and recovery material, schema/validator/scanner policies and retention holds. Restore into isolated scoped storage/DB, verify keys and generation integrity, fence leases and disable byte serving. Rescan accepted generations against current ready signatures before re-enabling downloads. Never restore shared patient/branch data blindly or infer trustworthy scan state from a copied ready flag.

## Required evidence before freeze/release

Freeze HTTP/page-action/schema/authority/retention contracts after scenario/threat/test review. Then literal executable RED before implementation; actual PostgreSQL barriers for dual upload, grant/epoch/IP change, withdrawal/promotion/download, lease expiry, unknown commit and audit failure. Use real isolated Pillow/ClamAV with clean images, safe EICAR scanner fixture, invalid-image rejection, exact 10MiB/+1 boundaries, decompression bombs, stale/reloaded signatures, corrupt/missing key/object, socket failure and timeout-process cleanup. A mock clean scanner cannot establish acceptance.

Require actual HTTP1.1/H2 CSRF/framing/body/disconnect tests on byte routes: B3 metadata no-Range/header behavior and five-second budget are not byte-route evidence. Freeze download Range/conditional rules separately (proposal reject Range/conditionals, no304/206), no-store/VaryCookie/nosniff/attachment, no public redirects or presigned URLs. Preserve delivered-entity/hidden-WSGI-byte limitations honestly.

Measure memory/CPU/disk/isolation, queue/backpressure and revocation interval with competing synthetic clinical traffic. Prove backup+retained-key+object restore and old-source rollback, fresh independent security review, exact CI/push, reviewed restricted-preview rollout/live verification and useful keyboard/staff workflow before activation. Production provider/host feasibility, clinical use and broader hospital release remain separate open gates.
