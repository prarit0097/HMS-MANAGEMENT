Helpers validate immutable stored preview/change graph and bindings, current path, reason/request digest/normalisations and monotonic revisions. 5. `backend/apps/core/network_api.py`: six management API views and network-only probe; strict duplicate-key JSON parser, 32KiB bounded read independent of Content-Length, object/exact fields/media/query/canonical UUID/strict integer validation. No shell, SQL, URL, arbitrary JSON/file policy or fabricated HTTP identity. Commands `management/commands/network_policy.py` and `network_operator.py` adapt argparse to typed services; exit 0/2/3. Recovery uses validated stored candidate/fallback only; transfer is the sole explicit old/new owner mismatch exception.
7. ## Lock and outcome protocol

HTTP transaction lock order: canonical actor User NO KEY UPDATE, existing IdentitySecurity FOR UPDATE (no create needed because enrolled is required), owner Organisation NO KEY UPDATE, actor NetworkOperator FOR UPDATE, singleton FOR UPDATE, addressed preview FOR UPDATE, addressed/current changes sorted UUID FOR UPDATE, event last. Preliminary reads never authorise. After all blocking boundaries and immediately before final changes/event, reload current authority rows/session digest/epoch/proof, current settings/resolver/IP, singleton/immutable graph/current path and fresh time. Insertion/FK dependencies are locked before final decision; after the last event INSERT (including possible uniqueness/FK waits), perform a final fresh authority/path/proof/deadline check; failure raises inside atomic and rolls back the entire business operation/event. No Branch/Bed/staff locks. Before independently committed expiry maintenance, current caller authority and effective path must already pass; domain conflicts are returned after that maintenance rather than throwing inside its atomic block.

OOB locks known actor/target Users sorted PK, identity rows sorted PK, Organisations sorted UUID, entitlements sorted (user,org), singleton, previews/changes. No new late actor discovery. Reconcile locks singleton then current change only and never calls actor operations. Staff's User then Organisation order is preserved. Revision overflow fails unavailable without partial event.

Preview fixed 300 seconds, no revision increment. Activated immutable candidate/fallback fixed 300 seconds, exactly one revision/event. Exact replay reauthorises and checks original expected revision and immutable bindings, never extends time. Terminal activate replay returns current terminal outcome. Confirm/revert opposite operation conflicts; same exact terminal replay succeeds without overwrite. Equality at rollback deadline selects fallback read-only; subsequent mutation materialises exactly one expiry then commits a stale-revision/expired conflict. Owner/version/epoch/session/IP/environment changes invalidate bindings. Candidate current-path denial prevents activation, OOB may deliberately recover to stored snapshot.

## Scenario, abuse and failure coverage

Positive synthetic owner master + OS entitlement + enrolled fresh proof. Reject master-only/operator-only/superuser/foreign owner/inactive actor/membership/operator, missing/corrupt/mismatched owner, stale/missing/future/NaN/bool proof even with ordinary MFA disabled. Reads create nothing. Replays cannot bypass path revocation or current authority. Malformed saved policy/digest/pointer fails503; denied environment remains403 without requiring DB. No GET repair/fallback cache. Guessed IDs concealed after authority. Duplicate query/JSON keys, coercions, nested/unknown/body-size/header/media/file/method attacks reject safely. History private target/version/owner/binding fields omitted; optional corruption null versus required corruption503. Probe is handled completely by NetworkPolicyMiddleware with early empty response after validated context/evaluation; SessionMiddleware is never entered even with SESSION_SAVE_EVERY_REQUEST. The explicit IdentitySessionMiddleware exact-path AND validated-marker skip remains defence in depth. Cookie/Authorization never causes epoch/logout/Set-Cookie.

## Security-review precisions before code

Environment binding fingerprint includes canonical policy, sorted canonical trusted proxy networks and owner descriptor: canonical UUID when valid, `missing` when empty, or SHA256 of invalid raw owner text with `invalid` discriminator. Enforcement does not require a valid owner, but a changed owner descriptor invalidates HTTP bindings. Invalid trusted-proxy configuration fails unavailable, never silently removes trust. Probe peers are separately validated loopback-only addresses.

Mutation transaction matrix: lock current identity/owner/operator/state and validate authority/current path before maintenance. Independently valid elapsed pending may be reconciled in the outer transaction. Perform requested business operation in inner atomic savepoint. Business conflict/expired response preserves authorized expiry accounting; final loss of authority/path/proof raises through outer transaction and rolls all work back, including expiry. Final business event insertion wait crossing its action deadline rolls back inner operation and then performs fresh authorized expiry reconciliation in outer transaction, returning409. Final post-insert timestamp and checks cannot merely reuse pre-insert `now`.

PostgreSQL matrix additionally includes explicit event INSERT/FK wait crossing preview/rollback/MFA deadlines, current path revoked during a wait, and two simultaneous reconcilers. Test-only baseline fixture runs once before a test, never request-time; missing-state tests explicitly delete singleton after fixture and no reseed occurs. Old transaction fixtures can opt out using a marker if they own migration/singleton lifecycle.

OOB recovery locks and validates complete current singleton pending graph first; addressed historical snapshot change and current pending change are locked together in UUID order after singleton. It validates both historical candidate/fallback digests and the chosen snapshot. If an active pending differs from addressed history, terminalise the current pending recovered and preserve reciprocal preview links. Recovery changes singleton once and appends a recovery event referring to the addressed immutable snapshot; it does not synthesize a new terminal Change (which would require fictional activation revisions), rewrite any terminal historical Change, or rewrite reciprocal links. With no current pending, only singleton and event change. Recovery dry run does not reconcile or write. Owner transfer similarly validates graph and preserves immutable links while terminalising existing pending with owner_transferred.

Coordinator ruling: HTTP network history remains filtered to the currently bound owner; historical foreign-owner events are not added to ordinary organisation audit feeds. Explicit OS recovery may select historical snapshots only under its separate audited authority. Environment fingerprint canonicalisation must preserve valid existing OS-configured resolver/network syntax; the stricter user-entered Policy grammar does not silently redefine trusted proxy parsing. Invalid configuration still fails closed.
