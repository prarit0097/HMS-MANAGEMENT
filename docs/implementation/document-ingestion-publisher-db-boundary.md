# Supervisor readiness: database privilege boundary

**DRAFT — 15 November 2026, Asia/Calcutta.** Proposed design only: no role, grant, function, schema, runtime, API or credential is created. Read with [launch proof](document-ingestion-launch-proof-draft.md), [guard authority](document-ingestion-guard-authority-contract.md), [persistence](document-ingestion-persistence-contract.md) and [runtime](document-ingestion-runtime-contract.md). Parent ingestion is unfrozen; S1 facts do not establish OS authority.

## Existing source and smallest candidate

`backend/hms/settings.py` uses the configured default database identity for Django. `infra/hostinger/prepare_host.py` initially creates `hms_app` and makes it database owner; this source is not a fresh inspection of live ACLs. NOCREATEDB/NOCREATEROLE alone does not prove column/function isolation. Do not reuse the general application/migration credential for the supervisor or assume that a Python method limits arbitrary SQL permitted to its login.

This proposal isolates the **publisher credential**, not the entire existing application/database-owner blast radius. Compromise of a general owner/migration credential is outside that narrow guarantee and can invalidate wider database security/availability assumptions. Before activation, inventory actual ownership/membership/schema/default privileges and freeze how new protected ingestion objects are created outside runtime ownership. No existing role is silently downgraded or declared isolated here.

| Choice | Benefit | Missing protection |
|---|---|---|
| Readiness-column UPDATE grants only | Small ACL change; expected-launch and gate columns can remain excluded | Allows arbitrary permitted readiness values, bypassing intended tuple/expiry/transition predicates. Existing table-level or inherited grants defeat column exclusions. Does not authenticate OS process identity. |
| Fixed typed SECURITY DEFINER lifecycle/readiness functions, no publisher table DML | Centralises the allowed conditional readiness mutation; direct writes to readiness, gates, accounting and expected launch are denied | Adds a tightly reviewed SQL security boundary. It still cannot authenticate launch descriptors, real scanner evidence or a Linux process from supplied SQL arguments. |

**Candidate:** the second choice for scanner registration/invalidation, publication/renewal and fixed unknown-ACK status lookup. This is one closed internal business vocabulary, not a general SQL broker. No enable/expected-launch-install/restore/claim endpoint is included. The candidate signatures below require an exact SQL/schema leaf before implementation; they are not executable code.

PostgreSQL permits column privileges, but a table grant still applies when a column grant is revoked. This rules out subtractive column restrictions on an already privileged login. [PostgreSQL 17 GRANT](https://www.postgresql.org/docs/17/sql-grant.html). Ownership also carries rights that ordinary revocation cannot permanently remove; publisher must not own protected objects. [PostgreSQL 17 privileges](https://www.postgresql.org/docs/17/ddl-priv.html).

Names below are candidate labels, not provisioned accounts. All dedicated service logins are NOSUPERUSER/NOCREATEDB/NOCREATEROLE/NOREPLICATION/NOBYPASSRLS, without grant options or membership/SET ROLE paths into privileged roles.

| Identity | Ceiling |
|---|---|

Function creation, PUBLIC-execute revocation and exact publisher grant occur in one future migration transaction. ## Typed business contract to freeze

Publication accepts only a closed tuple: installation/epoch, exact supervisor launch instance/context, independently named scanner generation, fixed manifest/policy/signature hashes, bounded observation timestamps, and one proposed publication UUID. No gate/accounting/expected-launch assignment, raw JSON expansion, actor ID, dynamic object name or SQL text is accepted. Exact scalar types/ranges and the final generation-name mapping must be reconciled with the generation draft before freeze.

The trusted supervisor service takes fresh guard/process/scanner observations **outside** every database transaction. The database primitive receives detached immutable values; SQL does not perform filesystem, network, key, scanner or process I/O. It locks only Control, skipping earlier untouched rows in the common lock order. Caller must not acquire earlier-order User/IdentitySecurity/Actor locks after this call within the same transaction. Maintenance takes the same Control lock; no process stop/start under that lock.

While locked, require the singleton to exist and be valid, installation/epoch and complete expected launch equality, API enabled, correct active current scanner generation/manifest/policy, and the database portion of first-slice authority. Non-restore external guard/process provenance must already be independently checked by the trusted service outside locks; this SQL comparison cannot authenticate it or detect a restored matching snapshot by itself. Missing/corrupt state fails closed. Require actual evidence ages and a server-checked validity cap no later than the permitted observation expiry and 60-second readiness bound; a caller timestamp cannot extend age by replacing the original observation. The publication function changes only the complete readiness tuple and its linked launch/scanner identities; the separate lifecycle primitives below may register/clear current scanner fields. Neither changes any gate or expected identity. Fixed denials expose no patient data or raw scanner signatures.

## Concrete scanner lifecycle bootstrap candidate

The following closed internal primitives resolve the former registration bootstrap gap as a **candidate**, not an implemented path. `L` is the complete immutable expected-launch tuple: installation/epoch/launch-instance/boot/PID/start-ticks/fixed-unit/runtime-manifest. `S` is immutable daemon-instance UUID, engine/config/validator/signature SHA256 values and signatures timestamp. Daemon identity is established once by the trusted supervisor after an actual owned daemon start, never from request data or DB rereads. Scanner generation is server-generated only on a successful registration CAS; a caller cannot choose it. Exact canonical hash/scalar/time domains must become SQL types/checks in the leaf.

| Candidate typed signature | Locked transition and closed result |
|---|---|
| `register_scanner(L, expected_previous_scanner_generation?, registration_operation, S) -> registered(generation) / same_current(generation) / denied` | Fresh trusted launch/guard/process/daemon observations precede lock. Under Control require valid singleton, exact expected L, API enabled and scans=0. Same current registration operation returns `same_current` only for the identical immutable fingerprint and active current registration; it is status/reconciliation, never a second start. Otherwise require inactive/retired scanner state and expected_previous_scanner_generation equal to the retained locked generation (NULL only before first registration). Server generates a fresh generation, writes operation/fingerprint/S, sets active=true and clears readiness atomically. No gate/expected-launch/counter changes. Fingerprint includes L, predecessor and S; a changed same-operation payload denies. |
| `invalidate_scanner(L, scanner_generation, reason) -> invalidated / same_retired / denied` | Match current trusted launch and exact targeted retained generation; API may already be closed and scans may be1. In one Control transaction set scanner_registered_active=false, record retired_at/reason and clear readiness; retain generation, operation, registration fingerprint/S as a tombstone/CAS predecessor. Identical already-retired target is a no-op `same_retired`; wrong generation cannot clear a replacement. Reasons are fixed `daemon_fault`, `readiness_expired`, `snapshot_replace`, `supervisor_stop`. No counter release or cessation claim. |
| `scanner_status(L, registration_operation, registration_fingerprint) -> active(generation) / retired(generation) / unavailable` | Fixed bounded Control lookup. Match current retained operation/fingerprint and L. Active additionally requires current API/expected-launch/scanner authority; retired proves current durable invalidation only. Absent, replaced, mismatching or uncertain operations return unavailable, not rollback or historic outcome. Caller may reconcile with API closed, but receives no current authority while closed. No patient/raw scanner output. |
| `publish_readiness(L, scanner_generation, publication_uuid, evidence) -> published / same_current / busy / denied` | Require current exact L/S, active scanner registration, API enabled and fresh unchanged immutable scanner snapshot. New token rotation requires scans=0 under Control; scans=1 returns `busy` without modifying token/evidence or extending expiry. Reconcile same publication UUID only with identical evidence fingerprint/current token; no retagging. Existing parent server-capped observation/validity rules apply. |

`invalidate_scanner` is deliberately allowed while busy: faults/expiry fence old work immediately, while that work retains its issued tuple and capacity until separately confirmed cessation/reconciliation. Any new actual scanner start requires the supervisor to confirm the previous owned daemon/descendants and issued scan writers ceased outside locks, reconcile their held slot through the separate worker-accounting contract, then call registration with a fresh operation/daemon identity and the exact retained previous generation. Control scans=0 is necessary, not a proof of death. Registration never decrements counters or manufactures cessation evidence.

Use bounded Control state, **no new lifecycle receipt table**: retained nullable scanner_generation, registration_operation UUID, registration_fingerprint SHA256, registration_supervisor_launch_instance/registration_restore_epoch, daemon-instance/policy/signature tuple, registered_at; scanner_registered_active bool defaultfalse; nullable retired_at/reason. Before first registration the registration tuple is all absent/activefalse/no retirement. Active requires complete registration tuple and no retirement; retired requires complete tuple and finite retired_at/fixed reason. New CAS replaces the retired tuple, retaining only the latest registration. Exact fields/checks join the future schema leaf. This supplies current-operation reconciliation, not a permanent historical operation ledger or full replay receipt. Historic attempts retain their issued generation evidence independently.

Predecessor equality prevents delayed old registration from replacing a later lifecycle: it must retain its original expected predecessor, operation and fingerprint on every reconciliation; never rebase to freshly read Control or retry a replaced operation as a new start. An old replaced outcome may remain permanently unavailable. Server generation is new per committed CAS; the process must keep the same pending actual daemon identity until commit is resolved, and must not start a second daemon on an unknown ACK. Trusted OS cessation and no-overlapping-start enforcement remain necessary; SQL CAS does not prove one operation corresponds to one physical start. Registration operation UUIDs are fresh for new legitimate starts; the bounded state does not claim global historical UUID-deduplication against a compromised caller.

All primitives lock only Control; do not invoke them after acquiring patient/work locks. OS observations occur before the transaction, with no OS I/O while any transaction/Control lock is held. Registration/invalidation cannot install expected launch, open API/intake/download or set scan counters. Root expected-launch replacement separately fences scanner/readiness under maintenance; old publishers cannot adopt the new expected tuple. The SQL receives trusted detached observations but cannot authenticate them; untrusted credential possession is not converted into OS proof.

Normal readiness renewal cannot invalidate an already issued attempt by rotating its token while scans=1. Claims serialise on Control and acquire the remaining claim rows in common order, then after the final claim-row lock wait take a fresh actual server-clock sample, recheck current L/S/token/active registration and require the complete original capped attempt end (at most45s) strictly less than readiness_valid_until. Equality denies; transaction-start now()/CURRENT_TIMESTAMP cannot replace that fresh clock sample. Neither lock waiting nor renewal remints the claim origin or attempt end. Claim takes the single scan slot in that transaction. If insufficient remaining validity, do not claim; request a normal new observation/renewal only after scans=0. Expiry or fault may still invalidate busy work; its token becomes stale and promotion denies, while cessation controls release. The <=60s readiness/45s attempt/one-slot liveness remains unmeasured acceptance, not throughput or completion evidence. The bounded current-publication schema/status candidate below requires exact leaf review before implementation.

Function success inside a transaction is not known COMMIT. Do not advertise readiness until the outer transaction has known commit and a new outside-lock guard/process check succeeds. No SQL function creates an atomic OS/DB view or instant revocation. Dedicated process credentials plus trusted code/descriptor custody are still required; a caller possessing the publisher credential could invoke the narrow function with fabricated evidence matching readable identity values. This candidate contains that credential to readiness operations; it does **not** prove evidence truth or resist arbitrary execution in the approved supervisor.

For a lost COMMIT ACK, remain locally unready. Reconnect using the same publication UUID and exact immutable evidence fingerprint; fixed status lookup under current Control may confirm that exact tuple only. A replaced launch/generation, closed API, expired evidence, mismatched token/fingerprint or unresolved status never implies permission. Do not generate a fresh observation time/token to conceal uncertainty, reopen gates, or assume old readiness disappeared. Once uncertainty resolves, a genuinely new observation is a separate normal renewal, with its own current authority checks. Only the bounded current-publication storage/status candidate below is proposed; exact SQL and independent acceptance remain required, with no historical outcome guarantee.

Retained registration launch/epoch must equal the current expected launch/epoch for publication or active status; a root replacement invalidates active registration and readiness before any new launch. Old retained identity remains only the next CAS predecessor.

Known registration COMMIT must precede any readiness publication; successful registration is not scanner-clean evidence or permission to claim. Unknown registration ACK uses the same L/operation/fingerprint in status; no second daemon/start/UUID is minted. If that generation is retired or launch/API/scanner state changed, remain unavailable and perform the normal cessation/replacement procedure. Unknown invalidation ACK immediately makes the supervisor locally unready and stops/fences owned work outside locks; status resolves the original retirement without restoring it. An uncertain outcome never justifies slot release.

Root install/replacement requires ingress and ordinary callers stopped, previous launch fenced, readiness cleared, old-process cessation proved outside locks, and a known committed expected tuple before publication. Failed cessation or unknown expected-install ACK blocks replacement. Restore retains external epoch authority and closed gates; copied expected/readiness fields cannot activate this first slice. No function is authorised to install an epoch or re-enable restore.

## Bounded Control schema candidate —15 November2026

This section replaces the earlier open registration/publication-storage obligation with an exact **DRAFT field candidate** in `core_documentingestioncontrol`, not new tables or installed SQL. Existing singleton PK/id=1, gates, storage/transfer/scan counters and their existing constraints remain. Types are PostgreSQL UUID, BOOLEAN, BIGINT, SMALLINT, VARCHAR and TIMESTAMPTZ; every time below is finite, UTC-serialisable within Gregorian years0001..9999, and every SHA256 is exactly64 lowercase ASCII hex characters. UUIDs are equality fences, not process authentication or ordered counters. No extra indexes beyond the singleton PK are needed for these bounded lookups; actual plans remain acceptance evidence.

| Group | Candidate fields and static checks | Mutating authority |
|---|---|---|
| Namespace | `installation_id uuid NOT NULL`, existing `restore_epoch uuid NOT NULL`; first-slice service never changes either. | Separately reviewed root maintenance/fresh-install procedure only; no runtime function may restore/re-enable. |
| Expected launch | Nullable `expected_supervisor_launch_instance uuid`, `expected_supervisor_boot_id uuid`, `expected_supervisor_pid bigint`, `expected_supervisor_start_ticks bigint`, `expected_supervisor_unit varchar(128)`, `expected_supervisor_manifest_sha256 varchar(64)`; six fields all absent or all present, PID>0/start>=0, fixed reviewed unit literal and hash grammar. | Root-install identity only, never publisher/function owner. Exact current tuple equality is the lost-install-ACK reconciliation identity; no speculative second launch. |
| Retained registration | Nullable `scanner_generation uuid`, `registration_operation uuid`, `registration_fingerprint varchar(64)`, `registration_supervisor_launch_instance uuid`, `registration_restore_epoch uuid`, `scanner_daemon_instance uuid`, `scanner_engine_policy_sha256 varchar(64)`, `scanner_config_sha256 varchar(64)`, `scanner_validator_policy_sha256 varchar(64)`, `scanner_signature_sha256 varchar(64)`, `scanner_signatures_at timestamptz`, `scanner_registered_at timestamptz`; entire tuple all absent or all present. Generation and registered_at are server-generated once on new registration CAS; other immutable snapshot fields bind the original actual daemon. | Restricted lifecycle-function owner through register only; publisher login no DML. Initial absence is legal only with active=false and no retirement/readiness. Replacing a retired tuple is permitted only by the typed predecessor CAS. |
| Registration state | `scanner_registered_active boolean NOT NULL DEFAULT false`; nullable `scanner_retired_at timestamptz`, `scanner_retired_reason varchar(32)` using only the four fixed invalidation reasons above. Active requires complete registration/no retirement, registration launch=expected launch and registration epoch=current epoch. Complete inactive registration requires both retirement fields, retired_at>=registered_at. Initial absent registration requires neither retirement field. | Restricted invalidate/register functions; root launch replacement may force inactive retirement and clear readiness. Neither path releases counters or proves OS cessation. |
| Current publication | Nullable `publication_operation uuid`, `publication_fingerprint varchar(64)`, `readiness_token uuid`, `readiness_supervisor_launch_instance uuid`, `readiness_scanner_generation uuid`, existing `readiness_checked_at timestamptz`, `readiness_valid_until timestamptz`, `engine_policy_sha256 varchar(64)`, `validator_policy_sha256 varchar(64)`, `signature_sha256 varchar(64)`, `signatures_at timestamptz`. Entire publication tuple all present iff `intake_ready=true`, otherwise all absent. True requires active registration, publication launch=expected/registration launch, scanner generation=retained current generation, exact registered engine/validator/signature hash and signatures_at equality, valid_until>checked_at and valid_until<=checked_at+60s. | Publish function generates readiness_token once per new operation, writes complete publication tuple atomically only while scans=0; invalidate/root replacement clears the complete tuple. No expected-launch/gate/counter privilege. |

`intake_ready` is stored evidence, not a promise that time has not advanced: static CHECKs enforce tuple shape/equality/time ordering only. Actual `clock_timestamp()`-equivalent server sample after lock waits must be strictly before evidence/validity cutoffs; no CHECK using wall time or transaction-start clock is proposed. Clock sampling and original caller monotonic deadline checks cannot extend real evidence lifetime. Hash/config/signature fields are internal and excluded from ordinary staff responses/logs.

Registration fingerprint is SHA256 of a closed canonical JSON object containing the complete L, original expected previous generation (JSON null initially), and complete S; keys sorted, compact separators, ASCII output, no optional/extra fields/floats, lowercase canonical UUID/hash spellings, integers as decimal JSON integers, timestamps as exact UTC `YYYY-MM-DDTHH:mm:ss.ffffffZ`. It excludes server-generated generation/registered_at. Publication fingerprint uses the same encoding over complete L, current scanner generation and original immutable evidence (including checked_at and original evidence-expiry). Replaying an operation with a different fingerprint denies; never reconstruct a new fingerprint using current DB identities to rebase old evidence. Exact closed key names and platform integer/unit limits must be reconciled with the launch wire/schema leaf; no parser/authentication claim follows from canonical hashing.

Add fixed `readiness_status(L, scanner_generation, publication_operation, publication_fingerprint) -> current(token, checked_at, valid_until) / unavailable`. It locks Control and confirms exact expected/registered/publication launch+epoch/scanner/op/fingerprint, active registration, API enabled, intake_ready and still-valid original evidence using a fresh actual server-clock sample. Invalidated, expired, replaced, mismatching, absent or uncertain publication returns unavailable, not historical failure or rollback. All response fields are bounded internal values. Matching `publish_readiness` operation is reconciliation only: return the same current token/times without extending expiry, even when scans=1; a new operation during scans=1 returns busy unchanged. A known current result remains locally unusable until the trusted service's fresh outside-lock guard/process check passes. This bounded current-status protocol supplies no historical receipt ledger.

Root installer may run in the **single fixed root launcher before permanent privilege drop**, but privileged DB credentials/connections must be closed and excluded from the final supervisor and its children. Under short Control transaction it installs the exact intended expected tuple, marks prior registration inactive with retirement evidence if present and clears publication; after known commit and outside-lock process/guard reconciliation it may continue the reviewed launch handshake. It performs no process/key/filesystem I/O while locked and does not borrow publisher credentials. Gate changes are separately reviewed root operations; launch install does not implicitly open them. Fixed root install status compares the same complete tuple after unknown ACK, never remints it. Credential drop/descriptor closure is an OS acceptance gate, not supplied implementation.

Restricted function-owner UPDATE grants enumerate only the retained-registration/state/publication columns above and `intake_ready`; SELECT is only the namespace/expected/current-state/gate/scans columns those fixed functions require. No expected fields, api_enabled/intake_open/download_open, namespace, counters, patient tables, table ownership or schema CREATE is writable by that owner. Root maintenance owns a separate installation capability; publisher LOGIN receives EXECUTE only and cannot SET ROLE to either owner. No broad table UPDATE grant may coexist with column exclusions. Schema-owner/migration credentials remain outside runtime; current general application-owner blast radius is not solved by this narrow candidate.

## Required literal tests before implementation

- Direct publisher INSERT/UPDATE/DELETE/TRUNCATE/ALTER/GRANT against Control, expected-launch/gate/accounting columns and patient tables fail; allowed EXECUTE alone succeeds only under its typed preconditions.
- App/worker/scanner/decoder/guard-reader credentials cannot execute publisher functions or assume their owner. Test indirect memberships, inherited table grants, PUBLIC privileges and writable schema/temp-object shadowing.
- A paused publisher cannot renew after API close, launch replacement, scanner replacement or epoch change while awaiting Control; no forbidden column changes occur on success, denial or exception.
- Registration before readiness, duplicate identical registration, changed fingerprint, stale predecessor/rebased-operation attempts, closed API, scans1 registration denial and invalidation while busy all preserve exact tuple/counters. New registration waits for confirmed old cessation and scans0.
- Lost register/invalidate/publication/install ACK tests preserve original UUID/fingerprint/times and independently inspect durable state; late ACK/expiry remains locally unavailable and never flips gates.
- Claim versus renewal serialises on Control: scans1 renewal cannot rotate/extend; claim after its final row-lock wait uses a fresh actual clock sample and requires original whole capped attempt_end < current token expiry, with equality denied. Expiry/fault may invalidate busy work without releasing capacity.
- No OS/scanner/key/process I/O under Control locks; failed postcommit guard/process observation suppresses advertisement. Malformed tuple/hash/expiry and nonexistent/corrupt singleton deny safely.
- Fixed-function owner is non-login, non-superuser and cannot replace expected tuple or gates; hostile search_path/temp objects cannot redirect any query; migration grants are atomic and have exact overload signatures.

No executable tests were run for this proposal. Freeze remains blocked on exact SQL/signatures, new protected schema ownership and migration strategy, credential custody, generation mapping, launch provenance, bounded Control CAS/current-status field constraints, lock/time budgets and actual isolated PostgreSQL/LINUX acceptance. No current source/runtime/preview capability changes.
