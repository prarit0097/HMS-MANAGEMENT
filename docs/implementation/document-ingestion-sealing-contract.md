# Registration ingestion: immutable sealing contract

**DRAFT — 10 November 2026.** Proposed resolution of replay, encryption and crash-recovery findings in the [security](document-ingestion-security-proposal.md) and [API](document-ingestion-api-proposal.md) drafts. This document controls those proposed details where they differ. It is not frozen, implemented, tested or deployed. Coordinator reconciliation with persistence/API/UI contracts and fresh independent review precede freeze, executable RED and code. No new operator endpoint, public mark-clean action or privileged generic tool is introduced.

## Chosen boundary

One declaration permits one reservation and one immutable generation, including failed sealing. A failed one-use seal requires an explicit new declaration; it cannot silently reuse the old identity. This sacrifices automatic recovery of interrupted encryption to preserve nonce discipline. Existing complete final objects can be reconciled without encryption. Replay never creates a quarantine candidate. Fresh internal encryption attempts under the same declaration and streaming unauthenticated encryption are rejected for this slice.

The first-binding cutoff is immutable: the earlier of declaration expiry and original post-authentication/real-CSRF context capture before reservation/body reading plus60seconds. The trusted ingress time is captured by the controlled ingress/service, never a caller header; actual edge-to-service timeout alignment needs protocol acceptance. The original request also enforces its monotonic60second deadline. A replay gets its own bounded body-reading deadline but never extends the original binding cutoff. First binding must commit strictly before the cutoff. Each DB phase has its own at-most5second transaction; no captured B3 context is extended.

## Durable facts and cryptography

The persistence contract must represent one reservation per intent and actor/operation/key uniqueness, declared fingerprint, immutable generation/scope/declaration facts, trusted start/cutoff, owner process identity, UUID equality fence, state and reserved bytes. Each claim/reconciliation replaces the UUID with a freshly generated value; all mutations require exact current-token equality. No ordering comparison or bigint counter is used. Lifecycle: `reserved → sealing → bound`, or either unbound state to `held_terminal → purging → purged`. No backward transition. A reserved body failure is terminal too. Content, receipt, work and response audit bind atomically. Reservation/crypto history remains after purge.

After bounded input verification, generate a fresh32byte DEK using `AESGCM.generate_key(bit_length=256)` and fresh12byte nonce using `os.urandom`. Use one `AESGCM.encrypt` call, with its full16byte tag, per generation. A separate random32byte document KEK uses library `aes_key_wrap`/`aes_key_unwrap` without padding:32byte DEK becomes40wrapped bytes. RFC3394 AES-KW has no caller nonce or AAD; it removes the shared-KEK nonce schedule proposed previously. No hand-written cipher/wrap algorithm or MFA key reuse. [Cryptography AES-GCM](https://cryptography.io/en/50.0.0/hazmat/primitives/aead/) forbids nonce/key reuse; [its key-wrap API](https://cryptography.io/en/50.0.0/hazmat/primitives/keywrap/) implements [RFC3394](https://www.rfc-editor.org/rfc/rfc3394).

Before encryption/object creation, known-commit the one-use `sealing` claim with wrapped DEK, wrap algorithm/version, initial KEK version, nonce, exact AAD and fence. Plaintext DEK is never stored in DB. Key IDs use ASCII `[A-Za-z0-9_-]{1,64}` and exact configured lookup; no arbitrary key paths, aliases to interchangeable material or trying every historical key. Unknown/disabled key fails closed. Separate current write-key eligibility from retained unwrap-key availability.

AAD version1 is exactly180bytes, assembled with stdlib integer packing/UUID bytes: `HMSDOC01`(8), version unsigned-big-endian16(2), organisation/patient/intent/generation UUIDs(16each), declared size unsigned-big-endian64(8), declared SHA256 raw bytes(32), media code JPEG=1/PNG=2(1), initial seal-key-ID ASCII length(1), that ID padded with zero bytes to64. All lengths/values must be canonical. Expected AAD is reconstructed from trusted immutable DB facts and compared to stored AAD, never adopted from object headers.

Envelope version1 is exactly78header bytes followed by `size+16` ciphertext/tag bytes: `HMSENC01`(8), version unsigned-big-endian16(2), generation(16), nonce(12), declared size unsigned-big-endian64(8), SHA256 of AAD(32). Require exact total length, header equality and successful full authenticated decryption, then recompute size/digest/media. No trailing bytes or unauthenticated plaintext release.

AES-KW alone does not bind patient/generation. Swapping another wrapped DEK fails the payload authentication using independently reconstructed expected AAD; swapping its ciphertext/nonce as well still fails scope-bound AAD. This assumes trusted DB scope relationships and independently generated DEKs, not protection from an attacker who can rewrite the whole authoritative database. **Rewrap/rotation mutation is deferred** until a separately typed, reviewed workflow and schema define its authority, transaction and historical evidence. This slice creates no wrapper-history table, rotation service or automatic mutation. Initial seal-key-ID/AAD/ciphertext and stored wrapped DEK remain immutable; a future-compatible current-wrap-key-ID field does not authorise changing them. Retain exact key-version lookup and all required old KEKs through backup holds and verified restoration; a future wrapping-key-ID must never be substituted into existing seal AAD.

## Receive, publish and reconcile

1. Authenticate real session/CSRF/IP and current scoped creator grants. Lock in the shared persistence order. Resolve receipt/reservation before first-binding state/expiry checks. New reservation consumes quotas/capacity and reserves `4096 + 4096 * ceil((declared_size + 78 + 16) / 4096)` logical bytes. Its fingerprint uses canonical declared facts; only matching server-observed bytes validate the final receipt fingerprint. Concurrent different keys cannot reserve the same intent.
2. Read exactly declared1..10485760bytes into bounded memory; compute SHA256 and verify media/declaration before sealing. No plaintext temp file. Matching bound replay only performs this verification and current authorised receipt/result audit; it allocates no generation/object/work or new-reservation quota. Mismatch fails without altering original content. Unbound competing requests cannot adopt an active sealing claim.
3. For a first seal, commit the one-use claim described above and confirm ownership/fence/current authority/cutoff. The owning live invocation may resolve a lost claim ACK by authoritative DB read before its first encrypt call. It records an in-memory call-started guard before calling once. A replacement process cannot inherit encryption permission: it cannot know whether the previous invocation encrypted. Errors after call-started never retry encryption.
4. Outside DB locks, create `<generation>.part` exclusively0600 relative to retained private directory descriptors, rejecting symlinks/nonregular files. Write the already-complete encrypted envelope, handling short writes; fsync and close its writable descriptor. Publish with same-filesystem exclusive hard link to `<generation>.seal`, never replacement rename. Fsync directory; unlink `.part`; fsync directory again. Existing final name is reconciled, never overwritten. Filesystem/link/fsync semantics are an actual-adapter gate, not presumed cloud-provider behavior.
5. Open final read-only and verify the complete expected envelope/tag/digest. Under fresh original-request authority and locked current fence, bind content+work+receipt+audit before original cutoff. No object/network I/O under locks. Only known bound commit permits202; unknown ACK returns503 until authorised authoritative reconciliation. Scanning starts only from resolved committed work.

A replacement request may bind a complete valid final without sealing again, before original cutoff, with fresh session/epoch/grants/IP and current fence. Reconciliation takes a new fence only after supervisor-confirmed former owner termination. Ordinary logout does not cancel already-bound scan work; it prevents using that browser session for further binding/disclosure. Epoch/grant/original-IP-policy revocation blocks worker promotion; callbacks never reconstruct browser contexts.

## Crash matrix

| Last possible action | Recovery rule |
|---|---|
| Reservation COMMIT/ACK uncertain | Authoritative key lookup; absence after resolved rollback permits normal reservation; unknown retains quota/503. No sealing before resolved reservation. |
| Sealing claim COMMIT/ACK uncertain | Same live invocation confirms claim before its first call; restarted invocation never encrypts it. No object means terminal after owner termination. |
| Encryption began/completed, no durable object | Terminal held identity; never regenerate/re-encrypt. New declaration only. |
| Partial `.part`, including write/fsync error | Terminal held; no truncation, resume, overwrite or conversion into final. |
| Complete fsynced `.part`, no final | Terminal held; replacement invocation does not publish `.part`. |
| Final link exists, directory fsync/part-unlink uncertain | After former owner termination, authenticate complete final, fsync file and directory, remove matching part alias and fsync directory; eligible binding only before original cutoff. Missing/invalid final is terminal. |
| Final durable, binding not begun/rolled back | Same complete-final reconciliation; expiry/revocation makes terminal, not downloadable. |
| Binding COMMIT/ACK uncertain | Resolve receipt/content/work transaction first; never infer rollback, delete, recreate or rescan from a lost reply. Bound replay may succeed after expiry; unbound final cannot bind after cutoff. |

## Fencing, deletion and acceptance

Lease expiry alone never releases writer capacity or proves filesystem I/O stopped. A fixed supervisor controls only receipt-owned writer process groups, identified by generation plus process-start/cgroup identity; no PID-only kill or arbitrary service command. Before reclaim/delete it confirms all old writer descendants gone. A stale writer may leave an orphan but cannot pass conditional DB binding. If termination cannot be proved, retain bytes/slot and refuse further intake at limits.

Orphan inventory is bounded100items/fiveminutes. Terminal objects require two authoritative unreferenced checks at least24hours apart, resolved commit outcomes, no live owner/lease and no backup/legal hold. Second check atomically replaces the fence UUID and enters irreversible `purging`; no bind is possible thereafter. Outside locks unlink owned aliases/final and fsync directory; only confirmed absence plus committed `purged` releases reserved bytes. Unknown deletion/ACK retains accounting. Never delete bound content through orphan cleanup. Historical audit, wrapper references and dependency manifests persist; purge is not proof of physical erasure. Ready retention and restore-rescan authority remain separately contracted.

Before freeze require independent review of this exact encoding/state protocol and persistence/API/UI agreement. Then executable RED/GREEN and actual PostgreSQL barriers at every matrix boundary, duplicate keys, stale writers, cutoff/revocation, unknown ACK and purge/bind races. Primitive tests must swap each wrapped key/nonce/header/AAD field/ciphertext/tag, cover1byte/10MiB/+1, missing/wrong KEK and rewrap with unchanged seal bytes. Actual filesystem power-loss/ENOSPC/short-write/fsync/link faults, process cleanup, HTTP framing/disconnect and backup+DB+object+old-key restoration remain acceptance gates.

## Coordinator alignment —10 November2026; no implementation freeze

The original cutoff is captured after authentication/real CSRF/global action checks and before reservation/body reading, once per first receive. Edge header/body inactivity limits are separate. First-binding eligibility is checked strictly before min(original_started_at+60s, declaration expiry) immediately before COMMIT; this is not a promise that COMMIT acknowledgement/HTTP delivery completes before that instant. A known committed binding is retained even when its reply arrives late. Unknown commit remains503 plus explicit reconciliation; never invent rollback.

Storage accounting uses the persistence formula `4096 + 4096 * ceil((declared_size + 78 + 16) / 4096)`; this includes envelope/tag/block rounding and a conservative metadata allowance, not proof of physical disk reservation against other applications. ENOSPC still fails closed.

Purge scheduling is not yet frozen: persistence must carry first-unreferenced-check/fence/epoch evidence and explicit backup/legal hold authority. The two-check narrative above does not authorise deletion when those dependencies are absent. Recovery execution/renewable recovery authority likewise remains deferred until a separate complete recovery contract; no restore re-enable service is delivered by this draft.
