Page: deployment-wide Network access, advertised only by current-user `platform.security.manage`, independent of branch or summary organisation. Mode, verified IP and current policy precede mode/allowlist/blocklist/reason draft fields. Each list is one exact address or CIDR per line, maximum 100 entries, each 64 characters; reason 10–500 characters. Blocks win and infrastructure restrictions still apply. Current-IP adds the verified server address with /32 or /128 to memory only. No browser storage, automatic preview or writes.

Actions/API: GET state on entry/reload; explicit preview POST with per-draft UUID; activation references only preview ID/base revision; Keep/Restore reference exact change/activation revision. Editing invalidates preview. State reload invalidates preview and preserves draft, with explicit Replace draft from current settings. Server response times anchor expiry and rollback countdown; no extension POST. Expired preview disables Apply; rollback expiry disables terminal buttons and reloads once. Separate lazy history GET with outcome/date filters, 25-row bounded pagination and server-pinned window. Project only declared history fields and validated policy snapshots, no raw JSON/detail audit links.

State/failure design: loading and write-pending disable competing actions; a ref prevents same-tick double submits. Empty lists/history are explicit. 403 permission/network denial and 503 unavailable are plain failures; MFA links Account security. Navigate away/back requires state/new preview (session binding may rotate). 409 clears preview, retains draft, requires Reload status before new preview. Any transport/5xx/unparseable-success POST outcome is unknown: disable writes, offer Reload status, never retry automatically. Reconnect does not write. Automatic rollback and audited administrator recovery are explained if access is lost.

Accessibility: native labels/selects/textareas/buttons, visible existing focus styles, field-linked errors, focusable error summary after failure, restrained status live region; countdown has no live announcement each second. No modal or custom keyboard traps. History dates are labelled and validated before GET; empty/server errors do not show stale records.

Pre-code scenario/permission review: only advertised capability controls navigation; server independently requires owner/master/operator/fresh MFA. No clinical or user-management rights added. Threat review: no client IP from headers/local state, no JWT/database access, no arbitrary endpoint selection, no auto-save/retry, no localStorage/sessionStorage draft, no raw history. Client validation aids staff only; server canonicalisation and permissions remain authoritative.

RED test design: draft-only current IP/dedup, canonical preview and deny-path activation, explicit activate/keep/revert exact references, edit invalidation, busy suppression, expired preview/pending deadline, 403/MFA/503/offline/unknown POST, conflict retained draft and reload, lazy bounded pinned history, and current-user permission navigation. ## Independent review repair design —24 October 2026 scheduled resume

Three Important findings are independently reproduced in ignored frontend/.local/network-review.test.tsx. This section is FROZEN by the coordinator after independent executable RED and source/scenario/threat review: (1) a deferred activation settles after Account security return and a newer GET, overwriting revision9 with8 and old Keep/Restore controls; (2) a400 error containing an object instead of an allowlist error-array crashes `.join`; (3) an outstanding GET settles after offline and clears the reconnect reload requirement.

Precisions: a single component context generation must invalidate every request settlement on navigation/reload/offline. Preview, activation and terminal-success/error callbacks capture their dispatch generation; a stale response cannot change rules, pending controls, messages, errors, loading gates or trigger a new GET. Draft fields remain in memory. Leaving the active context clears preview, request key, transient error and success text. Offline advances generation and clears active loading feedback while retaining the blocked state until a later explicit online Reload status successfully settles. A stale POST still releases its in-flight write lock, preventing a permanent busy state, but cannot assert current policy or revive an old control.

Error handling stays local to Network access: validate ApiError field maps as known network field names with bounded arrays of bounded strings, plus bounded string message/code, before any `.join`, `.startsWith` or rendering. Malformed projected errors become a plain unavailable GET or unknown POST outcome with explicit status reload; no raw reflected structures, retry, new rights or shared API behavior change. Server errors remain authoritative when their envelope is valid.

Portable tests will cover deferred success and rejected responses for preview/activate/confirm/revert across leave/return, newer GET preservation, no stale success/MFA/error messages, offline-during-GET response suppression and explicit reload recovery, malformed nested/oversized error maps/code, and valid field feedback preservation.
