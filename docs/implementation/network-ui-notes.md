# Network access Stage C client design

Pre-code design, 24 October 2026. Frozen authority/API source: network-access-contract.md §11 and OpenAPI 0.6.0. Existing React administrative panels, fields and buttons are retained. UI/UX Pro Max search `admin security forms` returned Minimalism & Swiss Style (applicable functional hierarchy); its marketing hero/font/palette recommendations are rejected as unsuitable to this existing staff application. The focused `form errors save conflict` search returned applicable Submit Feedback and Form Labels guidance; mobile gesture guidance is irrelevant.

Page: deployment-wide Network access, advertised only by current-user `platform.security.manage`, independent of branch or summary organisation. Mode, verified IP and current policy precede mode/allowlist/blocklist/reason draft fields. Each list is one exact address or CIDR per line, maximum 100 entries, each 64 characters; reason 10–500 characters. Blocks win and infrastructure restrictions still apply. Current-IP adds the verified server address with /32 or /128 to memory only. No browser storage, automatic preview or writes.

Actions/API: GET state on entry/reload; explicit preview POST with per-draft UUID; activation references only preview ID/base revision; Keep/Restore reference exact change/activation revision. Editing invalidates preview. State reload invalidates preview and preserves draft, with explicit Replace draft from current settings. Server response times anchor expiry and rollback countdown; no extension POST. Expired preview disables Apply; rollback expiry disables terminal buttons and reloads once. Separate lazy history GET with outcome/date filters, 25-row bounded pagination and server-pinned window. Project only declared history fields and validated policy snapshots, no raw JSON/detail audit links.

State/failure design: loading and write-pending disable competing actions; a ref prevents same-tick double submits. Empty lists/history are explicit. 403 permission/network denial and 503 unavailable are plain failures; MFA links Account security. Navigate away/back requires state/new preview (session binding may rotate). 409 clears preview, retains draft, requires Reload status before new preview. Any transport/5xx/unparseable-success POST outcome is unknown: disable writes, offer Reload status, never retry automatically. Reconnect does not write. Automatic rollback and audited administrator recovery are explained if access is lost.

Accessibility: native labels/selects/textareas/buttons, visible existing focus styles, field-linked errors, focusable error summary after failure, restrained status live region; countdown has no live announcement each second. No modal or custom keyboard traps. History dates are labelled and validated before GET; empty/server errors do not show stale records.

Pre-code scenario/permission review: only advertised capability controls navigation; server independently requires owner/master/operator/fresh MFA. No clinical or user-management rights added. Threat review: no client IP from headers/local state, no JWT/database access, no arbitrary endpoint selection, no auto-save/retry, no localStorage/sessionStorage draft, no raw history. Client validation aids staff only; server canonicalisation and permissions remain authoritative.

RED test design: draft-only current IP/dedup, canonical preview and deny-path activation, explicit activate/keep/revert exact references, edit invalidation, busy suppression, expired preview/pending deadline, 403/MFA/503/offline/unknown POST, conflict retained draft and reload, lazy bounded pinned history, and current-user permission navigation. Synthetic data only. Verification/results appended after execution; no browser walkthrough or deployment claimed here.

## Implemented client and observed verification

Implemented six-management-API client in NetworkAccess.tsx; added contract types, permission-only App navigation, existing-style panels/forms and summary metadata. App keeps the network component mounted within the authenticated workspace so Account security navigation retains unsaved draft; its active-state transition clears preview and reloads state. Older GET responses are ignored by a generation guard. Network loss invalidates preview and requires explicit status reload; no automatic POST retries. History pagination retains both the server window and the last applied outcome filter. Generic master administration receives only the frozen optional summary metadata, never network policy/owner/operator data.

## Parsed-response validation follow-up

Coordinator identified that TypeScript API casts do not validate parsed JSON: empty preview/state/history objects could crash rendering, while empty activation/terminal responses could imply success. Before repair, added 17 executable cases covering each POST `{}`, malformed state envelope/policy/revision/date/pending status, malformed preview normalisations/deadline, invalid change outcome/revision/date and malformed history. Observed **17 RED / 25 prior GREEN with 3 reproduced render errors**, then **42 focused GREEN in 15.16s**, typecheck passed. Added an enum-array regression and observed its RED/render error before requiring actual enum strings instead of coercion.

Local bounded guards now check the declared fields consumed by this screen, including safe revisions, UTC calendar timestamps, canonical ID shapes, boolean decisions, bounded policy arrays, normalisations and history snapshots/window. They do not parse IP policy or decide server authority. Malformed GET state/history shows plain unavailable status; malformed parsed POST requires Reload status with unknown outcome and no retry/success message. Synthetic fixtures now use canonical UUIDs. Raw synthetic-only RED logs reside in ignored `.local/`, not frontend source. Full follow-up suite/build evidence pending below.
