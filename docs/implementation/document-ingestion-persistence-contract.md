## Admission, rate and reservation sequence

All **five** operations share a new fixed actor60/UTC-minute allowance, separate from B3's unchanged60/minute. After genuine authentication/action and scalar/header validation, atomically charge once; all new-key attempts and same-key replays charge. Final errors do not refund a known committed allowance. Invalid transport/global authority consumes none; valid-but-disabled calls consume allowance then503 without PHI. Actor saturation429 Retry-After1..60; minute edges can admit120 nearby calls. No proposed60/organisation/hour throttle: synthetic capacity/concurrency backpressure is explicit and must not become an unmeasured hospital throughput claim.

List/detail/withdraw use only rate admission; withdrawal replays also charge. Receive and download additionally acquire actor/global transfer slots before body reading/decryption. Intake readiness affects receive only; routine scanner outage never disables accepted-file download, scoped reads or eligible withdrawal. Download requires storage/key/integrity and current clearance, independent of intake_ready. Queue ceiling20 pending received generations per organisation remains a proposed synthetic acceptance bound, counted under organisation lock, not throughput policy.

Receive fingerprint is canonical sorted compact JSON over operation/patient/intent/intent_version/declared size/type/hash from trusted persisted declaration plus validated matching headers. Reserve **before reading body**; reject changed same-key fingerprint409. Reservation origin is original post-auth context capture; first binding strictly before min(origin+60s,intent.expires_at), checked after waits and immediately before commit. Local monotonic elapsed and wall cutoff both apply; no remint/extension. Replay uses a fresh transfer deadline but cannot change original binding cutoff. Slow/unknown COMMIT cannot promise a60s response or rollback.

Committed replay acquires transfer capacity and reads/verifies<=10MiB plaintext in bounded memory; no new generation/object/encryption/scan/storage charge. Matching observed bytes resolve the current authorised existing receipt after expiry. First reservation charges `storage_charge=4096+4096*ceil((declared_size+78+16)/4096)`, covering fixed envelope/tag plus conservative allocation allowance; storage charge survives failures. Global reservation moves to retained on known binding without changing total; sealed orphans remain charged. Existing key with unresolved reservation reconciles that identity, never silently allocates another.

## Seal once; acknowledge precisely

After bounded plaintext size/type/hash verification, prepare random32-byte DEK, random12-byte content nonce and **AES-256-GCM once per generation**. Candidate wrapper: RFC3394 AES-KW under a separate32-byte document KEK, producing40-byte wrapped DEK; no wrapping nonce/counter. Persist complete crypto metadata and one-use state=sealing/seal_state=used claim in one transaction; acknowledge commit before encryption/storage I/O. Missing acknowledgement means authoritative reread by the same live owning invocation before its first call, never speculative/replacement-process encryption.

Adopt [sealing contract](document-ingestion-sealing-contract.md)'s **180-byte binary AAD v1**, replacing the preliminary JSON encoding: HMSDOC01(8), unsigned-big-endian16 version(2), organisation/patient/intent/generation UUID bytes(64), unsigned-big-endian64 declared size(8), raw declared SHA256(32), JPEG=1/PNG=2 media byte(1), initial seal-key-ID ASCII length(1), ID zero-padded to64. IDs match ASCII `[A-Za-z0-9_-]{1,64}`. Independently reconstruct from trusted scope/declaration rows and immutable seal_key_version; require stored AAD equality, never trust object-provided scope.

Object has the sealing contract's **78-byte header**: HMSENC01(8), unsigned-big-endian16 version(2), generation UUID(16), nonce(12), unsigned-big-endian64 size(8), AAD SHA256(32); then exactly size+16 ciphertext/tag bytes. Header equality, exact length, authenticated decryption and observed size/hash/media checks are mandatory. Never reuse MFA keys. Initial seal_key_version=current_wrap_key_version; both remain unchanged in this slice and exact retained-key lookup permits old unwrap keys independently of current write eligibility. **No rewrap mutation or immutable wrapper-history row is supplied.** Rewrap/rotation requires a separately typed authorised operation and reviewed persistence/history freeze before enablement; do not silently add a ninth model or promise that future history already exists.

The owning live invocation records an in-memory call-started guard **before** its one encryption invocation. Exclusive partial creation and exclusive immutable final publication, file+directory fsync, no overwrite. Record seal_state=complete only after verifying the final object outside locks. Replacement ownership/fence requires confirmed old-writer termination. It may reconcile an existing complete final before original cutoff, never encrypt or publish an old partial. Otherwise transition to held_terminal; held crypto identity is never reused and requires a new declaration. Unknown binding ACK holds object/key/charges; authorised receipt lookup determines committed outcome after cutoff without new binding/deletion.

## Lock order, fences and release

Transactions: User NO KEY UPDATE → existing IdentitySecurity → IngestionActor → singleton Control → organisation NO KEY UPDATE → existing content receipt → patient NO KEY UPDATE → intents UUID order → contents UUID order → reservation → work → append attempts/events. Skip untouched rows, never reverse. First actor-row creation serialises on User. Old B3 relative ordering remains compatible; no storage/scanner/process I/O under business locks. Use existing short transaction server ceilings, not their request context across transfer.

All producer mutations require exact lease_token AND writer_instance; worker completions require scan_cycle/lease_token/worker_instance/readiness/supervisor generation equality. Every new claim/reconciliation replaces the UUID; no token ordering/bigint counter. Expiry prevents further authorisation but **does not release counters or permit replacement while an old process might write**. Reaper invalidates readiness/lease, stops receipt-owned processes outside locks and confirms termination before writer_stopped_at/slot release. Unconfirmed death retains charges/slots. Transfer release clears matching actor tuple/decrements global count atomically once. Orphan purge needs two resolved unreferenced checks >=24h apart, no owner/backup hold, and fresh UUID transition held_terminal→purging before I/O. Confirmed unlink/fsync/absence permits purged+released_at+storage-counter decrement atomically. Unknown ACK rereads markers; no double release or purge of bound content. DB outage never justifies deletion.

## Readiness and restore cycles

Dedicated supervisor alone publishes a fresh readiness UUID after current loaded signature/engine/validator-policy checks; valid<=60s. Reload first closes intake and changes supervisor generation; old completions cannot promote. Claim snapshots readiness identities; promotion rechecks same identities/freshness plus original actor active/epoch/grants/current original-IP policy and no withdrawal. Ordinary logout does not cancel committed ingest work. No browser context persists. Signing fresh readiness is not a substitute for actual engine/isolation acceptance.

Restore starts under closed byte serving/admission, fences/stops old processes and assigns **new restore_epoch UUID**. Preserve original content verdict/accepted_attempt/receipts/times/all attempts; clear no history. Copied clearance epochs cannot match new epoch. For each eligible accepted generation create a fresh restore scan_cycle/purpose=restore/current epoch/new10min deadline/ordinals1..3. Replace work's current-cycle pointer only after prior worker termination; attempts retain old cycle identities. Successful current-clearance attempt sets clearance_epoch/clearance_attempt, never rewrites ingest acceptance. Failed/stale/missing current evidence denies download.

Ingest principal is original receiver with committed epoch/origin. Restore principal is separately authenticated, explicitly authorised scoped recovery operator under a frozen recovery contract; no original browser session or inherited master/clinical grant. Claim/promotion requires active recovery principal/current epoch/explicit restoration scope/current permitted network plus normal patient isolation. No arbitrary mark-clean/retry/tool bypass. Recovery route/permission and operator selection must be frozen before restore activation, not improvised by a job.

**Remaining feasibility gates:** crypto reviewer approval/real library tests; owned supervisor and isolation/stop proofs; actual parser/scanner policies and capacity under representative workload; concrete scoped recovery-authority contract; object/DB/key backup-restoration evidence. Coordinator's revised candidate is at least3GiB/preferably4GiB ClamAV and6GiB/2CPU aggregate, subject to owned isolation and clinical coexistence proof; no host capacity is reserved. Shared public-Nginx plaintext handling remains a production activation gate. Independent schema/race/replay review and OpenAPI/page-action freeze precede RED/code. Values here are proposals, not measured capacity or an implementation claim.
