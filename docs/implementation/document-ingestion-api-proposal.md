# Registration ingestion API and persistence proposal

**DRAFT — 8 November 2026.** Coordinator recommendation, not an approved contract, implementation plan, schema migration, test result or activation. Read with [reconciliation](document-ingestion-design.md), [6 November checkpoint](../operations/document-ingestion-planning-checkpoint-2026-11-06.json), current metadata contracts and source. Baseline: bdbe8c6/core0009/metadataFalse. Consume completed B1/B2/B3; do not repeat them.

## Recommended compatibility boundary

Choose application-mediated raw upload, immutable private objects, durable scan work and **new linked ingestion projections**. Keep the four B3 operations, exact closed response fields, pending/withdrawn CHECK, receipts, event vocabulary, rate window and fingerprints unchanged. Existing `can_upload=false`/`can_download=false` remain honest descriptions of that metadata API. New routes explicitly describe ingestion capabilities instead.

Alternative: deliberately version every document API and migrate the intent state machine to include receipt/processing/ready. That simplifies one UI DTO but requires new create/list/detail/withdraw contracts, expiry semantics, compatibility tests and replay preservation. Silently extending closed v1 objects or changing old receipts is unacceptable. Linked rows need several new tables but avoid rewriting deployed contracts. No direct object-store bearer upload, new provider, clinical category, PDF, OCR or URL import is proposed.

The existing intent UUID remains the staff-visible document identity. A declaration expires exactly 30 minutes after creation. **First durable byte binding must commit strictly before that deadline.** Once bound, scan completion/download do not expire at 30 minutes; declaration status can independently project `expired`. New ingestion withdrawal supports accepted files after that deadline. This distinction needs coordinator acceptance before freeze.

## Exact proposed HTTP surface

Let `I=/api/v1/patients/{patient_id}/document-ingestions/`. IDs/keys use existing lowercase canonical UUID grammar. Empty query except the list; unknown/repeated query keys fail400. No implicit HEAD/OPTIONS; authenticated mapped action ceiling precedes local405. Exact Allow is GET, PUT or `GET, PUT` as appropriate, POST for withdrawal. All responses no-store/nosniff/Vary Cookie; fixed JSON errors; no conditional304, ETag or Last-Modified.

|---|---|---|---|

| GET I`{document_id}/` | `getPatientDocumentIngestion` / `ingestion.detail` | No body |200 Result |

Use existing `createPatientDocumentIntent` to declare the chosen file; no new create route. Add CurrentUser field `document_ingestion={version:1,branches:{branch_uuid:{available:boolean,can_read:boolean,can_receive:boolean}}}` only for current branches with document-read conjunction. This is an explicit additive CurrentUser schema/page-action change requiring compatibility review, not another probe route. Readiness is an advisory sampled server fact, never authority. R04 discovers useful availability, creates one declaration, PUTs bytes and refreshes the **single new unified list**, including unreceived intents. It does not show a competing metadata list or interpret old false capabilities as ingestion availability.

PUT requires Idempotency-Key, `X-Document-Intent-Version` canonical decimal1..2147483647, Content-Length exactly declared size1..10485760 and Content-Type exactly image/jpeg or image/png (no parameters). No Content-Encoding, multipart, base64, client path, Content-Disposition or upload URL. Actual entity size/type/SHA256 must match declaration; server computes all three. Raw stream reader must be separate from 4096-byte JSON capture. Ordinary cookie/header/Origin real CSRF precedes body staging; opaque parser must not consume the file. Bounded pre-auth framing rejection remains permitted. Trusted ingress canonical framing and hidden WSGI bytes have the existing documented limits; no hidden-byte rollback claim.

POST uses existing strict JSON grammar/4096-byte bound, reason10..500 and version integer1..2147483647, no extras. Other GET bodies are forbidden. Download Range returns400; Accept is ignored; attachment uses verified media type, exact length, safe filename fallback plus encoded Unicode filename, no inline preview/public redirect/presigned URL. No successful binary response before durable disclosure audit. Client disconnect cannot recall bytes already released.

## Closed schemas and authority

All keys listed are required, additionalProperties false. UUID/time/string rules reuse B3; nullable fields are explicit. Encoded JSON limit262144 bytes. No locator, digest, scanner text, actor identifier, job token or demographics in staff projections.

| Result | `{server_time,document:Ingestion,capabilities:Capabilities}` |
| List | `{server_time,results:Ingestion[0..100],has_more:boolean,next_cursor:string or null,capabilities:Capabilities}` |
| Error | `{code,message}` fixed safe strings, no supplied values |

List selects intents, left-links at most one content row, uses immutable intent created_at/id ordering and cursor `v:1` with the existing exact patient/category/time/id encoding; no COUNT, offset or scan-status filter. New result selection is coherent at one server_time. Pending unbound→awaiting_file; unbound at expiry→expired. Bound queued/scanning→processing; accepted→ready; failed checks→rejected; exhausted retry/dependency/integrity→unavailable. Content withdrawal OR old intent withdrawal overrides all to withdrawn. Transient unavailable infrastructure can suppress download without permanently changing accepted verdict. Rejected content cannot be replaced: select another file through a new declaration. No automatic new-key retry.

Read/list/detail/download require current exact-branch patients.read AND documents.registration.read. Receive/withdraw additionally require patients.write AND documents.registration.write and creator identity. No master/doctor/nurse inheritance or cross-branch role union. Download permits authorised branch readers, not only creator. New-key receive requires stored pending, unexpired declaration, matching intent version and no received content; content version starts1 and only withdrawal increments it. New-key withdrawal requires a bound, not-yet-withdrawn content and matching content version; no30-minute restriction. For unbound rows, can_withdraw and the UI action use existing intent withdrawal/intent_version instead. Existing intent withdrawal remains independently valid under its old rules.

CurrentUser discovery reveals no patient data or infrastructure diagnostics. available requires both deployment gates, healthy storage/keys/validator/scanner/worker/capacity. New list/detail require scoped patient access and include current capabilities; disabled ingestion status remains safely readable independently of the old metadata creation gate. Dependency outage does not prevent authorised status/withdrawal reads; new receive/download fail closed. No capability boolean replaces server checks.

Local inherited errors retain B3 fixed messages:400 validation_error;401 ended session;403 anonymous/permission/CSRF;404 concealed missing/foreign/mismatch;405;409 idempotency_conflict/version_conflict. New409 `content_state_conflict`: `This file is no longer available for this action.` New422 `content_mismatch`: `The file does not match its declaration. Select the file again.` 413 request_too_large;415 unsupported_media_type;429 rate_limited with Retry-After1..3600; new503 `document_ingestion_unavailable`: `Documents are temporarily unavailable. Try again later.` Preserve existing pre-view network/session envelopes. No422 scanner detail; completed scan rejection is a successful status projection. Uncertain commit returns503 and requires reconciliation, never a rollback claim.

## Transactions, replay and worker ceiling

New ingestion contexts/operations require deliberate authority extension; current `_OPERATIONS` accepts only four metadata operations. Do not forge metadata contexts or broaden old admission proofs. Separate upload lifecycle deadline and resource reservations; never reuse/remint the metadata five-second context over staging. Short transactions can retain existing2s lock/3s statement/5s transaction server controls; those are not upload/scan/delivery deadlines.

Receive: current session/epoch/network/global and patient/creator checks, scoped receipt lookup; new commands additionally check version/state/expiry. Reserve bounded capacity durably; stage/hash/validate immutable object **without business locks**; final transaction reacquires fresh original authority/session/epoch/network and scope. Resolve receipt fingerprint first; only first bindings recheck version/state/expiry/capacity and insert content+work+receipt+event atomically. A matching replay can succeed after expiry/version change but never skip current creator/scope checks. Acknowledge commit, then return detached projection. Object durability precedes DB binding; unbound objects are reconciled, never exposed. No storage/scanner/network I/O inside locks. Authority loss or expiry during staging cannot create a first binding.

Supported lock order: User NO KEY UPDATE → existing IdentitySecurity → organisation NO KEY UPDATE → content receipt if existing → patient NO KEY UPDATE → intent(s) UUID order → content(s) UUID order → work → attempt/event writes. Actor serialisation protects first receipt creation; unique constraints backstop it. Resource reservations must fit this order before freeze. Queue selection may read candidate IDs unlocked; claiming then follows the same order and conditional state/lease checks. Never hold a work lock then acquire parent locks. Old metadata writers retain their order and serialize through parent intent; old withdrawal suppresses later promotion/download without adding new old-route side effects.

Receive fingerprint is SHA256 canonical sorted compact JSON `{operation:"content.receive",patient_id,document_id,intent_version,media_type,size_bytes,sha256}` using **server-observed matching bytes**. Same-key replay stages/verifies supplied entity into a new private quarantine candidate, then resolves current authorised content and removes the unbound candidate; it never overwrites or resubmits the original generation/work/version. Changed valid fingerprint409. Existing content under another key409. Withdrawal fingerprint adds normalised expected_content_version/reason. Replays bypass transition/expiry, never current scope/creator; each committed response gets a new event. Detail/list recovers lost responses or lost in-memory keys; no stale cached receipt response.

Worker: generation-bound durable work identity delegated by uploader; fresh active uploader/current epoch/exact-branch grants and original origin_ip evaluated against current environment/overlay policy at claim/promotion, plus explicitly permitted worker network path. Ordinary logout does not cancel accepted work; expired session is not reused. Epoch change, lost grants or policy denial prevents promotion. Scanner/decoder run outside locks; stale lease token/generation/signature/authority cannot promote. Withdrawal wins visibility even if scanning finishes. New JOB/MCP adapters use these services with equivalent scoped authorisation; no arbitrary URL/shell/SQL or service-role bypass. Exact delegation lifetime, resource limits, retention/purge and storage/scanner acceptance remain security rulings.

Download stages and verifies the immutable accepted generation outside locks, then fresh final authority/scope/withdrawal/integrity checks and committed audit authorise release of that exact staged object. Postselection revocation/disconnect cannot recall released bytes; no continuous-transaction authority claim. Accepted lifetime ends on withdrawal, integrity/policy failure or separately frozen retention, never merely declaration expiry.
