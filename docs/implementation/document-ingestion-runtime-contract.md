## 2. Owned scanner generation

Dedicated `hms-ingest-avctl` supervisor exclusively owns one daemon lifecycle through a root-owned broker permitting only start/stop/status of fixed `hms-ingest-clamd.service`. Broker accepts no unit name, PID, command, environment, path or property from requests. Supervisor has no general service administration; application/worker cannot invoke broker or access clamd socket. Broker confirms the owned unit cgroup empty, not merely a recycled PID or closed socket. Definition/binary changes require reviewed OS deployment.

Supervisor exposes only typed scan-of-issued-claim/readiness operations on `/run/hms-ingest/control.sock`, peer-UID restricted to the worker; no public/MCP endpoint. Claim binds content/generation/digest/size/cycle/attempt/fence. Clamd runs as `hms-ingest-av`, no DB/keys/object access/network; private `/run/hms-ingest-av/clamd.sock` is accessible only to supervisor and daemon. Fixed socket client vocabulary is PING, VERSION and INSTREAM; forbid path scans, FILDES, IDSESSION, RELOAD, SHUTDOWN and raw caller commands. [Protocol](https://docs.clamav.net/manual/Usage/ClamdProtocol.html): NUL-framed `zINSTREAM`, network-order32-bit chunk lengths, <=65536-byte chunks, zero terminator; bounded4096-byte reply, only exact `stream: OK` plus terminator is clean. FOUND/errors/limits/EOF/extra or malformed output never imply clean.

Generation UUID binds daemon start identity, engine/config/validator hashes and immutable official database snapshot hashes/version/timestamps. Readiness requires startup within180s, PING/VERSION within2s, successful policy fixtures, signature timestamp<=48h old and <=5min future tolerance. Recheck age/generation at claim and promotion; freshness observations expire after60s. VERSION alone does not establish database hashes. Persist generation and hashes with verdict.

One active scan;20s absolute deadline includes transfer/reply,5s no-progress bound. On timeout/disconnect/protocol uncertainty: immediately fence generation locally/unready, reject later replies, stop exact owned daemon, TERM then after2s KILL; require confirmed empty cgroup within5s. Persist the durable fence; unavailable DB never delays stopping and prevents fresh readiness until reconciled. Failed cessation remains unavailable/alerts; never launch a second daemon. Supervisor restart begins unready and reconciles/kills any owned survivor before fresh generation. Reservations/leases remain held until writer/process cessation is proved.

Updater `hms-ingest-update` has only official signature egress and staging-directory write, no content/keys/DB. At scheduled update: close intake/claims, drain active20s job or fence/stop it, confirm daemon gone, run bounded180s FreshClam update/test, create root-controlled read-only snapshot, then start new daemon/generation. No in-place reload or simultaneous old/new engines. Disable NotifyClamd, automatic executing hooks and automatic reload; `ConcurrentDatabaseReload no`, `SelfCheck 0`, immutable daemon DB mount and blocked reload signals/commands enforce the interlock. Source/config review and actual version tests must prove it. [Versioned config](https://raw.githubusercontent.com/Cisco-Talos/clamav/clamav-1.4.6/etc/clamd.conf.sample) is normative for option availability, not sample-main.

Proposed config: StreamMaxLength10485760, MaxFileSize12582912, MaxScanSize33554432, MaxRecursion4, MaxFiles100, MaxThreads1, MaxQueue2, MaxScanTime15000ms, CommandReadTimeout2s, ReadTimeout5s, AlertExceedsMax yes; keep format detection/signatures enabled. Versioned sample describes MaxScanTime as ZIP-limited: it cannot establish the image deadline. [Versioned daemon source](https://raw.githubusercontent.com/Cisco-Talos/clamav/clamav-1.4.6/clamd/server-th.c) explicitly disables self-check at0. Actual tests must prove every skip/limit non-clean and supervisor wall enforcement.

## 3. Isolation and full envelope

Select root-provisioned fixed service namespaces/cgroups for isolated synthetic acceptance, rather than a shared default container or current shared www-data execution. [Official Docker guidance](https://docs.clamav.net/manual/Installing/Docker.html) recommends3GiB minimum/4GiB preferred and warns reload/updater validation consumes additional memory. Therefore replace the prior unproven2GiB scanner proposal. This guidance is not a measured requirement for our exact build.

| Group | Hard proposal; includes descendants, buffers and tmp |
|---|---|
| Parent ingestion slice | 6GiB memory,2CPU aggregate,128 tasks, swap maximum0 |
| Isolated synthetic TLS/ingress | 128MiB/0.5CPU; all plaintext buffering in group |
| Bytes `hms-ingest-bytes` | 512MiB/1CPU; two upload+two download slots; each body<=10MiB; budget<=80MiB simultaneous plaintext including one full copy per slot |
| Worker `hms-ingest-work` | 128MiB/0.5CPU; one generation,64KiB bounded IPC chunks |
| Decoder child `hms-ingest-image` | 256MiB/1CPU,5s wall/3s CPU,16FD; one child;12million pixels,8192 each dimension,one frame |
| Scanner | 4GiB/1CPU; private128MiB tmp included;64FD |
| Updater | 1GiB/1CPU; mutually exclusive with scanner;1GiB signature staging disk quota |
| Supervisor/broker | 64MiB/0.25CPU;32FD; fixed bounded messages |

UIDs are distinct, no login, no supplementary shared-app groups. Root-owned read-only binaries/config under `/opt/hms-ingest/runtime/<manifest>/`; encrypted objects under `/var/lib/hms-ingest/objects/` accessible only to byte/worker service; KEKs through separately permissioned existing key facility, never scanner/updater. Root-owned namespace/mount setup must separate decoder from parent key/DB descriptors; child receives only bounded plaintext/metadata and closes inherited FDs. Worker DB access uses narrow typed business services, no arbitrary job payload SQL/shell. Network deny by default; only scoped TLS PostgreSQL for bytes/worker and permitted updater egress. Drop capabilities/no-new-privileges; restrict ptrace, process-memory access and cross-service signals.

All plaintext-bearing ancestors, including the public shared TLS-terminating Nginx before proxying, require demonstrated spill protection. Isolated synthetic ingress and descendants require swap0, core limit0/no crash collection, private `tmpfs,noswap,nodev,nosuid,noexec` scratch (scanner128MiB,bytes64MiB,decoder16MiB) charged to group limits. Shared proxy buffering, body logging, framework spooling, dumps and disk fallback are forbidden. [Kernel cgroup](https://docs.kernel.org/admin-guide/cgroup-v2.html) and [tmpfs](https://docs.kernel.org/filesystems/tmpfs.html) document separate swap controls: ordinary tmpfs can swap. Synthetic isolated Nginx proof does not attest the existing public front. Production bytes remain disabled until reviewed full-chain spill evidence, potentially encrypted swap or dedicated ingress, exists; no new host/IP/paid provider, global swap/proxy rewrite or other-app change is selected/authorised here. Unsupported noswap/enforcement or host crash-dump exposure blocks activation. No physical memory-erasure guarantee.

8November4CPU/15992MiB RAM/10961MiB available/4095MiB swap with21containers is dated, unreserved. Measure steady/load/update/OOM/temp exhaustion and competing synthetic clinical latency before placement; unavailable on failure, never silently increase caps/reduce signatures. Decoder verify/reopen/full-load, decompression warnings-as-errors and strict container policy belong to reconciled validator contract, preserving original bytes. Downloads fully verify<=10MiB into bounded memory before final current authorisation+committed audit over that exact file;30s transfer/10s no-progress, no Range/conditional cache bypass. No per64KiB DB reauthorisation promise: later revocation cannot recall selected, buffered or transmitted bytes.

## 4. Restore purpose, authority and epoch

Introduce immutable scan cycle `(content_id,purpose,epoch_uuid)` with purpose `ingest|restore`; attempts1..3 unique per cycle, new UUID equality claim fence. Ordinary ingest keeps receipt+10minute promotion cutoff and active uploader/epoch/current branch-conjoined grants/current recorded-origin IP policy. Logout alone does not cancel committed work. Restore never edits old receipt, accepted pointer/history or attempts, and never borrows the old receipt deadline.

Recovery principal is named OS-authenticated owner/operator invoking root-owned fixed recovery entry point, running non-login `hms-ingest-recovery`; no master-role inference. Reviewed typed operations: begin(snapshot manifest hash,organisation/branch allowlist), verify, enqueue-cycle, inspect, close. Inputs are bounded IDs/enums, no arbitrary filesystem/SQL/shell/URL/MCP interface. Application backup portal/API is not delivered; future app exposure requires versioned authorised contracts. Recovery authorisation is durable, scoped, time-limited24h with current operator-active/recovery-grant/epoch/network checks at claim/promotion; explicit audited renewal required after expiry. It replaces uploader liveness only for restoring already accepted files, granting no signing or disclosure authority.

Protocol: close byte serving/intake; durably advance restoration epoch and revoke/fence old workers; confirm owned processes stopped; restore isolated DB/object namespaces only from dependency manifest binding snapshot/schema, object/envelope digests, KEK versions/current readable key and audit history. Verify all dependencies; missing/corrupt material stays held. Create restore cycles for formerly accepted nonwithdrawn files, preserving historical evidence; restored unaccepted work stays held for separate current authorised ingest action. Each cycle has10minute deadline from its own claim-start, retries at+60/+300s, <=3 attempts; exhausted cycles remain held, never reset history. New recovery authorisation/epoch is required for an audited later cycle.

Worker rescans exact restored generation against actual current scanner generation; promotion validates recovery scope, current patient/branch policy, epoch/fence and withdrawal/hold precedence, and writes new evidence+audit atomically. Old-uploader offboarding alone does not destroy eligible restoration. Explicit close verifies all manifest objects accounted for as accepted/held, keys usable, workers fenced and audit complete. Keep public capability disabled; separately reviewed release may enable only accepted current-epoch files through ordinary current reader APIs. No public mark-clean, operator verdict import, automatic flag flip or blanket patient-data overwrite.

## Coordinator recovery disposition —10 November2026

Recovery execution is explicitly deferred from this ingestion freeze candidate. The proposed24hour authorisation/renewal workflow above has no complete durable scope/expiry/revocation representation yet; it is not callable or implemented. An ingest-only worker cannot rescan a day-old restored file by resetting historical attempts. Restored downloads remain disabled until the separately reviewed recovery workflow passes.

Required recovery invariant: create and retain the target epoch/maintenance guard outside the snapshot before restoring. After restoring DB/object namespaces, install that external target epoch into the restored Control with every serving/admission/readiness gate false, clear stale leases/clearances as specified by the future recovery contract, and verify identity/manifest before any worker or serving process starts. Restoring old enabled Control fields cannot reinstate serving. No claim is made that the app detects arbitrary root database replacement outside this guarded procedure.

Future restore cycles start their10minute interval at the first known committed claim, persisted once; retries never extend it. Ordinary ingest cycles remain receipt-based. All lease fencing is UUID equality, not an increasing counter. Old acceptance/scan history stays immutable. Public shared TLS-front buffering/swap/core custody and full resource enforcement remain unresolved activation gates; an isolated listener does not prove them.
