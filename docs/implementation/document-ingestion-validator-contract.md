# Registration image validation contract

**DRAFT — 13 November 2026; five saved review rulings reconciled at draft level only.** Proposed narrow first-slice policy for reconciliation and independent scenario, security and test-design review. Not frozen, implemented, installed, tested or activated. Parent [ingestion](document-ingestion-design.md), [transport](document-ingestion-transport-contract.md), [sealing](document-ingestion-sealing-contract.md), [persistence](document-ingestion-persistence-contract.md), [runtime](document-ingestion-runtime-contract.md) and [retain-all](document-ingestion-retention-contract.md) contracts remain DRAFT. This file changes no dependency, application code, schema, worker, scanner, API, UI, flag or live environment. No executable test was run for this document.

## 1. Scope and decision

Only one registration JPEG or PNG, original delivered entity length **1..10485760 bytes inclusive**, exact declared SHA256 and declared media type. No PDF, HEIF/HEIC, WebP, GIF, TIFF, SVG, DICOM, clinical interpretation, OCR, thumbnail, preview, conversion or new rendering path. File extension and browser MIME are advisory; actual container and decoded format must match the immutable declaration. Preserve original bytes, including accepted metadata; no stripping, EXIF rotation, colour transformation or re-encoding. Attachment-only download uses the original authenticated object, never pixels returned by the validator.

Select a deliberately restricted image profile rather than accepting every valid JPEG/PNG: JPEG baseline/progressive 8-bit grayscale/RGB with bounded familiar metadata; static 8-bit PNG with a small explicit ancillary allowlist. This makes parser behavior and resource limits reviewable. It rejects some valid phone images and screenshots; compatibility acceptance below must quantify this before a staff release. A decoder success and a signature scan are limited evidence, not proof that a file is harmless, contains no hidden payload, has one possible interpretation in every viewer, or is clinically legible. Metadata, compressed pixels and embedded EXIF thumbnails may contain arbitrary information; there is no universal polyglot detector here.

## 3. Immutable input and cheap bounded checks

Receive framing/declaration/digest checks remain transport work, before immutable encrypted binding. A later claim must authenticate/decrypt the exact sealed generation and independently recompute size/SHA256 before validation. Never let a content row's mutable status, filename, MIME guess or scanner reply select other bytes. Missing/corrupt object, tag failure, expected-fact mismatch or short internal stream is unavailable/integrity hold, not a clean file or a user-image rejection. Preserve retained evidence and alert through bounded internal diagnostics.

The proposed pure byte layer takes exact immutable bytes plus trusted expected media/size/digest; no coercion, filesystem, imports of Pillow, decompression, XML/TIFF parsing, subprocess or DB. Linear bounded cursor walking and incremental CRC/hash only; no recursive grammar or attacker-sized allocation. Counters fail before exceeding caps. Return closed structural facts or a fixed rejection enum; never content excerpts. The same checks run inside the decoder sandbox before library open; doing cheap checks earlier is an optimisation, not permission to bypass the isolated full check.

Common limits: width/height each1..8192 inclusive; width*height<=12000000 inclusive; exactly one primary raster; complete container begins at offset0 and its terminal marker ends at byte length, with no BOM, prefix, suffix, whitespace padding or concatenated second file. All offsets/lengths checked against remaining bytes before access. Header dimensions are untrusted but sufficient to reject excessive allocation before decode; they must agree with both Pillow opens and post-load facts. The pixel limit is intentionally below a4032x3024 phone photograph (12192768 pixels); that common mode is rejected, not rounded down or secretly resized.

### 3.1 JPEG container profile

Require SOI FFD8 at0; exactly one SOF0 or SOF2 with precision8 and one or three components under the explicit bounded field rules below; >=1 SOS and one EOI FFD9 at exact EOF. SOF1, lossless/SOF3, arithmetic, differential/hierarchical, DNL dimensions, four-component CMYK/YCCK and every other SOF are rejected. Grayscale must decode L, three-component JPEG RGB; no draft/thumbnail path. At most4096 counted marker occurrences including restarts, <=64 SOS scans, <=64 APP/COM segments and <=262144 aggregate APP/COM payload bytes. These complexity caps deliberately reject some unusually segmented legal JPEGs.

Walk length-bearing markers with big-endian length>=2 and complete bounded payload. Outside entropy accept only SOI-at-start, the single allowed SOF, DQT, DHT, DRI, SOS, allowed metadata below and final EOI; no SOS before SOF. The13November primary-source reread of [T.81 AnnexB](https://www.w3.org/Graphics/JPEG/itu-t81.pdf) informs these field checks; selected restrictions remain HMS policy. Segment lengths below include the two length bytes. Keep only bounded component IDs/table-ID facts and counters, never coefficients, decoded blocks or an attacker-sized tree. DQT/DHT may precede SOF; retain their bounded ID facts and apply any SOF-specific field restriction once SOF is known, rather than rejecting that legal ordering.

| Marker | Exact structural/profile responsibility of the pure walker |
|---|---|
| SOF0/SOF2 | Length exactly8+3*Nf; Nf exactly1 or3; precision8; dimensions under common limits. Component IDs unique; each H/V sampling nibble1..4 and sum(H*V)<=10; quantisation-table selector0..3. Record component IDs/sampling/selectors as untrusted structural facts. |
| DQT | One or more complete table records consuming the whole payload. Selected first profile permits only precision nibble0, table ID0..3 and exactly64 nonzero8-bit quantisers per record;16-bit quantisation is deliberately unsupported. Later redefinition of a table ID is permitted as framed bytes, not a proof of decode validity. |
| DHT | One or more records: class0 or1, ID0..1 for SOF0 or0..3 for SOF2, exactly16 count bytes, sum1..256, then exactly that many symbol bytes before the next record/end. No canonical Huffman tree construction, code-space/oversubscription test or coefficient/entropy interpretation in this layer. Native load must validate table semantics and actual use. |
| DRI | Length exactly4; record the unsigned16-bit interval, with0 disabling restart markers. |
| SOS | Length exactly6+2*Ns; Ns1..Nf, unique component IDs all in SOF, DC/AC selector nibbles0..1 for SOF0 or0..3 for SOF2. Baseline requires Ss0/Se63/Ah0/Al0. Progressive requires0<=Ss<=Se<=63 and Ah/Al0..13; Ss0 requires Se0; Ss>0 requires Ns1. No cross-scan coefficient coverage, refinement order, table-use correctness or successive-approximation semantics is asserted here. |
| Entropy boundaries | Walk each byte once: FF00 is stuffing; bounded FF fill runs are consumed without unbounded lookahead; unstuffed nonrestart markers end a scan. RST0..RST7 require nonzero DRI and modulo8 order startingRST0 per scan. The walker does not count decoded MCUs or prove restart spacing/alignment. EOI is recognised only as a marker, never by searching opaque APP payloads. |

Reject framing/field/cap failures deterministically. Missing/invalid table use, invalid Huffman code spaces/symbol semantics, entropy corruption, coefficient ranges, restart MCU spacing and progressive scan sequencing/coverage are **native decoder responsibilities at isolated full load**. A structural pass may therefore include a semantically invalid JPEG and must never be named decode-valid or clean. Actual pinned-native behavior must be tested; a warning-free successful load is the chosen decode evidence, not an independent proof of every T.81 conformance rule. Do not build a second JPEG decoder to turn this layer into that claim. Test expected structural facts separately from actual pinned-native decode outcomes; later leaf freeze must resolve any remaining normative field ambiguity against T.81 without silently broadening this table.

Metadata is permitted only before first SOS:

| Segment | Exact first-slice rule |
|---|---|
| APP0 JFIF | At most one, identifier `JFIF` plus NUL, standard14-byte payload with zero thumbnail width/height and valid fixed fields. Embedded JFIF/JFXX thumbnails rejected. JFIF is optional. |
| APP1 EXIF | At most one, prefix `Exif` plus two NULs, payload<=65533 bytes including prefix. Bounded opaque retention after prefix; no application TIFF traversal or metadata extraction. EXIF may itself contain a thumbnail/GPS/device information. No claim that it is sanitised, structurally valid TIFF or free of embedded files. |
| APP2 ICC | Only `ICC_PROFILE` plus NUL and sequence/count bytes, each nonzero, count<=16, exactly one complete unique sequence1..count in increasing contiguous order; combined profile data<=131072 bytes. Preserve opaque ICC bytes; no ImageCms invocation/profile interpretation or conversion. |
| APP14 Adobe | At most one exact12-byte Adobe payload, version/flags structurally present and transform0 or1 consistent with a three-component JPEG; absent for grayscale. No four-component Adobe handling. |
| COM | At most one payload<=4096 bytes, opaque and never displayed/logged/extracted. |
| Everything else | Reject: XMP including extended XMP, MPF/MPO APP2, JFXX, gain-map/HDR markers, APP13 Photoshop, arbitrary APP segments and unknown payload prefixes. |

Accepting EXIF/ICC trades attack surface and retained sensitive metadata for ordinary phone compatibility. [Tagged JPEG plugin source](https://raw.githubusercontent.com/python-pillow/Pillow/13.0.0/src/PIL/JpegImagePlugin.py) shows that open may derive DPI from EXIF and that the JPEG factory can inspect MP metadata. Therefore application avoidance of getexif does not mean the library never parses EXIF; the sandbox is mandatory. Reject MPF before library entry; do not trust n_frames alone to detect concatenated/HDR content. No thumbnail is decoded intentionally, but the primary-image promise does not erase EXIF thumbnails.

### 3.2 PNG container profile

Exact eight-byte PNG signature; <=4096 chunks total. Every chunk has ASCII-letter type with reserved bit valid, bounded complete length/data/CRC and correct CRC32, including ancillary chunks. Exactly one first IHDR length13, compression/filter method0, interlace0 or1. Only bitdepth8 and colour types0,2,3,4,6; no16-bit or1/2/4-bit PNG in this first profile. Exactly one last IEND length0 and exact EOF. One nonempty aggregate contiguous IDAT run; no IDAT restart after ancillary data.

Allowed ancillary chunks only: single sRGB length1/intent0..3; single gAMA length4/nonzero; single cHRM length32; single pHYs length9/unit0..1; single sBIT length matching colour type with each significant-bits value1..8; single tRNS only for types0,2,3 with lengths2,6,or1..palette_entries respectively and valid sample values. All occur before IDAT; sRGB/gAMA/cHRM/sBIT before PLTE if present. PLTE is required for type3, forbidden for0/4, optional for2/6; one PLTE length3..768 divisible by3, preceding tRNS/IDAT. Type3 palette index validity requires a bounded iteration of the loaded P-mode primary raster inside the child: reject any index>=PLTE entry count. Do not assume Pillow rejects undefined palette indices. No pixels leave the child or full duplicate raster is created; this iteration consumes the same wall/CPU budget. PNG ancillary payload total<=65536 bytes. Allowed chunk fixed fields use specification byte order/ranges; no unknown critical or ancillary chunk is accepted.

Reject acTL/fcTL/fdAT even if only one frame/default image; reject iCCP, eXIf, tEXt/zTXt/iTXt, tIME and all other chunks. Thus no compressed metadata reaches Pillow in this profile. PNG metadata is preserved when allowed, never stripped. Refusing otherwise valid ICC/text/EXIF PNGs is a compatibility cost; rejecting unknown ancillary chunks is stricter than PNG decoder conformance requires. This explicitly declines future PNG extensions until reviewed.

Full PNG validation must additionally prove exactly one complete zlib image stream consumes all concatenated IDAT data, with no unused compressed suffix/second stream; exact decompressed scanline byte count and filter selectors0..4 for the selected colour type/interlace; no short or extra decompressed bytes. For Adam7 compute each pass's nonempty row count/width from IHDR, sum one filter byte plus ceiling(bits_per_pixel*pass_width/8) per row; no allocation based on attacker lengths. This work belongs inside the5second sandbox, not the pure byte layer: incremental zlib output <=65536 bytes per call, exact expected output ceiling, bounded row accounting, no full second raster. Require zlib EOF/empty unused_data/no remaining input. This strict IDAT-consumption policy deliberately rejects some PNGs tolerated by other decoders. [Tagged PNG source](https://raw.githubusercontent.com/python-pillow/Pillow/13.0.0/src/PIL/PngImagePlugin.py) is a review input; Pillow verify alone does not establish this additional policy.

## 4. Decoder execution and exact evidence

One fresh unprivileged child per attempt in the proposed runtime decoder isolation; receive only bounded plaintext and fixed claim facts through fixed IPC, no path/filename/import selector. Close all inherited DB/key/object/scanner descriptors. No network, shell, external converter, writable persistent filesystem or supplementary shared-app group. Import/startup/resource failures are unavailable, never fallback to decoding in a request/DB worker.

Order under one externally enforced **5second absolute wall budget including startup, IPC, pure checks, PNG inflate, both opens, verify, load, palette check and reply**; cumulative CPU<=3seconds, memory cgroup256MiB including descendants/IPC/private16MiB no-swap tmpfs, swap0/core0,16FD, one child, task maximum1 after the fixed launcher enters/executes the child, <=64KiB IPC chunks and <=4096-byte closed reply. Never reset budget on reopen or progress. Parent observes the complete-attempt and stage deadlines below using monotonic time and fences/kills the exact owned child/cgroup on timeout; TERM then after2seconds KILL, require confirmed empty cgroup within5seconds of timeout and within the remaining complete-attempt cessation budget. The5second child budget is nested inside the complete attempt, not added after its lease; timeout immediately makes the result unusable, and cleanup time grants no validation extension. Confirm no descendant before releasing slot/lease. No new child while old cessation is uncertain. Decoder has no reason to write plaintext scratch; intentional disk writes are forbidden even inside its private tmpfs. These are proposals, not measured feasibility.

1. Check claim input length/digest and strict byte profile. Pin warnings policy in the child: all warnings during open/verify/load are rejection; never warning suppression/truncated-image recovery. Set Image.MAX_IMAGE_PIXELS=12000000 and ImageFile.LOAD_TRUNCATED_IMAGES=False before open; enforce exact dimension/product policy independently because warning/error thresholds differ. No process-global mutation in the application.
2. For PNG perform bounded exact inflate/row checks above. First fresh seekable read-only in-memory input: Image.open with formats exactly `["JPEG"]` or `["PNG"]` selected by trusted declaration, not None/all plugins. Check exact format, dimensions and permitted mode; n_frames default1 only where the plugin has no frame property, is_animated must be false. Call verify immediately, then close. No seek-to-other-frame, getexif, image.text, ImageCms, exif_transpose, draft, thumbnail, save, convert, copy or pixels export.
3. Reopen a fresh seekable stream over the identical immutable bytes with the same single-format restriction. Recheck facts, call load to decode full primary raster without scaling; recheck format/size/mode/one-frame. Modes PNG0=L,2=RGB,3=P,4=LA,6=RGBA; JPEG as above. No transformed pixels or library metadata leave child. Treat unexpected warnings, changed facts and documented parse/decode failures as reject; missing codec, MemoryError/OOM, native crash, unknown exception, deadline/IPC failure as unavailable. Unknown exceptions never become a successful verdict or a claim that user bytes are malformed.
4. Close decoded image/streams; reply with exact typed evidence and exit. Parent accepts only after normal process exit, complete closed reply and confirmed owned-process cessation. The child is untrusted isolation, not independent cryptographic authority; authentication/hash of the original is established by the trusted byte path, and result comparison is mandatory. Rehash/count original supplied stream at handoff and scanner handoff; never trust an unbound child-reported digest.

### 4.1 One complete attempt budget, including cessation

Proposed absolute schedule, **unmeasured and not frozen**: capture paired monotonic `t0` and wall `attempt_started_at` immediately before the first claim transaction, before pool acquisition/lock wait. Retain this origin through acknowledgment, IPC, reconnect and final selection. Proposed durable lease expiry is `attempt_started_at+45s`, capped by the unchanged cycle deadline; claim-commit time never resets it. A known issued ordinal and UUID fence cannot be reminted on uncertain claim acknowledgment. No object/decoder/scanner work starts until the claim commit is known and still current. An unissued timed-out claim attempt performs no byte work; uncertain issuance is reconciled by its original identity.

| Stage | Own maximum and absolute latest completion from t0 |
|---|---|
| Claim |5s including connection/pool acquisition, transaction lock waits/statements and known claim acknowledgment; finish by t0+5s. |
| Object and handoff |5s including object acquisition, authenticated decryption, size/hash checks and bounded handoff preparation; finish by t0+10s. Complete plaintext IPC delivery is charged to the decoder stage below, so this boundary never assumes a child can consume input before startup. |
| Decoder |5s including startup, complete plaintext IPC delivery, checks/verify/reopen/load/IPC reply/normal exit and confirmed child cessation; finish by t0+15s. Handoff preparation is already charged above; all remaining transfer/copy is charged here, never free. |
| Scanner |20s including supervisor admission, same-original recount/hash/handoff, full INSTREAM transfer and complete reply/job completion; finish by t0+35s. Existing5s no-progress bound also applies. Normal known completed scan does not require stopping its reusable daemon. Uncertain jobs fence/stop that owned generation. |
| Final business selection |5s including connection/pool/lock waits, authority/claim/lease/cycle/guard checks, result/evidence/audit writes and attempted commit acknowledgment; final authorising sample strictly before t0+40s. |
| Cessation reserve |No new validation/promotion after its applicable cutoff; up to t0+45s to fence/stop outstanding owned work and confirm cessation. This is cleanup only, never an extra decoder/scanner/DB authorisation interval. |

Each stage cutoff is the minimum of stage-entry+its own cap, its absolute boundary above, the original cycle deadline and the capped lease expiry, enforced with paired monotonic elapsed and current wall cutoffs. The useful selection deadline is further capped at five seconds before min(t0+45s,lease expiry,cycle deadline), preserving cessation reserve even near cycle expiry. Do not begin a stage unless the remaining interval can preserve its cleanup requirement. Stages may complete early but cannot borrow a later absolute boundary or extend the cycle; guard observations and all descriptor/stream closure are charged within the relevant stage/reserve. Scanner/decoder timeout immediately invalidates promotion evidence. Fence and initiate cessation immediately on failure; never wait until the reserve to stop a timed-out process. If the cycle/lease is too short or cessation cannot be proved within the candidate schedule, hold unavailable and retain slots/charges until actual cessation is proved; never launch replacement work while the old process is uncertain. These caps describe attempted bounded execution, not a demonstrated ability to force an OS/kernel to stop by a deadline.

No physical COMMIT-acknowledgment or response SLA is claimed. Sample authority/time again after waits and immediately before final write/commit initiation; at or after the selection cutoff do not initiate an authorising write. An already initiated COMMIT can complete/acknowledge late or be unknown. Do not infer rollback, repeat promotion or renew the lease: reconcile the original attempt/evidence under a fresh read; a known committed result stays durable without manufacturing new authority after expiry. The runtime acceptance must measure final transaction, lost ACK and process-cessation cases; if the schedule cannot be met it needs explicit reviewed revision before freeze, never a silent lease extension.

No image, scanner, object, process or guard-file I/O occurs under business row/advisory locks or an open DB transaction. Claim short transaction → detached immutable claim → authenticate/decrypt/check/decode/scan outside transaction → fresh short promotion transaction. Lock waits never remint a claim, deadline or context. Final promotion resamples current authority, installation/epoch/externally observed guard fence, content/attempt/cycle/claim equality and withdrawal/security policy; stale clean results cannot promote. The separate guard-authority DRAFT defines outside-lock pre/post observations and locked DB authority; its full schema/OS proof and parent agreement remain gates, not a claim of atomic filesystem/DB selection.

## 5. Closed outcomes and scanner conjunction

Proposed internal result union; no exception strings, metadata, filenames, profiles or pixels:

| Variant | Required facts and meaning |
|---|---|
| image_validated | claim_id, content_id, immutable generation, epoch_uuid, cycle_id, attempt1..3, equality fence, observed_size/SHA256, expected media, width, height, frame_count1, allowed mode, validator_policy_hash, exact runtime_artifact_hash, completion time. Only structural/profile/full-primary-decode evidence. |
| reject | Same immutable claim identity and policy/artifact hashes; fixed reason `unsupported_profile`, `malformed_container`, `dimensions_exceeded`, `metadata_exceeded`, `decode_failed`, or `decoder_warning`. Final invalid-image rejection for this immutable generation; no automatic repair/retry under same declaration. |
| unavailable | Same issued claim identity and known hashes; fixed reason `runtime_not_ready`, `input_integrity`, `resource_limit`, `timeout`, `child_failed`, or `protocol_failed`. Holds content; bounded existing attempt/retry policy applies, never fail-open or reset history. |

Reject is used only for a deterministic observed policy/decode failure; inability to finish checking is unavailable. Enum priority for multiple violations is fixed check order (input integrity first, then size/media/container/profile/dimensions/metadata, PNG inflate, open/verify/load). Staff projection remains existing proposed rejected/unavailable with fixed plain wording; these internal enums are not extra HTTP error details. Integrity failures are internal hold/alert, never evidence of malware. No scanner is required to prove a deterministic container rejection.

Image_validated is insufficient for ready. Independently scan **the same original complete authenticated bytes**, including allowed EXIF/ICC/COM, through the runtime's fixed [INSTREAM protocol](https://docs.clamav.net/manual/Usage/ClamdProtocol.html). Trusted handoff counts/hashes all bytes; each complete scanner observation binds the same claim/content/generation/digest/size/epoch/cycle/attempt/fence, engine/config/signature generation and validator policy. Missing, stale, mismatched, skipped/limited, malformed or ambiguous results never promote. Opaque EXIF/ICC retention is not sanitisation, and a valid container/full primary decode does not erase embedded metadata payloads.

Scanner reply precedence is closed and order-sensitive: first validate exact framing, bounded single reply, issued identity/generation and timely complete stream; then recognise the pinned internal limit family **before generic FOUND rejection**. For proposed ClamAV1.4.6 the exact recognised names are `Heuristics.Limits.Exceeded.MaxFileSize`, `.MaxScanSize`, `.MaxFiles`, `.MaxRecursion`, and `.MaxScanTime` (each abbreviated suffix expands against that same full prefix). A FOUND carrying one of these means unavailable/resource_limit (MaxScanTime maps unavailable/timeout), never final malware rejection or clean. Any other name under the reserved `Heuristics.Limits.Exceeded` prefix is unavailable/protocol_failed pending scoped version review; no permissive wildcard recognises new suffixes as trusted runtime facts. Other well-formed FOUND is final rejection; ordinary ERROR/limit/disconnect/timeout remains unavailable. Names/raw scanner output never reach staff APIs, logs or HTTP errors; persist only the closed classification and bounded policy/engine identities. A syntactically exact `stream: OK` is clean only after every framing/identity/complete-stream/deadline requirement and current scanner-generation check succeeds.

Primary-source recheck13November2026 at08:08UTC: [tagged configuration](https://raw.githubusercontent.com/Cisco-Talos/clamav/clamav-1.4.6/etc/clamd.conf.sample) documents limit heuristic naming; [tagged library implementation](https://raw.githubusercontent.com/Cisco-Talos/clamav/clamav-1.4.6/libclamav/others.c) emits the five exact names above; [tagged scan implementation](https://raw.githubusercontent.com/Cisco-Talos/clamav/clamav-1.4.6/libclamav/scanners.c) shows file-size limiting can return a virus verdict; [tagged daemon reply handling](https://raw.githubusercontent.com/Cisco-Talos/clamav/clamav-1.4.6/clamd/scanner.c) routes virus verdicts to FOUND. This source review supports classification, not proof of actual configured daemon behavior. Actual pinned-engine limit/skip/timeout fixtures remain mandatory; artifact/config changes require regenerating and reviewing the closed family.

Acceptance is strictly **isolated full decode AND same-original complete scanner clean AND current immutable claim/fence/lease/cycle/authority/promotion gates with atomic evidence/audit**. A late clean from an earlier claim/generation cannot combine with a newer decoder result. No public mark-clean or trusted caller boolean exists.

Retain original encrypted bytes and immutable verdict/history under retain-all, including rejected/unavailable files; no purge/refund/quota release. Retry must reread the exact immutable object and redo checks under one issued claim; decoder checks cannot repair or authorise a new generation. Accepted evidence remains subject to parent current-epoch/security holds and serving gates; restore-purpose scans/reopening are deferred. Accepted does not mean antivirus catches every malicious payload or a future download viewer is safe.
