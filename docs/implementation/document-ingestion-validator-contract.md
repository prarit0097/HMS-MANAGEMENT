# Registration image validation contract

**DRAFT — 12 November 2026.** Proposed narrow first-slice policy for reconciliation and independent scenario, security and test-design review. Not frozen, implemented, installed, tested or activated. Parent [ingestion](document-ingestion-design.md), [transport](document-ingestion-transport-contract.md), [sealing](document-ingestion-sealing-contract.md), [persistence](document-ingestion-persistence-contract.md), [runtime](document-ingestion-runtime-contract.md) and [retain-all](document-ingestion-retention-contract.md) contracts remain DRAFT. This file changes no dependency, application code, schema, worker, scanner, API, UI, flag or live environment. No executable test was run for this document.

## 1. Scope and decision

Only one registration JPEG or PNG, original delivered entity length **1..10485760 bytes inclusive**, exact declared SHA256 and declared media type. No PDF, HEIF/HEIC, WebP, GIF, TIFF, SVG, DICOM, clinical interpretation, OCR, thumbnail, preview, conversion or new rendering path. File extension and browser MIME are advisory; actual container and decoded format must match the immutable declaration. Preserve original bytes, including accepted metadata; no stripping, EXIF rotation, colour transformation or re-encoding. Attachment-only download uses the original authenticated object, never pixels returned by the validator.

Select a deliberately restricted image profile rather than accepting every valid JPEG/PNG: JPEG baseline/progressive 8-bit grayscale/RGB with bounded familiar metadata; static 8-bit PNG with a small explicit ancillary allowlist. This makes parser behavior and resource limits reviewable. It rejects some valid phone images and screenshots; compatibility acceptance below must quantify this before a staff release. A decoder success and a signature scan are limited evidence, not proof that a file is harmless, contains no hidden payload, has one possible interpretation in every viewer, or is clinically legible. Metadata, compressed pixels and embedded EXIF thumbnails may contain arbitrary information; there is no universal polyglot detector here.

## 3. Immutable input and cheap bounded checks

Receive framing/declaration/digest checks remain transport work, before immutable encrypted binding. A later claim must authenticate/decrypt the exact sealed generation and independently recompute size/SHA256 before validation. Never let a content row's mutable status, filename, MIME guess or scanner reply select other bytes. Missing/corrupt object, tag failure, expected-fact mismatch or short internal stream is unavailable/integrity hold, not a clean file or a user-image rejection. Preserve retained evidence and alert through bounded internal diagnostics.

The proposed pure byte layer takes exact immutable bytes plus trusted expected media/size/digest; no coercion, filesystem, imports of Pillow, decompression, XML/TIFF parsing, subprocess or DB. Linear bounded cursor walking and incremental CRC/hash only; no recursive grammar or attacker-sized allocation. Counters fail before exceeding caps. Return closed structural facts or a fixed rejection enum; never content excerpts. The same checks run inside the decoder sandbox before library open; doing cheap checks earlier is an optimisation, not permission to bypass the isolated full check.

Common limits: width/height each1..8192 inclusive; width*height<=12000000 inclusive; exactly one primary raster; complete container begins at offset0 and its terminal marker ends at byte length, with no BOM, prefix, suffix, whitespace padding or concatenated second file. All offsets/lengths checked against remaining bytes before access. Header dimensions are untrusted but sufficient to reject excessive allocation before decode; they must agree with both Pillow opens and post-load facts. The pixel limit is intentionally below a4032x3024 phone photograph (12192768 pixels); that common mode is rejected, not rounded down or secretly resized.

### 3.1 JPEG container profile

Require SOI FFD8 at0; exactly one SOF0 or SOF2 with precision8, one or three components and valid component/sampling/table fields; >=1 SOS and one EOI FFD9 at exact EOF. SOF1, lossless/SOF3, arithmetic, differential/hierarchical, DNL dimensions, four-component CMYK/YCCK and every other SOF are rejected. Grayscale must decode L, three-component JPEG RGB; no draft/thumbnail path. At most4096 counted marker occurrences including restarts, <=64 SOS scans, <=64 APP/COM segments and <=262144 aggregate APP/COM payload bytes. These complexity caps deliberately reject some unusually segmented legal JPEGs.

Walk length-bearing markers with big-endian length>=2, complete bounded payload, legal ordering and field lengths. Outside entropy, accept only SOI-at-start, the single allowed SOF, DQT, DHT, DRI, SOS, allowed metadata below and final EOI. DQT/DHT/DRI/SOS obey T.81 field lengths/ranges/references for the selected SOF; reject reserved/unsupported markers and duplicate SOF/SOI. Within entropy, FF00 is a stuffed data byte, FFD0..FFD7 restart markers are permitted only with declared restart interval and expected modulo8 order, fill FF bytes are bounded input, and an unstuffed nonrestart marker ends that scan. Do not locate EOI with an unconstrained byte search: marker-like bytes within APP/EXIF/ICC are payload. Missing tables, invalid scan membership/order or undecodable entropy remain rejection at actual load; pure framing does not claim a complete independent JPEG entropy decoder.

Metadata is permitted only before first SOS:

| Segment | Exact first-slice rule |
|---|---|
| APP0 JFIF | At most one, identifier `JFIF` plus NUL, standard14-byte payload with zero thumbnail width/height and valid fixed fields. Embedded JFIF/JFXX thumbnails rejected. JFIF is optional. |
| APP1 EXIF | At most one, prefix `Exif` plus two NULs, payload<=65533 bytes including prefix. Bounded opaque retention after prefix; no application TIFF traversal or metadata extraction. EXIF may itself contain a thumbnail/GPS/device information. No claim that it is sanitised, structurally valid TIFF or free of embedded files. |
| APP2 ICC | Only `ICC_PROFILE` plus NUL and sequence/count bytes, each nonzero, count<=16, exactly one complete unique sequence1..count in increasing contiguous order; combined profile data<=131072 bytes. Preserve opaque ICC bytes; no ImageCms invocation/profile interpretation or conversion. |
| APP14 Adobe | At most one exact12-byte Adobe payload, version/flags structurally present and transform0 or1 consistent with a three-component JPEG; absent for grayscale. No four-component Adobe handling. |
| COM | At most one payload<=4096 bytes, opaque and never displayed/logged/extracted. |
| Everything else | Reject: XMP including extended XMP, MPF/MPO APP2, JFXX, gain-map/HDR markers, APP13 Photoshop, arbitrary APP segments and unknown payload prefixes. |

Accepting EXIF/ICC trades attack surface and retained sensitive metadata for ordinary phone compatibility. [Tagged JPEG plugin source](https://raw.githubusercontent.com/python-pillow/Pillow/13.0.0/src/PIL/JpegImagePlugin.py) shows that open may derive DPI from EXIF and that the JPEG factory can inspect MP metadata. Therefore application avoidance of getexif does not mean the library never parses EXIF; the sandbox is mandatory. Reject MPF before library entry; do not trust n_frames alone to detect concatenated/HDR content. No thumbnail is decoded intentionally, but the primary-image promise does not erase EXIF thumbnails.

### 3.2 PNG container profile

Exact eight-byte PNG signature; <=4096 chunks total. Every chunk has ASCII-letter type with reserved bit valid, bounded complete length/data/CRC and correct CRC32, including ancillary chunks. Exactly one first IHDR length13, compression/filter method0, interlace0 or1. Only bitdepth8 and colour types0,2,3,4,6; no16-bit or1/2/4-bit PNG in this first profile. Exactly one last IEND length0 and exact EOF. One nonempty aggregate contiguous IDAT run; no IDAT restart after ancillary data.

Allowed ancillary chunks only: single sRGB length1/intent0..3; single gAMA length4/nonzero; single cHRM length32; single pHYs length9/unit0..1; single sBIT length matching colour type with each significant-bits value1..8; single tRNS only for types0,2,3 with lengths2,6,or1..palette_entries respectively and valid sample values. All occur before IDAT; sRGB/gAMA/cHRM/sBIT before PLTE if present. PLTE is required for type3, forbidden for0/4, optional for2/6; one PLTE length3..768 divisible by3, preceding tRNS/IDAT. Type3 palette index validity requires a bounded iteration of the loaded P-mode primary raster inside the child: reject any index>=PLTE entry count. Do not assume Pillow rejects undefined palette indices. No pixels leave the child or full duplicate raster is created; this iteration consumes the same wall/CPU budget. PNG ancillary payload total<=65536 bytes. Allowed chunk fixed fields use specification byte order/ranges; no unknown critical or ancillary chunk is accepted.

Reject acTL/fcTL/fdAT even if only one frame/default image; reject iCCP, eXIf, tEXt/zTXt/iTXt, tIME and all other chunks. Thus no compressed metadata reaches Pillow in this profile. PNG metadata is preserved when allowed, never stripped. Refusing otherwise valid ICC/text/EXIF PNGs is a compatibility cost; rejecting unknown ancillary chunks is stricter than PNG decoder conformance requires. This explicitly declines future PNG extensions until reviewed.

Full PNG validation must additionally prove exactly one complete zlib image stream consumes all concatenated IDAT data, with no unused compressed suffix/second stream; exact decompressed scanline byte count and filter selectors0..4 for the selected colour type/interlace; no short or extra decompressed bytes. For Adam7 compute each pass's nonempty row count/width from IHDR, sum one filter byte plus ceiling(bits_per_pixel*pass_width/8) per row; no allocation based on attacker lengths. This work belongs inside the5second sandbox, not the pure byte layer: incremental zlib output <=65536 bytes per call, exact expected output ceiling, bounded row accounting, no full second raster. Require zlib EOF/empty unused_data/no remaining input. This strict IDAT-consumption policy deliberately rejects some PNGs tolerated by other decoders. [Tagged PNG source](https://raw.githubusercontent.com/python-pillow/Pillow/13.0.0/src/PIL/PngImagePlugin.py) is a review input; Pillow verify alone does not establish this additional policy.

## 4. Decoder execution and exact evidence

One fresh unprivileged child per attempt in the proposed runtime decoder isolation; receive only bounded plaintext and fixed claim facts through fixed IPC, no path/filename/import selector. Close all inherited DB/key/object/scanner descriptors. No network, shell, external converter, writable persistent filesystem or supplementary shared-app group. Import/startup/resource failures are unavailable, never fallback to decoding in a request/DB worker.

Order under one externally enforced **5second absolute wall budget including startup, IPC, pure checks, PNG inflate, both opens, verify, load, palette check and reply**; cumulative CPU<=3seconds, memory cgroup256MiB including descendants/IPC/private16MiB no-swap tmpfs, swap0/core0,16FD, one child, task maximum1 after the fixed launcher enters/executes the child, <=64KiB IPC chunks and <=4096-byte closed reply. Never reset budget on reopen or progress. Parent observes deadline using monotonic time and fences/kills the exact owned child/cgroup on timeout; TERM then after2seconds KILL, require confirmed empty cgroup within5seconds of timeout. This adds a proposed explicit decoder cessation bound for runtime reconciliation; timeout immediately makes the result unusable, and cleanup time grants no validation extension. Confirm no descendant before releasing slot/lease. No new child while old cessation is uncertain. Decoder has no reason to write plaintext scratch; intentional disk writes are forbidden even inside its private tmpfs. These are proposals, not measured feasibility.

1. Check claim input length/digest and strict byte profile. Pin warnings policy in the child: all warnings during open/verify/load are rejection; never warning suppression/truncated-image recovery. Set Image.MAX_IMAGE_PIXELS=12000000 and ImageFile.LOAD_TRUNCATED_IMAGES=False before open; enforce exact dimension/product policy independently because warning/error thresholds differ. No process-global mutation in the application.
2. For PNG perform bounded exact inflate/row checks above. First fresh seekable read-only in-memory input: Image.open with formats exactly `["JPEG"]` or `["PNG"]` selected by trusted declaration, not None/all plugins. Check exact format, dimensions and permitted mode; n_frames default1 only where the plugin has no frame property, is_animated must be false. Call verify immediately, then close. No seek-to-other-frame, getexif, image.text, ImageCms, exif_transpose, draft, thumbnail, save, convert, copy or pixels export.
3. Reopen a fresh seekable stream over the identical immutable bytes with the same single-format restriction. Recheck facts, call load to decode full primary raster without scaling; recheck format/size/mode/one-frame. Modes PNG0=L,2=RGB,3=P,4=LA,6=RGBA; JPEG as above. No transformed pixels or library metadata leave child. Treat unexpected warnings, changed facts and documented parse/decode failures as reject; missing codec, MemoryError/OOM, native crash, unknown exception, deadline/IPC failure as unavailable. Unknown exceptions never become a successful verdict or a claim that user bytes are malformed.
4. Close decoded image/streams; reply with exact typed evidence and exit. Parent accepts only after normal process exit, complete closed reply and confirmed owned-process cessation. The child is untrusted isolation, not independent cryptographic authority; authentication/hash of the original is established by the trusted byte path, and result comparison is mandatory. Rehash/count original supplied stream at handoff and scanner handoff; never trust an unbound child-reported digest.

No image or scanner I/O occurs under business row/advisory locks or an open DB transaction. Claim short transaction → detached immutable claim → authenticate/decrypt/check/decode/scan outside transaction → fresh short promotion transaction. Lock waits never remint a claim, deadline or context. Final promotion resamples current authority, installation/epoch/external-guard fence, content/attempt/cycle/claim equality and withdrawal/security policy; stale clean results cannot promote. Exact guard read-versus-lock placement remains the parent contract gate, not resolved by this validator.

## 5. Closed outcomes and scanner conjunction

Proposed internal result union; no exception strings, metadata, filenames, profiles or pixels:

| Variant | Required facts and meaning |
|---|---|
| image_validated | claim_id, content_id, immutable generation, epoch_uuid, cycle_id, attempt1..3, equality fence, observed_size/SHA256, expected media, width, height, frame_count1, allowed mode, validator_policy_hash, exact runtime_artifact_hash, completion time. Only structural/profile/full-primary-decode evidence. |
| reject | Same immutable claim identity and policy/artifact hashes; fixed reason `unsupported_profile`, `malformed_container`, `dimensions_exceeded`, `metadata_exceeded`, `decode_failed`, or `decoder_warning`. Final invalid-image rejection for this immutable generation; no automatic repair/retry under same declaration. |
| unavailable | Same issued claim identity and known hashes; fixed reason `runtime_not_ready`, `input_integrity`, `resource_limit`, `timeout`, `child_failed`, or `protocol_failed`. Holds content; bounded existing attempt/retry policy applies, never fail-open or reset history. |

Reject is used only for a deterministic observed policy/decode failure; inability to finish checking is unavailable. Enum priority for multiple violations is fixed check order (input integrity first, then size/media/container/profile/dimensions/metadata, PNG inflate, open/verify/load). Staff projection remains existing proposed rejected/unavailable with fixed plain wording; these internal enums are not extra HTTP error details. Integrity failures are internal hold/alert, never evidence of malware. No scanner is required to prove a deterministic container rejection.

Image_validated is insufficient for ready. Independently scan **the same original complete authenticated bytes**, including allowed EXIF/ICC/COM, through the runtime's fixed [INSTREAM protocol](https://docs.clamav.net/manual/Usage/ClamdProtocol.html). Trusted handoff counts/hashes all bytes; each complete clean scanner observation binds that same claim/content/generation/digest/size/epoch/cycle/attempt/fence, engine/config/signature generation and validator policy. Missing, stale, mismatched, skipped/limited, FOUND, malformed or ambiguous results never promote. FOUND is final rejection; scanner error/limit/timeout is unavailable, not proof of malware. Only validator pass AND scanner clean AND current final business gates with atomic evidence/audit may accept. A late clean from an earlier claim/generation cannot combine with a newer decoder result. No public mark-clean or trusted caller boolean exists.

Retain original encrypted bytes and immutable verdict/history under retain-all, including rejected/unavailable files; no purge/refund/quota release. Retry must reread the exact immutable object and redo checks under one issued claim; decoder checks cannot repair or authorise a new generation. Accepted evidence remains subject to parent current-epoch/security holds and serving gates; restore-purpose scans/reopening are deferred. Accepted does not mean antivirus catches every malicious payload or a future download viewer is safe.

## 7. Remaining whole-contract gates

Coordinator must reconcile this restricted profile with API/CurrentUser/page-action discovery and plain rejection guidance: JPEG/PNG and10MiB alone do not describe acceptance; dimensions,12million-pixel threshold, metadata/colour/interlace restrictions and no-conversion behavior must be discoverable before send. Choose exact closed capability fields/versioning and public rejection wording in transport/OpenAPI/R04 review, not ad hoc UI text or new internal-code exposure here. Explicitly accept or revise the common12.19MP phone rejection and PNG ICC/XMP/HDR compatibility costs before freeze.

Persistence must freeze complete typed validator/scanner observation representation, hash identities, precedence/finality/retries, claim duration and original10minute promotion cutoff; child5s plus scanner20s and process-cessation time must fit existing cycle/lease budget without extending it. Runtime must prove worker128MiB/copies, child256MiB/native codec startup, scanner4GiB and total6GiB including plaintext/cgroups; those figures remain unmeasured. Scanner embedded-payload detection and limit/error semantics need actual acceptance. Public TLS ancestor spill/swap/core custody, exact external guard lock placement and restore hold policy remain independent blockers.

Smallest eligible next leaf after independent review is the pure immutable-byte framing/profile/facts checker, with a separately frozen explicit surface and literal RED. It must be named structural-only, avoid zlib/Pillow/filesystem/services, preserve originals and deliberately demonstrate that structure-valid malicious opaque metadata is not declared clean. It exposes no ingestion capability. PNG bounded inflate, isolated verify/reopen/load, scanner supervision and business promotion require later reviewed leaves and actual OS/engine evidence. Whole-parent freeze or activation is not inferred from that future leaf or this draft.
