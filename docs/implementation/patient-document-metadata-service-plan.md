## Interfaces and trusted-context boundary

Proposed document_authority public interface: `capture_document_context(request, operation: str) -> DocumentContext`. Accept only server Django HttpRequest (or the raw request of an already authenticated DRF adapter, unwrapped by B3), existing authenticated server session and operation in intent.list/detail/create/withdraw. Require an already resolved authenticated actor; do not evaluate a lazy request.user, which can indirectly call mutating auth.get_user. Validate the existing persisted DB Session row read-only with the exact configured Django ModelBackend, current/fallback constant-time auth hashes, active actor, expiry and captured epoch, not arbitrary caller actor_id or a trusted=True argument; no session creation/cycle/write. B3 calls capture only after ordinary authentication/CSRF/transport validation; B2 tests construct genuine synthetic authenticated sessions through existing Django facilities. A caller-supplied plain object/user or forged context must not mint authority. Internal Python with access to session secrets is trusted server code, not a sandbox this class can secure.

DocumentContext is a frozen dataclass with immutable captured scalars: actor_id, session_digest, captured_epoch (int>=0 or legacy None), operation, remote_addr, forwarded_for, verified_ip, environment_digest; plus private mint identity and private request reference excluded from repr/comparison. The live request reference is only for rechecking session binding/actor/epoch, never for replacing captured epoch/network fields. It makes the request binding live; do not claim the entire referenced object graph is immutable. No session key/cookie/IP/proof in logs, errors or access events. No context constructor/factory accepting arbitrary IDs or trusted booleans as public service authority. Mint token is process-private; direct constructors fail service checks. Optional future MCP/job adapters must supply an independently reviewed authenticated scoped context at the same ceiling, not reuse this HTTP session mint with fabricated requests.

At every required authority check: context type/mint/operation must match service, current request session digest/actor/epoch binding must match capture, fresh User active, exact captured epoch must match existing IdentitySecurity or0 when absent. Retain legacy missing-session-epoch compatibility ONLY if actual epoch0; bool/negative/noninteger values reject. Never refresh captured epoch from a later row. Preserve current enrolled-user/session authentication ceiling; reception gets no new privileged recent-MFA rule. No IdentitySecurity row is created for missing-profile reads. Live request/session logout or identity epoch change denies a reused context. Clarify server-side concurrent session-row deletion behavior in review; epoch revocation is the guaranteed cross-request revocation mechanism, and an in-memory request reference alone is not proof of immediate other-request logout detection.

Services in document_access:

- `list_document_intents(context, patient_id: str, query_pairs: list|tuple) -> DocumentServiceResult`
- `get_document_intent(context, patient_id: str, document_id: str) -> DocumentServiceResult`
- `create_document_intent(context, patient_id: str, key: str, body: bytes) -> DocumentServiceResult`
- `withdraw_document_intent(context, patient_id: str, document_id: str, key: str, body: bytes) -> DocumentServiceResult`

DocumentServiceResult is frozen `{status: int, body: bytes}`; body is final UTF8 JSON encoded within the audited transaction,<=262144bytes, with only contract scalar/list/dict projections. Success status list/detail/withdraw200 and create201, replay unchanged. Return it only after successful outermost business commit. No Response/HttpResponse/serializer/model/queryset/generator/callback escapes. Later adapter sends these exact bytes and adds frozen HTTP headers; it does not query/recompute capabilities.

`DocumentServiceError(code,status,message,retry_after=None)` carries only fixed contract-safe values;429 retry_after actual int1..3600; no exception/PHI/payload. B1 DocumentContractError is mapped without echo. Existing SecurityError not_authenticated remains safe401 internally; branch/noaction permission403, concealed scope404, exact409states, unavailable503 per contract. Network deny retains generic network403, evaluator failure503. Unexpected errors are never turned into metadata success. Ambient misuse returns unavailable before either phase.

Inputs use B1 canonical_uuid/parse_list_query/parse_create/parse_withdraw/command_fingerprint. Validate global action authority before detailed errors; exact scope is rechecked in business phase before replay disclosure. Invalid transport/CSRF belongs B3 and never reaches this API. Pure scalar validation/valid-command key checks precede allowance consumption; body bytes are already bounded supplied values, not stream reads. No arbitrary SQL/shell/URL tool, scanner/provider call or storage interface exists.

## Exact two-phase algorithm and time semantics

Public entry rejects connection.in_atomic_block OR autocommit=False before reads/admission/domain work; atomic(durable=True) alone is insufficient because TestCase/manual-autocommit exceptions exist. transaction=True/TransactionTestCase tests demonstrate outermost commits. Production services require PostgreSQL>=17; SQLite can test only model/pure pieces, never successful lock/timeout paths via a permissive fallback.

Capture monotonic start and aware wall-clock start. One cooperative5second work budget covers both phases; check before/after blocking stages, final encoding and atomic exit boundaries. It cannot interrupt synchronous driver COMMIT or guarantee HTTP acknowledgement. Each outermost durable phase immediately sets LOCAL lock_timeout2s, statement_timeout3s, transaction_timeout5s before row locks. These are server defenses, not one total5second request bound; two phases may each consume server time. No in-request retry loop/driver monkeypatch/foreign-thread connection transfer. No connection-global setting change.

**Phase A (committed admission before PHI):** fresh actor User NO KEY UPDATE -> existing IdentitySecurity -> actor limiter row. Recheck session/identity/current global-action conjunction from active Membership/ROLE_PERMISSIONS, without patient lookup. The required branch-grant sets must have nonempty intersection, not unrelated grants combined across branches. Verify effective network using captured trusted socket/header descriptor/current environment before admission. Validate the feature flag as an exact bool; invalid configuration503 precedes admission. A valid disabled call commits its increment and then raises503 OUTSIDE phase A, without Patient lookup. Saturation429 takes precedence; later disable/dependency failures never refund a committed admission. Missing actor limiter row is created under stable User lock; DB unique is backstop. Floor server UTC time to minute. Same-minute count<60 increments; next minute resets to1; equality at window end resets; earlier time before saved window start fails503. count60 yields429 Retry-After ceil(window_end-now) clamped1..60, no growth. Force constraints before phase-A commit, with no later writes. Only successful commit permits phase B; unknown/failed commit503/no phase B. No refunds or patient-bound events.

**Phase B:** reacquire fresh actor User NO KEY UPDATE -> existing IdentitySecurity -> resolve tentative visible patient branch/org -> single Organisation NO KEY UPDATE -> current actor exact-branch Membership read -> existing command Receipt NO KEY UPDATE if any -> Patient NO KEY UPDATE -> addressed intent or selected list intents NO KEY UPDATE, UUID order. All explicit joined row-lock queries use of=('self',). Skip explicit Membership row locks: org gate serializes supported staff changes including absent memberships; final read/validation is still mandatory. Do not acquire target creator User/StaffAccessRevision, Branch, Bed/Encounter, network owner/operator or second org lock. Scope changed after wait=>fail closed; never follow it into another org. Patient PATCH/reception can contend on Patient without an inverse org chain.

Recheck active/captured epoch/exact branch conjunctive permissions and scope after locks. Read requires patients.read AND documents.registration.read; create/withdraw require those plus patients.write/documents.registration.write at that same branch. Grant union is navigation only. Resolve missing/foreign/inaccessible patient or mismatched doc identically404; absence of the global same-branch action conjunction yields403 before validation/admission/patient lookup; after that global entitlement, inaccessible patient/document scope yields concealed404. Creator-only withdraw403 precedes receipt/state checks. Phase B captures snapshots only; no read-side lifecycle/profile/epoch maintenance or metadata writes on list/detail beyond required access accounting. No page total COUNT.

Matching receipt under actor+operation+key must have exact fingerprint and a result whose patient/document linkage matches the current command; corrupt linkage503, altered command409 without original metadata. Matching replay reauthorises/currently projects same result (pending/expired/withdrawn), logs a new disclosure event, does not refresh times/version or create a duplicate. New-key terminal withdrawal409 intent_state_conflict; pending stale/max expected version409 version_conflict. Withdrawal creator, deadline and version checked again at final selection; first success increments once and preserves reason privately. Create stores declared metadata with created_at captured under gates and expires_at exactly+30minutes. No bytes accepted.

For list gather<=101 candidateIDs using patient/category and immutable keyset(created_at,id) descending, select<=limit, then lock only returned<=100 in UUID order and materialise all fields under gates. Sentinel never appears in event digest/body/count. Org gate serializes supported inserts/withdrawals, preserving page selection; cursor is an independent position per request, not a cross-request snapshot. Build next cursor only when has_more.

Perform transition/new intent/complete receipt; insert one required DocumentAccessEvent, then SET CONSTRAINTS ALL IMMEDIATE. Events: list evenempty count0..100/documentnull; detail/create_result/withdraw_result count1/exactdocument; digest of compact UTF8 sorted canonical returned ID array, correlation UUID server generated. No filename/reason/request/proof/PHI or generic audit-history union. Replays produce new result events; denied/error paths do not fabricate inaccessible-patient events. No on_commit/best-effort/sampled disclosure audit.

Finish remaining authority/scope/network DB reads before selected_at, keeping identity/org/patient/intent locks. Final checks after selected_at must be pure over freshly materialised snapshots. All pending/expired/canwithdraw and server_time share one selected_at; selected_at>=expires_at means expired; no state/version write. Clock before wall start503. If any later wait/read is introduced, redo final materialisation/authority/time checks; no writes follow SET CONSTRAINTS. A withdrawal crossing expiry during event/FK wait rolls back transition/receipt/event. Encode detached final body before COMMIT and reject>256KiB with503/no projection. Successful commit releases result; after-selection network/expiry changes cannot retract an already selected audited result.

**Final network-time correction proposed:** use existing environment_snapshot and normalise_client_ip on captured remote/header values, compare environment digest and verified IP against capture (environment drift fails503/re-capture, deny generic403). Load one coherent NetworkSnapshot after all potentially blocking inserts/checks. At final selected_at choose candidate only when pending graph has selected_at<rollback_at; otherwise confirmed fallback. Validate selected_at is not before activation; never reuse effective_policy calculated before a blocking snapshot read across deadline. Add a small pure private selector in document_authority using public snapshot fields, without changing network modules or acquiring network-owner locks. Evaluate environment AND selected overlay at the same final selected_at. Review/test pending/expired_unreconciled/no-pending and equality explicitly before freeze.

Catch DB exceptions only after atomic exits. Ordinary rollback leaves no business transition/receipt/event; a successfully committed phase-A increment remains. COMMIT connection loss is unknown, never labelled rolled back: when driver returns,503/no result, discard suspect connection and permit later explicit same-key retry under current authority. Test both definite rollback and committed-but-lost-ack outcomes. Do not compensate-delete/reset quota/history. If synchronous call hangs the service cannot promise prompt503; worker/network blackhole recovery remains separate B3/release integration. No automatic request retry.

## Quotas and PostgreSQL query acceptance

Then select up to1000 org intentIDs/created_at where derived patient.branch.organisation==locked org and created_at>quota_now-3600seconds, ordered created_at/id.1000means429 until earliest created_at+3600seconds. Exact cutoff excluded; withdrawn/expired creations still count historical window. Choose Retry-After ceil of limiting waits clamped1..3600; if both limit, use maximum wait. Replay/withdraw bypass new-create quotas but consume actor allowance. Rollback frees tentative creation naturally; unknown commit reconciles receipt, never presumed free. No retention deletion/history cap or bed-capacity implication.

Keep derived scope/no duplicated org column. Existing patient-time and status-expiry indexes are correctness-compatible but LIMIT bounds returned rows, not scanning/join/sort cost. Candidate conditional(patient,expires_at,id) WHERE status=pending only if observed plan justifies an approved amendment; no speculative index/ledger/table. Record rows/plans/timing and timeout503.
