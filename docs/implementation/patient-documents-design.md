## Two realistic approaches

| Approach | Benefit | Cost and boundary |
|---|---|---|
| A. Application-mediated bounded upload and download, private storage adapter, durable DB scan work | All byte access passes current session/network/category authority; easy synthetic independent API tests; no bearer file link | App bandwidth and bounded worker capacity; requires careful DB/storage reconciliation |
| B. Private object-store direct upload plus asynchronous scan and application-mediated download | Reduces application ingress load; scalable immutable object versions | Adds provider IAM, upload bearer expiry/replay, object-generation and completion protocol; object ingress needs a separate permitted network path |

Recommend A for this bounded source slice, with a typed storage interface allowing B later. Do not return presigned download links: their bearer lifetime cannot express current per-request HMS permissions. Production storage provider/region/KMS/volume, scanner host, queue technology, backup destination and paid resources remain explicitly deferred. A private local adapter may be implemented/tested without making it a production choice.

## Authority and categories

Owner-established: authenticated least privilege, organisation/branch/category checks, master has no automatic clinical authority, backend IP policy, API parity for jobs/MCP, immutable signed history, privileged backup/restore. The following are engineering proposals, not owner approvals:

* Categories: `registration` (registration source documents) and future `clinical_reference` (external referral/report/prescription source). Insurance/claims/consents require later independently frozen categories.
* Distinct branch capabilities `documents.registration.read`, `.write`; clinical_reference grants are future contract candidates only. Read requires **both** current `patients.read` and the category read grant at the patient's branch. Create/upload requires those plus category write. First-unit create/withdraw additionally require `patients.write`. Proposed reception receives registration grants; doctor, nurse, master-only, pharmacist/accounts/therapist and unassigned roles receive no default document grants. Future clinical access requires a separate freeze. Multi-role membership is evaluated in the selected branch, never global role union.
* First exact source sub-slice: **registration only**. Clinical reference remains planned, unavailable in accepted category enum and capability advertisements until separately frozen. No role automatically inherits clinical signing. Future care relationship restrictions need actual care-team data; current free-text doctor_name cannot establish assignment.
* Every lookup checks document -> patient -> branch -> organisation consistency. Caller-supplied branch/org/encounter/storage/scanner fields are never accepted. Explicit inaccessible branch selection follows existing 403; missing/foreign patient/document and category-invisible document IDs return concealed 404. A caller with no document action receives 403 without an object-existence oracle. Names/counts/states of invisible categories are excluded.

## Proposed v1 API (four paths, six operations)

Base `P=/api/v1/patients/{patient_id}/documents/`; UUID paths canonical; no extra query keys, duplicate query values, unknown fields, duplicate JSON keys, nonfinite JSON numbers or nonobject JSON. Mutations retain normal session/CSRF/network enforcement and current session epoch. JSON max4096 original bytes, bounded before parser/CSRF stream consumption; content upload uses its separate bounded raw reader. Do not reuse the network-specific body replay implementation blindly.

| Method/path; operation ID | Closed inputs and result |
|---|---|
| GET P; `listPatientDocuments` | Optional `category=registration`, `limit` integer1..100 default25, `offset` integer0..10000. Fixed newest-created/id order. 200 `{count,results,capabilities}`; no free search/sort/branch/org filter. Count/results use identical current scope. |
| POST P; `createPatientDocumentUpload` | Required UUID `Idempotency-Key`; exact JSON `{category,filename,media_type,size_bytes,sha256}`; no encounter field. Filename1..120 Unicode characters, reject controls/path separators/dot-paths; media enum image/jpeg,image/png,application/pdf; size integer1..10485760; SHA256 lowercase64hex. 201 detail, same-key exact replay201 same ID/current state (including withdrawn/expired); changed fingerprint409. Creating metadata reserves no storage and promises no upload availability. |
| GET P{document_id}/; `getPatientDocument` | Empty query; 200 detail and current action capabilities; document-state read only, with required disclosure-audit append. |
| PUT P{document_id}/content/; `uploadPatientDocumentContent` (future) | Empty query; application/octet-stream, no multipart, encoding or JSON; `If-Match: "{original_intent_version}"` required. Stream <=10MiB+one overflow sentinel regardless of Content-Length; computed size/digest must exactly match intent. Immutable accepted-upload receipt binds document, original intent version, generation, observed digest/length and sealed receipt ID. Exact currently authorised byte replay matches this original receipt, not the document's later mutable version, and returns202 current detail without duplicate work. Same receipt replay after ready/rejected/scan_failed/withdrawn/expired returns current terminal state, never revives/rescans; receipt missing or bytes/original version mismatch409. Initial expired/withdrawn intent without a receipt rejects409. No separate client completion/scan-verdict operation. |
| GET P{document_id}/content/; `downloadPatientDocument` (future) | Empty query; ready only. Authorised audited attachment200 with trusted media type, safe server-built Content-Disposition, length, nosniff/no-store. Reject Range with416; ignore conditional headers and never304. No public URL, redirect, inline rendering, ETag or client cache. |
| POST P{document_id}/withdraw/; `withdrawPatientDocumentUpload` | Required UUID Idempotency-Key; exact JSON `{expected_version,reason}`, integer version>=1, trimmed reason10..500. Only uploader with current category write may withdraw awaiting/quarantined/rejected/scan_failed intents. 200 detail; altered-key409, stale409. Ready documents409 `correction_workflow_required`; no physical deletion. |

First source slice accepts only `registration` category. Metadata media types are declarations, not validated-byte acceptance. Missing scanner/storage does not prevent authorised audited metadata operations; it always prevents upload/ready/download success. The future byte-acceptance media enum is proposed pending the validator gate below; do not claim PDF protection from filename/magic checks. If that gate cannot be resolved, remove PDF from the frozen byte contract/UI before ingestion implementation rather than accept unchecked PDF.

Detail exact projection: `{id,patient_id,branch_id,category,filename,media_type,size_bytes,status,version,created_at,expires_at,created_by,can_download,can_withdraw}`. `created_by` is a bounded display label, not arbitrary user details. No storage key/path, digest, scanner internals, signatures, reason text or foreign clinical fields in normal projections. Server metadata may retain these privately. List `results` use this projection. `capabilities={upload_categories,max_size_bytes,allowed_media_types,max_filename_characters}` derives from current authority and enabled configuration; first unit always has empty upload_categories and can_download=false. Metadata creation/withdrawal UI needs separately explicit `can_create_intent`/per-row can_withdraw; it must not call an unavailable upload feature usable. Runtime dependency failures return plain actionable503, never false configured availability. Full schemas/error enums must be frozen into OpenAPI and R04 action map before code. Every document response is no-store. HEAD/OPTIONS and other unlisted methods are rejected405 with a generic bounded envelope; disable DRF implicit metadata/HEAD behaviour deliberately, with no object projection or body disclosure.

List, detail and every successful create/withdraw/content replay must commit a bounded access audit **before** returning document metadata (including count/capabilities), and final permission checks must cover the disclosed projection. Audit includes actor, operation, branch, bounded result count and at most100 result IDs; no filename/content/reason text, no unbounded query or clinical payload. Audit persistence failure returns503 without metadata/bytes. Disclosure events are excluded from generic clinical-free administrative history; no new audit-history UI is granted. Domain change and disclosure audit commit atomically for writes; reads may append audit but never repair document state.

Error envelope follows existing `{code,message,field_errors?,request_id?}` with closed bounded codes/plain messages; no filenames/paths/raw scanner errors echo. 400 validation/invalid content,403 action/CSRF,404 concealed object,409 version/state/key mismatch,413 over limit,415 media,416 range,429 capacity,503 unavailable/scanner/storage/key/audit failure. Nonready download409 `document_unavailable`; missing/corrupt bytes503 `document_unavailable`, never an empty successful file. Existing authentication status behavior must be described accurately rather than silently changed to401.

UI: keep persistent patient name/UHID/branch and existing detail context; no nested dialogs. List, upload, status refresh, download and eligible withdrawal map directly to these operations. Reload reconciles ambiguous POST/PUT outcomes with the retained logical key/document ID; no automatic new intent/retry. Browser memory only, clear file references on patient/logout/context change; do not persist bytes or keys in browser storage. UI peer owns exact labels/keyboard/offline behavior.

## Storage, scanning and state

Metadata: UUID document; patient/branch/category; immutable original safe display filename/media/declared size/digest; creator; version; status; created_at and fixed expires_at=created_at+30minutes; future opaque storage object ID+generation/upload receipt; trusted observed digest/size; bounded scanner engine/signature version/time/outcome; nullable withdrawal reason/actor/time. PROTECT patient/branch dependencies. No encounter field in this slice. Category/patient/content cannot be relabelled after intent creation. Scope relations are validated under locks and all service writes (including jobs) enforce them. DB constraints enforce nonnegative size/version, category/status enum and state-required fields; relational consistency also needs service tests, not a false claim that ordinary cross-table CHECK constraints enforce it.

First unit persists only awaiting_upload or withdrawn; at server-selected time **>=expires_at**, awaiting_upload projects expired with can_withdraw=false and no version increment/state write. expires_at never extends on reads, replay or worker retry. First acceptance is permitted strictly before the fixed deadline; later accepted states do not expire merely because this original upload deadline passed. Future ingestion states: `awaiting_upload -> quarantined -> ready | rejected | scan_failed`; eligible states may ->withdrawn. Scan_failed is inaccessible and retryable only by bounded typed worker policy; no public mark-clean API. A retry cannot revive withdrawn or expired data. Select one server time after final authority/state selection for coherent boundary decisions; backward clock or corrupt deadline fails503. A typed maintenance service may record expiry later; no automatic purge/read-time state repair in this slice.

Private storage interface accepts only server-created opaque IDs, bounded streams and immutable generations; no arbitrary paths/URLs/shell commands. Root outside static/MEDIA/webroot, private permissions, no symlink following/traversal/overwrite. Distinct quarantine/accepted namespaces; never deduplicate across patients or tenants using a digest. Storage creation uses exclusive random object IDs. App/scanner/worker secrets and dedicated encryption keys are outside Git/logs; do not reuse Django SECRET_KEY or MFA keys. Production encrypted storage configuration is required; missing key/version/adapter readiness fails503. Synthetic test fixtures may use explicit test adapters, never a production clean-scanner fallback.

Scan bytes from the exact immutable generation; compute server SHA256/length and bind verdict to both. Private local scanner socket or authenticated isolated transport; never expose unauthenticated ClamAV TCP. Missing signatures, stale signatures (proposed maximum24h), timeout, unknown response, transport fault, oversize/recursion limit and truncated scan are **not clean**. Scanner no-malware verdict is necessary but insufficient: validate supported structure with pinned maintained parsers, disallow encrypted/active/embedded PDF content, reject malformed/trailing-polyglot data. Proposed validator budgets: image <=25million decoded pixels, <=100MiB decoded allocation; PDF<=100pages, no embedded files/scripts/launch actions; isolated parse+scan <=30seconds,128MiB worker memory and no network. Exact parser/API, resource feasibility and scanner limit configuration require source/dependency review before freeze. No substring check or image signature alone establishes safety. CDR/rasterisation would create a derivative; preserve original quarantine and provenance, do not silently change signed/source bytes.

Future ingestion uses a durable scan-work/outbox row in the metadata transaction; delivery is at least once. Claim a lease in a short independent transaction, commit/release its Outbox lock, then perform bounded IO; never retain an Outbox claim lock while acquiring actor/authority locks. Bounded attempts3 with backoff and no busy loop; restart recovers expired leases. Completion reacquires locks in the global order below and checks exact lease token/generation. A DB-driven typed worker is a feasible first adapter; Celery/broker is not required by this design. Work identity permits only scanning the designated object, not general clinical read/download. Worker carries original actor/category/branch ceiling and rechecks active originating grant at promotion; revoked authority prevents ready promotion. No adapter obtains arbitrary SQL/shell/URL capability. A fresh authorised user may later initiate a separately designed recheck, not impersonate the original actor.

## Transactions, races and disclosure

Intent creation + key fingerprint/result pointer + audit commit atomically. Retry keys required for these new creates/actions; existing optional reception keys remain unchanged. Proposed new document-service global lock order: **User -> IdentitySecurity -> Organisation -> Memberships (branch_id,role,id order) -> StaffAccessRevision -> retry record -> Patient -> Document -> Outbox**; skip absent stages, never acquire an earlier stage while holding a later one. No missing retry-row race may insert after taking Patient/Document locks. Recheck session, MFA where applicable, membership and category after final waits. No network/filesystem IO inside a long database lock: stage bounded immutable bytes, then short lock/recheck/state commit. Failed staging cannot publish metadata-ready state; committed outbox cannot point to unsealed bytes. Losing concurrent staging objects are tracked for safe reconciliation, never exposed. Orphan recovery is identifier/manifest-based, not recursive filesystem guessing.

Actual-source compatibility verified by reading `core/identity_security.py:lock_identity` (User FOR NO KEY UPDATE then IdentitySecurity FOR UPDATE), `staff_access.py:locked_organisation` (lock_platform before Organisation) and `change_staff` (Memberships then StaffAccessRevision). Resource configuration likewise locks identity before Organisation; existing service retry locks occur before their domain locks. Existing admission uses Bed then Patient; this proposal acquires neither Bed nor Appointment, avoiding an invented global reorder. Staff edits do not lock the target User after Organisation; preserve that fact and do not introduce target-user locks in this unit. New document services need these explicit ordered locks rather than blindly wrapping existing `idempotent_create`, whose callback/replay ordering must be checked before reuse. This is a compatible extension for these paths, not a claim every source path already uses the new complete sequence. PostgreSQL revoke/replay/read races must verify it before delivery.

Unique actor+operation+key claims, object generation CAS and one scan job per generation prevent duplicate ingestion. Scanner promotion and withdrawal lock the same document and recheck version/state/digest/authority; either withdrawal wins and no ready result, or ready wins and withdrawal returns correction-required. Two uploads with different bytes cannot overwrite an intent. Worker duplicate completion does not increment version/audit twice. Metadata, ready decision and accepted object pointer commit together only after a durable verified object exists; physical cleanup cannot run before metadata/hold/backup dependency checks.

Download: verify current request network/session and category scope, open exact private generation, verify digest/length in bounded processing, then final reauthorisation + durable disclosure audit before first response byte. Audit includes actor/document/category/branch/result/correlation ID, no file content/title/clinical text; generic admin history must exclude these events. Audit failure503. Authority linearises at the final check before transfer: future revocation cannot retract already transferred bytes; no inaccurate promise of mid-transfer recall. Single bounded transfer; resource/time/concurrency limits require measured validation. Log success as authorised transfer start, not proof that the client received all bytes.

## Retention, corrections and backups

No DELETE, silent replacement or legal retention duration is invented. Ready files are immutable historical source records. Future correction must create a new linked version with reason/provenance and preserve the prior file under the same access restrictions; it cannot approve/sign a clinical record. Retention schedule/legal hold/purge authority remains an owner/reviewed policy decision; no purge job until it exists. Withdrawal cancels availability of unfinished uploads while retaining audit/metadata and protected bytes pending reviewed cleanup.

Backup manifest must bind metadata snapshot, opaque object generation/digest/length/state and encryption key-version dependency. Quarantine and ready objects need explicit inclusion/exclusion policy; cannot restore ready metadata without matching available verified bytes/key dependencies. Restore into an isolated private target, validate hashes and scope, re-evaluate security/holds and retain quarantine; no portal backup blindly overwrites shared patients/documents. Production encrypted backup/restore drill and key-loss recovery are release gates, not delivered by source tests.

## Primary-source research (reviewed 24 October 2026)

* [Django 5.2 security / uploaded content](https://docs.djangoproject.com/en/5.2/topics/security/#user-uploaded-content): framework validation does not make uploaded content safe; upload limits and serving context require explicit design. This design uses attachment delivery and no inline renderer.
* [OWASP File Upload Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/File_Upload_Cheat_Sheet.html): defence in depth includes allowlists, independent type/content checks, bounded size, generated storage names, private storage and scanning. These are architecture inputs, not evidence of this implementation passing.
* [ClamAV scanning documentation](https://docs.clamav.net/manual/Usage/Scanning.html): signature databases are required and clamd TCP has no built-in authentication. Local/private transport and signature readiness are mandatory here; antivirus never establishes clinical correctness.
* [Amazon S3 presigned URLs](https://docs.aws.amazon.com/AmazonS3/latest/userguide/using-presigned-url.html): URLs can be reused until expiry and uploads can replace an existing object key. This supports deferring direct upload until immutable-generation/completion semantics are reviewed; no S3 provisioning is selected.
