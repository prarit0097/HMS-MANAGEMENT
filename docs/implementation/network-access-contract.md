## 1. Existing source and selected approach

Inspected actual source: `backend/apps/security/ip_policy.py` supplies `normalise_client_ip(remote_addr, forwarded_for, trusted_proxies)` and `evaluate_ip(address, allowlist, blocklist, allowlist_only)`; it bounds forwarded chains to 64 hops/8192 characters, rejects malformed trusted chains and maps IPv4-mapped IPv6 to IPv4. `backend/apps/core/middleware.py` currently enforces environment policy only on `/api/`, excluding the exact health route. `backend/hms/settings.py` places it before sessions/authentication. Preserve that pre-auth network boundary.

`identity_security.py` supplies `lock_identity`, `require_session`, epoch validation, encrypted enrollment and factor timestamps. `require_platform` skips factor requirements when `HMS_REQUIRE_ADMIN_MFA` is false; it is therefore insufficient for this feature. `lock_identity` locks User NO KEY UPDATE then IdentitySecurity and may create the latter; use it on authorised mutation paths, never a GET. Its `session_hash(request)` can create a session; network GET/probe must not call it. `authorization.current_user` derives ordinary permissions from active branch memberships. `resource_admin.locked_configuration_organisation` and `staff_access.locked_organisation` establish User/security then Organisation ordering and fresh checks after waits. Build on these services rather than create a parallel authentication system.

Alternatives considered: environment-file editing through the UI would mix OS/proxy authority with application authority and offer no safe rollback; organisation-only post-login rules cannot guard login or static HTML; selected approach is one deployment-wide durable overlay intersected with the existing environment ceiling, using the existing resolver and a network-only internal edge probe. Tradeoff: database availability becomes necessary for portal requests. No permissive cache or automatic repair is acceptable.

## 2. Policy grammar, limits and effective decision

`Policy` is exactly `{allowlist_only: boolean, allowlist: string[], blocklist: string[]}`; all fields required, additional properties false. Strict JSON booleans only. Each list has 0–100 entries, each raw input 1–64 ASCII characters before trimming ASCII space/tab at ends; the trimmed value must remain nonempty; no CR/LF, zone identifiers, ports, hostnames, comments or empty entries. Total rules at most 200. Exact addresses and CIDRs are accepted. Canonicalise through the existing address/network rules, emit every entry as network/prefix (`/32` or `/128` for exact addresses), sort by address family/network integer/prefix and deduplicate after normalisation. Mapped IPv6 CIDR prefix must be >=96; map it to equivalent IPv4. Reject an empty allowlist when allowlist_only=true. Overlaps are legal; blocks always win. Rule enable flags, expiry, per-organisation overrides and allowlist exceptions to blocks are deferred.

For request time `t`: select saved pending candidate only while status=pending and `t < rollback_at`; otherwise select confirmed policy/fallback. Validate the *entire* selected saved policy including shape/count/type/fingerprint before allowing any match. Invalid state, inconsistent pointers/snapshot or unavailable DB yields 503 `network_policy_unavailable`, never unrestricted policy. Evaluate `environment_allows(ip) AND selected_overlay_allows(ip)`. A missing/mismatched owner environment binding disables management, not enforcement of stored rules. Invalid environment rules/trusted-proxy configuration fail closed. No auto-whitelisting and no rule can change trusted proxies, environment ceiling, host validation or origin exposure.

Canonical environment fingerprint = SHA256 of deterministic JSON containing canonical environment allow/block lists, strict allowlist_only, canonical trusted-proxy rules and owner configuration descriptor: `{status:"valid",value:canonical_uuid}`, `{status:"missing"}`, or `{status:"invalid",value_digest:SHA256(raw_environment_string)}`. Malformed/missing owner UUID disables management but is not a parser exception that disables internally consistent stored-policy enforcement; never expose/hash-substitute malformed IP/trusted-proxy rules into a permissive policy. Store only final digest in bindings; do not expose proxy/env configuration. Environment changes require coordinated worker restart; mixed worker fingerprints invalidate writes rather than silently authorise them. Worker consistency is an operational release check.

Validate crosslinks on every enforcement snapshot: singleton revision and policy digest valid; pending.owner equals stored bound_owner; pending.base_revision+1 equals pending.activation_revision equals singleton revision; pending fallback digest equals confirmed digest; candidate/fallback digests match canonical snapshots; pending status is pending; rollback_at equals activated_at+300seconds; preview/change identity and policy digests match where a preview exists. No pending pointer may refer to terminal change, foreign owner or dangling row. Any failure503. Retained terminal history is not itself an effective pending snapshot. Owner configuration mismatch does not invalidate an internally consistent stored-owner policy for enforcement.

## 3. Authority and current-user advertisement

Installation owner must be explicit UUID `HMS_SECURITY_ORGANISATION_ID`, equal to singleton.bound_owner_id; never choose first organisation. An HTTP manager requires all of: authenticated active User; current session epoch; active `Membership(role=master_admin)` through a branch of that configured owner; active separately provisioned `NetworkOperator(user, organisation)` entitlement; enrolled `IdentitySecurity.active_ciphertext`; numeric finite proof timestamp with `0 <= now - factor_verified_at <= 900` seconds. These last two checks are unconditional in DEBUG/development, even if ordinary platform MFA is disabled. A generic master grant, Django superuser/is_staff flag or other organisation membership is insufficient. Direct service adapters use the same context and checks; no MCP exemption.

Proposed `require_network_operator(context, locked_identity=None)` performs these checks without creating state. `lock_network_operator(context)` uses the lock protocol below and the unconditional proof helper, not an ordinary `lock_platform` decision alone. A proof minted by existing Account security step-up is reused; no password/TOTP is accepted in policy payloads. Session binding is SHA256 of an already existing session key; absence is 401, no session creation. Rotation/epoch change invalidates previews, including Account security step-up that cycles the session key: step up first, then create a new preview.

Existing `GET /api/v1/auth/me/` / OpenAPI operationId `getCurrentUser` (current-user capability) stays the existing operation, not an eighth route. Add `platform.security.manage` to its top-level permissions only when owner binding, active owner master membership and entitlement are all current; omit from branch_permissions because it is deployment-wide. Advertisement does not depend on current MFA freshness, so the UI can offer Account security enrollment/verification; every one of the six management operations does require fresh MFA. Do not add this permission to ROLE_PERMISSIONS. GET performs pure bounded DB reads; unavailable state must never advertise the capability (normal network middleware may already return 503). No operator lists, owner IDs, rules or preview bindings enter ordinary current-user or generic audit responses.

Existing `platform_summary` / OpenAPI operationId `getPlatformSummary` currently labels `security.ip_mode` from environment alone. Change that existing response, without adding an operation: retain `ip_mode` enum but derive `allowlist_only` if either environment or time-selected overlay is whitelist-only; otherwise `allow_authenticated`. Add `policy_scope:"effective_deployment"` and `blocked_addresses_apply:true` so an unrestricted-mode label does not imply absent blocks. UI label “Network access mode” describes this effective mode; no raw rules/owner/operator information is disclosed to ordinary platform.read callers. Missing/corrupt state503, never environment-only success. Freeze this additive schema/page label change in OpenAPI and test pending/expired fallback projections.

## 4. Exactly seven new API operations

Methods outside the listed operation return 405 (framework HEAD may mirror safe GET; HEAD is not a new capability). Unsupported media type 415. Reject non-object JSON, files, unknown/nested unexpected fields, coerced booleans/integers and bodies >32768 bytes before parsing. Require `application/json` on POST. ## 5. Exact response projections

All declared response objects have additionalProperties=false; serializers construct projections field by field, never return stored JSON directly. Missing optional context is explicit null.

* `NetworkState`: `{scope:"deployment", revision, owner_organisation:{id,name}, server_time, verified_client_ip, confirmed_policy:Policy, effective_policy:Policy, pending: Pending|null, environment_allows_current_ip:boolean, effective_allows_current_ip:boolean}`. Owner name <=160, canonical IP <=45. `revision` is stored revision, not an invented GET revision. `Pending` = `{change_id, status:"pending"|"expired_unreconciled", activated_at, rollback_at, activation_revision, candidate:Policy}`. Never include actor session hash/epoch/environment digest or entitlement details. Read uses a coherent singleton+referenced immutable change snapshot from one SQL statement/consistent DB snapshot; no read-time reconciliation or repair. Expired_pending effective_policy is fallback even though candidate remains visible as expired pending.
* `Preview`: `{preview_id, base_revision, policy:Policy, normalisations:[{list:"allowlist"|"blocklist", index:0..99, input:string<=64, canonical:string<=49}], current_path:{environment_allows:boolean, candidate_allows:boolean, effective_allows:boolean}, can_activate:boolean, created_at, expires_at, server_time}`. Normalisations at most200, exclude unchanged entries. Persist canonical policy plus bounded normalisation output; request fingerprint binds original full validated request/reason so altered request under same key conflicts. Preview is allowed when candidate blocks current IP, but can_activate=false and activation returns400 `validation_error` with a plain explanation; deliberately locking out the initiating path is OOB-only. Current path comes solely from server resolver.
* `ChangeResult`: `{change_id, outcome:"pending"|"confirmed"|"reverted"|"expired"|"recovered"|"owner_transferred", activation_revision, revision, activated_at, rollback_at, finished_at:null|timestamp, server_time}`. `revision` is current singleton revision; clients reload full state to inspect policy. Immutable per-operation replay metadata preserves original request revision/result outcome; a replay never falsely reports an old pending operation as a new activation. If an activate replay now refers to terminal change, return its current terminal outcome with no write.
* `NetworkHistory`: `{count, results:[NetworkEvent], window:{after,before}}`. `NetworkEvent` = `{id,created_at,action,outcome,actor:{id,username}|null,os_actor:string|null,reason,change_id:null|uuid,revision,before:Policy|null,after:Policy|null}`. Malformed optional context (`actor` as a whole, os_actor, change_id, before/after historical snapshots) projects null; malformed required id/created_at/action/outcome/revision/reason yields503 `network_policy_unavailable`, never undeclared null/unknown enum. History query: single decimal ASCII limit1..100 (default25), offset0..10000 (default0), each <=5 characters, reject rather than clamp; `outcome` one enum above <=11 characters. `after`/`before` <=35 chars, same strict RFC3339 parser/valid calendar and offset rules as audit_history.date_bound; defaults before=min(requested,now), after=before−30days; require after<before and span<=90days. Dedicated NetworkPolicyEvent table/index; do not broaden ADMIN_ACTIONS/SELF_ACTIONS or expose these payloads through generic AuditEvent.

## 7. State, revisions, retries and exact deadline semantics

No persistent draft; browser draft is memory only. `Preview` saved at t0 expires t0+300s. POST preview rejects any live pending change; if an old pending change expired, first materialise expiry inside transaction, then compare caller expected_revision; stale caller receives409 after expiry commit and must reload. All mutation entry points use this maintenance pattern. Expiry accounting must commit even when returning a later conflict; do not throw an exception that rolls back required reconciliation. Return a domain outcome after atomic block, as existing identity failure-accounting services do.

Preview saves the entire immutable candidate; current policy is unchanged and revision is unchanged. Preview creation is idempotent only for identical actor/request-key/request digest AND current same session/epoch/IP/owner/operator version/environment binding. Exact replay before expiry returns the same preview/times after current authorisation. Expired replay409; different payload409. Replayed consumed preview returns its original preview plus original expires_at; activation determines existing change outcome. No retry refreshes either five-minute period.

Activation locks and validates bound preview, expected base revision and no pending change; re-evaluates environment/current confirmed path AND candidate path. Candidate must allow initiating IP under the environment ceiling. Atomically create change with fallback=current confirmed policy; set pending pointer; increment revision once; activation_revision is that value. Activation consumes only saved policy; no replacement policy/reason/deadline accepted. Exact activation replay may return its existing change under current authorisation and exact bindings, even if now terminal; original expected base revision must match, not current revision. A different expected revision409. No second event/deadline extension. Requests denied by active network policy never get replay privileges.

While pending and now<rollback_at, candidate is effective. Confirmation must arrive through candidate, same actor/session/epoch/IP/owner/operator version/environment, fresh authority/proof, matching activation revision and pending pointer. It sets confirmed=candidate, clears pending, status=confirmed, increments revision once and emits one private event. Explicit revert has identical binding/authority requirements, restores immutable fallback, clears pending and increments once. Another entitled operator cannot adopt someone else's pending change through HTTP; OS recovery remains available. Exact repeat of the same terminal operation returns200 only for original expected revision and bindings after current reauthorisation. Opposite terminal operation409. A later singleton revision is not overwritten on a replay.

At now>=rollback_at the network evaluator selects fallback without any write, worker or scheduler. GET reports `expired_unreconciled`, unchanged stored revision and server_time. A subsequent mutation/reconcile command locks singleton/change, marks expired, clears pending, preserves fallback, increments revision once and creates exactly one expired event. Confirmation/revert at equality or after returns409 `network_change_expired` after any expiry accounting commit. A confirm that wins the transaction before deadline may commit later; deadline and MFA are rechecked at final decision/audit point, not claimed as universal post-commit cancellation. Every pointer/fingerprint mismatch503, not guessed recovery.

Environment drift invalidates preview/confirm/revert; active enforcement immediately uses current environment AND selected overlay. Saved deadlines never change. An unconfirmed candidate may therefore require waiting for rollback or OOB recovery. Role/entitlement revocation, epoch change and owner transfer invalidate all bound previews/pending HTTP operations. Never automatically retry a POST in browser or proxy. Bounded network timeouts are ambiguous: reload state/history, keep original IDs, explicitly retry only the exact same operation if still appropriate.

## 8. Lock order and post-wait checks

All policy mutation services run transaction.atomic. Acquire locks in this global order: canonical actor User NO KEY UPDATE; actor IdentitySecurity FOR UPDATE (reuse lock_identity); owner Organisation NO KEY UPDATE; actor NetworkOperator FOR UPDATE; singleton FOR UPDATE; addressed preview FOR UPDATE; addressed/current change FOR UPDATE (UUID order if more than one); append event last. If a missing entitlement/owner must be created via OS operation, lock its parent User/Organisation before insertion under unique constraints. Do not lock a preview before singleton. No policy service takes Branch/Bed/staff revision locks. Existing staff writer holds actor User then Organisation and changes memberships; organisation locking serialises authority rechecks without adding target User locks behind it.

After *each* blocking wait, discard cached authority/revision/time decisions; after all locks and immediately before event/final write, refresh User active state, security epoch/enrollment/proof time, owner binding/membership, entitlement active/version, request existing session digest, canonical verified IP/current resolver configuration, environment digest, selected current path, revision/pointers and deadlines. Use the locked fresh User for global active check while comparing captured session epoch/proof to locked security row. Recompute timestamp after DB uniqueness/FK waits before the audit boundary. Validate exact stored snapshot digests again before writes. No call to require_platform with DEBUG opt-out substitutes for these checks.

This includes preview creation and every activation/confirmation/revert replay: middleware admission at request start is insufficient after a wait. Re-evaluate current environment AND currently effective overlay for canonical request IP at the final locked decision; deny403 if the path was revoked, and503 for inconsistent policy. Replays do not bypass this check even when a saved result exists. Activation also checks saved candidate allowance. OS commands intentionally use their separate audited OS context and do not fabricate an HTTP current-IP path.

OOB actor/target user sets are locked sorted by User PK first, identity rows sorted second, organisations sorted UUID third, entitlements sorted(user,organisation) fourth, singleton fifth, preview/change thereafter; never discover an extra user lock late. Owner transfer invalidates by owner binding/generation/revision rather than scanning and locking all preview actors. OOB reconciliation needs no User/organisation/entitlement lock because it is system expiry only, then singleton/change; it must not later call an actor-locking recovery function. HTTP paths may do preliminary reads but cannot authorise from them. PostgreSQL event-controlled races must prove no reverse lock edge with staff revocation, factor revoke/disable, operator commands or concurrent expiry.

## 9. OS-authorised commands, bootstrap and owner transfer

Commands are local OS operator tools, never HTTP/MCP actions or shell/SQL tool wrappers. Proposed names/interfaces:

* `manage.py network_policy inspect --os-actor LABEL --reason TEXT`: bounded redacted current state, no mutation or secrets; exits nonzero on unavailable/corrupt state.
* `manage.py network_policy bind-owner --organisation UUID --expected-revision N --os-actor LABEL --reason TEXT`: only when bound_owner null and configured owner equals argument; bind owner, revision++, owner.bound event; no entitlement/master membership creation.
* `manage.py network_operator grant|revoke --organisation UUID --user-id INT --expected-version N --expected-revision N --os-actor LABEL --reason TEXT`: explicit owner match, active User and current owner master required for grant; expected version0 means create new. Revoke can target inactive user; increments only entitlement version, invalidates that user's previews/pending HTTP authority and records event at current policy revision. It does not change policy revision or another operator's pending change. A revoked pending initiator must wait for automatic fallback or use OS recovery; revocation never extends the deadline. OS actor is OS accountability label, not a forged application identity. No MFA required for this distinct OS capability. No automatic selection of user/owner and no last-operator bypass; show recovery dependency before explicit revoke.
* `manage.py network_policy reconcile --os-actor LABEL --reason TEXT`: materialise expiry exactly once; no-op if no elapsed pending; never apply unexpired fallback by accident.
* `manage.py network_policy recover --change UUID --expected-revision N --os-actor LABEL --reason TEXT`: select immutable candidate/fallback from that change with mandatory `--snapshot candidate|fallback`; no arbitrary file/JSON/URL/SQL input. Validate selected policy; explicit one-step recovery replaces confirmed policy, terminalises pending as recovered, revision++, event. Can restore more permissive overlay, never environment ceiling; this is deliberate OS authority and is audited. Print before/after canonical policy and require explicit `--apply` to mutate (dry run otherwise). No network reachability guarantee from this command.
* `manage.py network_policy transfer-owner --from UUID --to UUID --expected-revision N --os-actor LABEL --reason TEXT --apply`: OS-authorised, existing organisations, target equals newly configured HMS_SECURITY_ORGANISATION_ID. This is the only deliberate mismatch exception: stored old owner must equal --from and configured new owner --to. Locks both orgs in UUID order; preserves confirmed policy, reverts/terminalises any pending as owner_transferred, revision++, owner.transferred event. Old entitlements are not copied/rebound and no new grants are created. All old previews invalid by owner+revision; target requires separate explicit entitlement grant/master membership. Deploy consistent new owner env to all workers before management resumes; failclosed enforcement continues during mismatch. Dry run without --apply.

All flags strictly parsed, reason10..500 and OS label1..150 printable characters, no secrets in command args/output; commands use same parser/snapshot/transaction/event services with explicit `OutOfBandContext`, never a fabricated HTTP superuser. command exits0 success/no-op,2 invalid input/conflict,3 unavailable; rollback on invalid input except independently committed expired reconciliation. DB outage requires DB repair; corrupt snapshots require forensic OS repair outside these safe commands (do not add unsafe override). Environment lockout/trust misconfiguration requires separately audited OS configuration recovery. Configure initial approved environment admin path and test console/recovery access before full edge enforcement; unrestricted initial DB overlay is not a production bootstrap approval.

## 10. Full portal edge contract and probe circularity

Probe is network-only, not staff/session authority. For this exact path NetworkPolicyMiddleware first validates the internal probe context below (invalid context404 before policy DB access), then resolves/evaluates its normal trusted address once and marks an internal validated-probe request attribute. IdentitySessionMiddleware requires an explicit early skip for this exact path AND validated attribute before touching request.user/session/epoch; empty DRF authentication classes alone cannot bypass earlier middleware. Handler uses empty authentication classes and AllowAny, returns204 when allowed, and does *not* bypass network evaluation. The network middleware exact-path response adapter returns empty no-store403/503/404 for probe denial/unavailability/invalid context instead of ordinary API JSON, never WWW-Authenticate/Set-Cookie. A supplied Cookie/Authorization on a direct trusted-loopback probe is ignored, never used to expire/logout/flush a session. Do not recurse into HTTP, read current_user, require MFA, create sessions or use probe success as permission to access patient data. Middleware still protects all ordinary `/api/` paths; only exact `/api/v1/health/` is exempt. No response cache or stale fail-open fallback.

Nginx internal location `= /_hms_network_check` makes fixed GET loopback request to `http://127.0.0.1:8185/api/v1/network-policy/edge-probe/`, `internal; auth_request off; auth_basic off; satisfy all; proxy_pass_request_body off; proxy_pass_request_headers off; proxy_set_header Content-Length ""; proxy_method GET;`. Send only explicit Host `hms.praritsidana.com`, X-Forwarded-Proto `$scheme`, X-Forwarded-For `$remote_addr`, X-Real-IP `$remote_addr`, and X-HMS-Network-Probe `1`. No Cookie/Authorization/Forwarded/CF headers/X-Original-URI are forwarded. Canonical backend probe context requires socket REMOTE_ADDR in an explicit loopback-only `HMS_NETWORK_PROBE_PEERS` setting plus header exactly `1` and no body/query; do not trust header alone or all general trusted proxies. This marker is routing context, not a secret authentication token; an OS-local process already has separate infrastructure trust, and the evaluator still enforces the supplied canonical network path.

In every ordinary proxied location, overwrite X-HMS-Network-Probe with empty string so visitors cannot select probe context; block external exact `/api/v1/network-policy/edge-probe/` with404 at Nginx (its internal check location reaches backend directly). Maintain explicit overwrite XFF=$remote_addr and fixed Host/proto; never append a visitor chain in this direct-edge topology. If a CDN/LB is added, freeze/test a new trust topology before changing these headers.
